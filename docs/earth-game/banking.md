# 银行、信用和贷款

分支 `claude/earth-banking`（从 main `4f9c9e5` 开出），changelog v43。

本文的每一节都标了状态：

- **【现状】**：main 上已有的规则（本分支开工时）。
- **【新·已落地】**：本分支第一版实现了的。
- **【提议】**：只写了设计，没有实现。

这是游戏机制。数值参照澳洲公开的规则做了简化和缩放，**不是理财建议**。界面上也写了这句话。

新数值一律标「待平衡」。Claude 不下平衡结论，§6 只列模拟结果的变化。

## 3. 设计【新·已落地】

### 3.1 银行账户和借记卡

- 动作 `{ t: 'bank', op: 'open' }`。不花钱、不花游戏时间，任何地方都能开（手机核验身份）。
- 开户后有一张借记卡。第一版里借记卡只是标记：现金 `cash` 本来就当作账户余额，没有拆成「现金」和「存款」两份。
- 开户是申请任何信用产品的前提，包括房贷。
- 开户本身不产生信用记录。

### 3.2 信用分

游戏用 0–1000 分制。没有任何信用记录时显示「无记录」，银行审批时按起点分 500 算。

**分数怎么形成**（`core/credit.ts` 的 `creditScore`）：

```
信用分 = 500
       + min(150, 记录周数 × 2)
       + min(52, 按时还款周数) × 5
       − 近 182 天的申请次数 × 10
       − 近两年的逾期次数 × 80
       − 近五年的违约次数 × 250
       − 40（信用卡欠款超过额度一半时）
       钳到 0–1000
```

- **记录从哪天开始**：第一次申请信用卡、贷款（含房贷、车贷）或先买后付的那天。
- **按时还款的一周**：这周有至少一笔还款，并且所有该还的都还上了。有一笔没还上，这周就不算。
- **逾期一次扣掉 10 个按时周**。
- 分档名用 Moneysmart 的五档：低、一般、良好、很好、优秀。分界线 550 / 625 / 700 / 800 是游戏值。

**分数怎么下降**：

| 情况 | 影响 | 持续多久 |
| --- | --- | --- |
| 申请一次信用（信用卡、个人贷款、车贷、房贷、先买后付） | −10 | 182 天（待平衡） |
| 一笔欠款连续 2 个结算周没还（= 14 天） | 记一条逾期，−80，按时周数 −10 | 两年（来源） |
| 一笔欠款连续 9 个结算周没还（≈ 63 天）且 ≥ $30 | 记一条违约，−250，转催收 | 五年（来源） |
| 房贷断供被强制卖房 | 记一条违约 | 五年 |
| 信用卡欠款 > 额度的一半 | −40 | 还到一半以下就恢复 |

- 现实里违约门槛是 $150。游戏物价约为真实的 1/5，所以用 $30。
- **审批没通过不记申请**。现实里被拒的申请也会留记录，但游戏界面会先显示能不能批，被拒基本是点错，记下来只会惩罚误操作。这是简化。
- 存档里每种日期记录最多留 12 条（`HIST_MAX`）。

### 3.3 共同的审批门槛

`creditBlocked()`：

1. 没开户 → 不批。
2. 五年内有违约记录，或有正在催收的欠款 → 不批任何新信用。
3. 有一笔正在拖欠（还没满 14 天也算）→ 先补上。

**还款能力**（`bankCapacity()`，参照负责任放贷「看收入、开销」）：

```
每周收入   = 正式工作每班工资 × 5          （零工不算）
可用于还款 = (每周收入 + 出租房租金 × 0.8 − 已有固定开销) × 0.75
已有固定开销 = 房租 + 车辆保险保养 + 房产物业费和房贷 + 银行这边每周要还的 + 信用卡额度 × 3%
```

申请按揭自住时，现在的房租不算进开销（买了房就不用再租）。

`× 5`、`× 0.8`、`× 0.75`、`3%` 都是游戏值，待平衡。

### 3.4 信用卡

| 项目 | 规则 |
| --- | --- |
| 申请 | `{ t: 'bank', op: 'card' }`，记一次申请 |
| 额度 | 三档：$500（450 分）、$1,500（625 分）、$3,000（700 分）。按「三年内能还清整个额度」评估：额度按信用卡利率 156 周等额还款的每周金额 ≤ 还款能力，批能批的最高一档 |
| 怎么用 | **第一版只有取现**：`{ t: 'bank', op: 'draw', amount }`。手续费 3%（至少 $2），手续费也占额度；从当天起计息，没有免息期 |
| 利息 | 每周 0.4%（约年化 21%），待平衡，未取来源 |
| 还款 | 每周结算自动扣最低还款 = max($10, 欠款 × 3%)，不超过欠款；也可以随时手动还 |
| 欠款 | 付不起最低还款：罚金 $5，记一次欠款 |

**为什么第一版没做刷卡消费**：要让信用卡带免息期地付房租、买车、买东西，得改引擎里所有扣现金的地方。第一版只做「取现」，它在现实中本来就没有免息期，规则说得通。刷卡消费见 §7.1。

### 3.7 房贷：给现有按揭加审批【新·已落地，改了现状】

买房的规则（首付 10%、利率、本金、断供）**全部不变**。新加的只有：

1. **要先开户。**
2. **审批**（`homeOffer`）：
   - 信用分 ≥ 450。没有记录的人（按 500）可以申请；刚记了逾期的人通常过不了。
   - 测算还款 = 每周固定本金 + 贷款额 × (每周利率 + 3% ÷ 52)。其中 3 个百分点是 APRA 的缓冲。测算值 ≤ 还款能力才批。
3. **贷款保险**：首付不到 20%（现在固定 10%，所以总是要交）时，保险费 = 贷款额 × 2%（待平衡），并进贷款。
4. 记一次申请。
5. **信用记录**：房贷拖欠满 2 个结算周记一条逾期；断供被强制卖房记一条违约。按时还房贷算按时还款周。

| 能买什么 | 第一版只接家具（在住处时）：`{ t: 'bank', op: 'bnpl', id, ack: true }` |
| 分期 | 分 4 期，下单付第一期（除不尽的零头算在第一期），之后每个结算周一期，不收利息 |
| 风险提示 | 下单前确认框原样显示 `BNPL_WARNING` 三条。**服务端要求请求带 `ack: true`**：协议层（`parseAction`）和引擎（`buyFurnitureBnpl`）各查一次，旧客户端或绕过界面的请求不受理 |
| 申请 | **每笔都记一次申请**（Moneysmart：每次申请都会查信用） |
| 逾期 | 每期没付上收 $2 逾期费，随下一期一起扣。一笔订单的逾期费合计不超过订单额的 25%（待平衡）。拖满 14 天记逾期，60 天以上且 ≥ $30 记违约 |
| 数量 | 同时最多 4 笔 |

风险提示原文：

1. 先买后付也是借钱：每次申请都会查一次信用，记在信用记录上。
2. 哪一期没按时付，会收逾期费；拖到 14 天以上会记逾期，信用分下降。
3. 同时开好几笔，每周要付的钱会叠在一起。

### 3.9 逾期、违约和催收

每周结算的顺序（`engine.ts` 的 `weeklyTick`）：

```
房租 → 房产（租金、维修、物业费、房贷、断供）→ 车辆保险 → 银行（信用卡 → 贷款 → 先买后付 → 房贷的信用记录 → 催收）
```

现金不够就记一次欠款，**不会让现金变成负数**。

| 连续欠款 | 后果 |
| --- | --- |
| 第 1 次 | 罚金（信用卡、贷款 $5；先买后付 $2）；车贷发违约通知 |
| 第 2 次（14 天） | 记逾期，信用分 −80 |
| 第 5 次 | 车贷收车 |
| 第 9 次（≈ 63 天）且欠款 ≥ $30 | 记违约，信用分 −250；这笔债停止计息和罚金（游戏简化）；转催收 |
| 催收中 | 每个结算日记一条「催收公司来电」（规则按 Moneysmart：每周最多 3 次、限时段），刷新「被催收」心情（−6，7 天，待平衡）；不批任何新信用 |

- 补上欠款后，拖欠次数清零，但已经记下的逾期、违约**不撤销**，到期自然失效。
- 违约的欠款还清后，催收停止。
- 第一版没有「困难援助」，见 §7.2。

### 3.10 净资产

`netWorth()` = 现金 + 车 + 家具 + 房产权益 − **欠银行的钱**（信用卡欠款 + 贷款余额 + 先买后付没付的期数和逾期费）。

房贷原本就在房产权益里扣过，没有重复扣。贷款保险并进了房贷，所以按揭买房的人净资产会比以前少一笔保险费。

### 3.11 存档字段 `bank`

按 `save-sync.md` §5 加字段，没改 `SAVE_VERSION`，没改已有字段：

```ts
bank: {
  open: boolean;
  card: { limit; bal; missed; def? } | null;
  loans: { kind: 'personal'|'car'; bal; pay; rate; missed; vehicle?; def? }[];   // 每种最多一笔
  bnpl: { item; amt; left; missed; fees; owe; def? }[];                          // 最多 4 笔
  hist: { since; ok; late: number[]; def: number[]; enq: number[] };             // 日期是游戏日
}
```

- `createCharacter` 给 `emptyBank()`；`sanitizeState` 的 `out` 里加了一行 `bank: cleanBank(…)`。
- **旧存档**：没有 `bank` 字段就是未开户。**有房贷的旧存档视为已开户**（房贷本来就是银行给的），否则这些玩家不能再看到信用记录。
- `cleanBank` 不抛异常；金额钳到 [0, $1,000,000]；额度只认数据表里的三档；利率只认数据表里的值，否则用最高一档；车贷的抵押车、先买后付的家具用已知 id 过滤；日期丢掉未来、负数、非整数的，每种最多 12 条；`since` 不晚于今天，缺了就从最早一条记录补；幂等。
- 银行数据不是秘密，`publicState` 原样发给客户端（界面要显示信用分和欠款）。
- 序列化后：空的约 100 字节，所有列表、金额都填满约 1KB（远低于 §5.1 的 4KB）。

### 3.12 服务端校验

- 所有银行动作都是新的 `GameAction`，只能经服务端 `applyAction` 结算，没有新的写存档途径。
- `parseAction`：金额必须是有限数、≥ 1、≤ $1,000,000，取整；`kind` 只认 `card / personal / car`；id 走现有的 `ID` 正则；先买后付必须 `ack === true`。**利率、额度、期数、首付都不从客户端收**，客户端多传的字段直接丢掉。
- 引擎在动作里重新审批（分数、还款能力、门槛），不信任界面上的「能批」。
- 车贷、先买后付的实现方式：先把银行放款记进一份**拷贝**的现金，再调用原来的 `buyVehicle` / `buyFurniture`。原流程失败就返回原存档；成功后才记贷款。因为原流程会先检查「现金够不够」再扣全价，放款额 = 车款 − 首付，所以现金净变化正好是首付，不会多给钱。
- 银行动作不能离线排队（`queue.ts` 的白名单没加）。

## 7. 提议（没做）

### 7.1 刷卡消费和免息期

让信用卡、借记卡都能用来付房租、买东西：每个扣现金的地方先扣现金，不够再走信用卡（或者让玩家选）。全额按期还上的消费不计息（来源：Moneysmart，免息期只在全额还款时有效）。需要改引擎里所有 `state.cash -=` 的地方，影响面大，建议单独一批。

### 7.2 困难援助

Moneysmart：贷款机构必须考虑困难援助申请，可以暂缓或调整还款；援助记录 12 个月后删除，本身不影响信用分。游戏里可以加一个「申请困难援助」：暂停还款 N 周、不记欠款，但这期间不批新信用。这是现实里避免违约的正路，值得做。

### 7.3 浮动利率

`claude/earth-home-vehicle` 文档 §1.3 的提议。按数据表每季度调一次利率，不跟真实利率挂钩，免得现实加息直接打乱存档。

### 7.4 临时签证和外国人购房

留学生是主要玩家。现实里外国人（含临时签证持有人）买房要过外国投资审批，而且据报道有一段时间禁止购买现房。**本轮没读到官方原文**，所以没做。如果要做，应该和签证分支 `claude/earth-visa` 一起设计：签证类型决定能不能按揭、能买哪类房。

### 7.5 信用报告页

每 3 个月可以免费查一次信用报告（Moneysmart）。可以做一个查看历史明细的页面，列出每条逾期、违约、申请的日期和到期日。

### 7.6 储蓄放进银行卡片

`claude/earth-economy` 合并后，把 `savings` 高息储蓄显示在银行卡片下面，作为银行账户的一部分；规则仍归那边。
