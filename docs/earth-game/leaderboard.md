# 排行榜与赛季（第一版）

- 分支：`claude/earth-leaderboard`，基于 `main` 4f9c9e5（2026-11-20）。更新日志 v43。
- 代码：`src/game/core/leaderboard.ts`（纯函数）、`src/game/data/leaderboard.ts`（数值）、`src/game/server/world.ts`（聚合、缓存、结算）、`src/game/ui/board.ts`（卡片 HTML）、`src/pages/earth.astro`（「社交」页）。
- 测试：`tests/earth/leaderboard.test.ts`（23 条）；`server.test.ts`、`save-sync.test.ts` 里原有的榜单测试按「上榜要同意」改过；`ui.test.ts` 的整页测试加了旧玩家上榜提示（弹出、回答、写到服务端、不再弹）。
- 标注：**【现状】** = 写这份文档前 `main` 上已经有的；**【新】** = 本分支第一版落地的；**【提议】** = 只写在这里、还没做的。所有标「待平衡」的数值都是占位，交给 Codex 看线上数据和模拟报告后给建议，Claude 不下平衡结论。

## 1. 现状（写之前 main 上有什么）

- **【现状】全服净资产榜**（经济方案阶段 D，PR #21，`core/board.ts`）：每次存档落盘，服务端顺带写 `rank:<id 哈希前 12 位>` = `{ name, avatar, worth, day, at }`；`board` 接口返回前 20 名和自己的名次；内存里缓存整张列表，**任何一次落盘都作废**，下次看榜重新 `list('rank:')` 全量读。
- **【现状】所有人默认上榜**，没有同意、没有匿名。
- **【现状】旧分支 `claude/earth-networth-board`** 就是 PR #21 合并前的版本（2 个提交），内容已全部在 main，没有额外可借的东西。
- **【现状】安全审查**（`security-review.md`）里和榜单有关的：S-05「灌满排行榜」（已用每来源每小时 20 个新角色缓解）、S-07 榜单插 HTML 已全部过 `esc()`；`save-sync.md` R2「榜单缓存每次写入都作废，下一次看榜要 list 全部 rank:」，建议「定期汇总」。
- **【现状】统计分支 `claude/earth-analytics`**（PR #50，未合并）：埋点走单独的 `@STATS` 实例，不碰 `rank:`；注册日存在 `born:<h>`。和本分支没有键名冲突（见 §9）。

- 同分时：先达到这个值的在前（每一项单独记达到时间 `ats`），再同分按哈希排，保证稳定。

## 3. 三种榜

| 榜 | 谁在上面 | 状态 |
| --- | --- | --- |
| 全服 | 所有同意上榜、不在复核期的玩家 | 【新】 |
| 地区 | 本赛季**登记地区**相同的人。登记地区 = 本赛季第一次落盘时存档所在的州（`state.region`，现在只有 `wa` / `sa`），**整季不变**，之后去哪都不跟着变。玩家可以关掉「参加地区榜」 | 【新】 |
| 好友 | 自己 + 存档里「常遇见的人」（`met`，一起做过共同事件或交易过的玩家，最多 30 人），且对方没关掉「在好友榜显示」 | 【新】 |

- 游戏里还没有玩家之间的「加好友」，所以第一版用 `met` 当好友名单。**【提议】**等社交分支（`claude/earth-social-npc` 做的是 NPC 知己，不是玩家好友）或以后的玩家好友功能有了正式名单，把 `lbBoard()` 里取 `met` 的一行换掉即可。
- `met` 是单向的：我记得你，你不一定记得我（比如对方后来删档）。好友榜只看看榜人自己的名单。

## 5. 隐私

- **上榜要本人同意**【新】：默认**不上榜**（`lbp:<h>` 不存在 = 不同意）。没同意的玩家照样能看榜、看到自己的成绩，卡片上有「用昵称上榜」「匿名上榜」两个按钮。
  - **这是行为变化**：旧版所有人默认在净资产榜上。上线后旧玩家全部下榜，要自己点同意才回来。
  - **旧玩家弹一次提示**【新】（用户 2026-11-20 定）：新角色建好时就写一条「不上榜」设置（`lbp:<h>`，`at` = 建号时间）；没有这条设置的就是改版前的旧角色。旧角色读档（`get`）时服务端在响应里带 `lbAsk: true`，页面在没有事件、没有事件结果时弹一个窗：说明改版和隐私，三个按钮「用昵称上榜」「匿名上榜」「暂不上榜」。三个都会写下 `lbp:`，所以**只问一次，换设备也不再问**；回答没发出去（断网）的话下次读档再问。只在 `get` 带，`act` 等不带，免得每个动作多读一个键。
- **匿名**【新】：榜上显示「匿名旅人 👤」，名字和头像都不发给别的客户端（服务端在 `lbView()` 里替换，不是页面隐藏）。徽章照常显示。
- **不暴露位置**【新】：发给客户端的行只有名次、名字（或匿名）、头像、分数、游戏天数、是不是自己、徽章。没有地点、坐标、地区、id 或哈希（测试锁住）。地区榜只按「本季第一次落盘时在哪个州」分，关掉地区榜就不出现在任何地区榜上。
- 设置项四个开关：上榜、匿名、地区榜、好友榜（`boardpref` 接口，只认布尔值，要同步码）。不是游戏进度：不改存档、不要版本号、不占动作。
- 导出数据（`export`）多了 `leaderboard: { pref, titles, season }`；删号时一起删 `lbp:`、`lbt:`、前后三季的 `lbs:`，内存索引同步删掉。

## 6. 反作弊

- **服务端计算**【现状 + 新】：所有榜单数值都在 `persistMany()` 里从刚结算完的权威存档算（`lbEntry` / `lbSeasonRec`），客户端没有任何写榜单的途径；`boardpref` 只能改四个布尔开关。比赛积分只在服务端共同事件结算时记。
- **异常值复核**【新】：每次落盘把新数值和上一条榜单记录比，涨得超过下面的线就**挂起** `LB_HOLD_DAYS` = 7 天（**待平衡**）：不上任何公开榜，本人看到「复核中」，这一季被挂起过的人赛季结算时不发奖，名单记进 `lbrev:<赛季>`。游戏本身不受影响（动作照常结算）。

  | 规则（`LB_ANOMALY`，均**待平衡**） | 线 |
  | --- | --- |
  | 一个动作净资产涨幅 | $40,000 × 这次落盘跨过的动作数 |
  | 一小时（现实时间）净资产涨幅 | $200,000 |
  | 一个动作新增打卡地点 | 3 × 动作数 |
  | 一个动作图鉴完成度涨幅 | 100‰ × 动作数 |
  | 一个动作声望涨幅 | 60 × 动作数 |
  | 打卡地点数超过世界上的打卡点总数 | 直接挂起 |

  - 动作数 = 这次存档版本号 − 上一条记录的版本号（共同事件、交易一次也是 +1）。只看涨不看跌。旧代码写的记录没有版本号时只做绝对值检查。
  - 线怎么定的：按模拟报告里机器人「单个动作最大涨幅」留余量（§8）。真实玩家有模拟里没有的来源（交易、周目标、二手摊、GPS 打卡），**线上可能误判**；所以挂起会自动到期，不永久下榜。
  - **【提议】人工复核工具**：第一版没有管理接口（加一个就要加管理员凭证，属于安全决定，交给用户）。现在只能用 `wrangler` 看 `lbrev:` 和带 `hold` 的 `rank:` 记录。
  - **残余风险**：小号通过送礼、二手摊、共同事件给大号刷（S-15），每个动作都不超线就不会被挂起。比赛积分有每天封顶；身家、声望没有，**【提议】**结合 S-15 的「新角色 N 天内不能交易」一起定。
- **GPS 伪造**：打卡榜直接继承 S-01/S-02 的残余风险（模拟定位 App）。S-01 的速度/精度检查在 `claude/earth-gps-anticheat-3d8db4`。

## 7. 性能：DO 内聚合和缓存

- 所有存档都在 `@SAVES` 一个实例里，榜单就在这里聚合。
- **内存索引**【新】：第一次看榜时把 `rank:`、`lbp:`、`lbs:<当前赛季>:`、`lbt:` 整批读进内存（每人一条 `LbItem`），之后每次落盘、改设置、结算**就地更新**，不再整表重读（解决 save-sync R2 的「每次写入都作废、全量 list」）。读入期间发生的写入记下来，读完再补（测试覆盖）。换季时重新读。
- **排名缓存**【新】：全服和地区榜按「维度 | 范围 | 地区」缓存排好的列表 `LB_CACHE_MS` = 30 秒（**待平衡**）；期间的普通落盘不触发重排。改上榜设置、删号、发称号时清缓存；看榜时还会把已退出、被挂起、删了号的人再滤掉一次，不等缓存过期。好友榜最多 31 人，现排不缓存。
- 代价：每次落盘多读 1 个键（本季赛季记录，和原有的 `rank:` 一起并行读）、多写 1 个键（`lbs:`）。内存里每名玩家约几百字节；**【提议】**玩家数到几十万时改成只在内存里保留每个维度的前 N 名 + 每人自己的分数。
- 自己的名次在缓存期内可能比实际落后最多 30 秒；`mine.score`（自己的成绩）总是最新的。

## 8. 模拟（`npm run earth:sim -- --days=180 --runs=100`）

2026-11-20 在本分支和 main（4f9c9e5）各跑一次，180 天 × 每种策略 100 个种子：

- **原有各表与 main 逐字相同**（`diff` 只有新增的一节）。规则引擎没改：榜单只读存档、不改存档，赛季奖励只有称号，比赛积分不进存档。
- **新增「排行榜」一节**（`tools/earth/balance/sim.ts`）：每个成功动作后用服务端同一个 `lbEntry()` 算榜单记录，现实时间按每个动作 10 秒算。

| 策略 | 单个动作最大涨幅：净资产 | 声望 | 图鉴‰ | 触发复核 | 期末净资产 / 声望 / 图鉴（中位） |
| --- | --- | --- | --- | --- | --- |
| 咖啡店上班族 | $288 | 6 | 0 | 0% | $28,067 / 88 / 0‰ |
| 救生员 | $384 | 6 | 0 | 0% | $35,318 / 90 / 0‰ |
| 矿工 | $900 | 6 | 30 | 0% | $74,396 / 78 / 0‰ |
| 打零工的背包客 | $900 | 6 | 61 | 0% | $177 / 254 / 424‰ |
| 保守背包客 | $250 | 4 | 0 | 0% | $751 / 72 / 0‰ |
| 什么都不干 | $250 | 4 | 0 | 0% | $4 / 46 / 0‰ |
| 酒保 | $300 | 6 | 0 | 0% | $30,525 / 92 / 0‰ |
| 农场工 | $384 | 6 | 61 | 0% | $22,181 / 100 / 30‰ |
| 咖啡店 + 共同事件（三种搭档假设） | $288 | 6 | 0 | 0% | 约 $33,000 / 135–141 / 0‰ |

（「最大」是 100 个种子里每个机器人单个动作最大涨幅的最大值；p99 和最大相同。）

怎么读：
- 1,100 个机器人没有一个碰到复核线。线和机器人实际最大涨幅之间留了很大余量（净资产约 44 倍、声望 10 倍、图鉴约 1.6 倍）。
- 余量大是因为模拟里**没有**的来源：GPS 打卡奖励、交易和二手摊、周目标领奖、事件里的大额现金、房产一次性操作。这些在线上可能更大，所以线先放宽；要不要收紧，等 Codex 看线上 `lbrev:` 和挂起记录再给建议。
- 图鉴单个动作最大 61‰（一次见到两种新动物/鱼）离线 100‰ 最近，图鉴加了新动物或新鱼后分母变大、单种的千分比会变小，不会更容易误判。
- 机器人不用真实定位，打卡维度测不到；比赛积分只在服务端记，没模拟。
- 赛季长短（4 周）对各维度能拉开多大差距，模拟只跑游戏日，换算不到现实周，没有结论。
