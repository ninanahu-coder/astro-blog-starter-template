## 1. 需求：每小时怎么掉，活动怎么恢复

### 1.1 消耗公式【现状】

`src/game/core/vitals.ts`（第 23 批从 `engine.ts` 挪过来，数值没改）：

```
需求(t + Δ分钟) = clamp(需求(t) − DECAY[k] × 特质衰减倍率[k] × Δ, 0, 100)
特质衰减倍率 = 所有特质 mods.decay[k] 连乘（没有就是 1）
```

| 需求 | 每分钟 | 每小时 | 从 80 掉到 0 | 特质修正 |
| --- | --- | --- | --- | --- |
| 饱食 hunger | 0.07 | 4.2 | 19.0 小时 | 运动健将 ×1.15 |
| 精力 energy | 0.05 | 3.0 | 26.7 小时 | — |
| 清洁 hygiene | 0.035 | 2.1 | 38.1 小时 | 爱干净 ×1.5 |
| 娱乐 fun | 0.04 | 2.4 | 33.3 小时 | 没心没肺 ×0.7 |
| 社交 social | 0.03 | 1.8 | 44.4 小时 | 自来熟 ×1.3、独行侠 ×0.5 |

结算顺序（`applyEffect`）：**先流逝时间、再加效果里的需求**。所以「住旅馆 精力 +100」无论睡前多累，醒来都是满的——第 23 批起「满」是精力上限，见 §1.3。睡眠期间的衰减倍率也见 §1.3。

### 1.3 体力（精力）与隐藏属性【新 · 已落地，待平衡】

模拟人生类游戏的做法：看得见的需求条背后，有几项不显示的内部量互相牵动。本批按这个思路给「精力」（玩家说的体力）建了一套关系，代码在 `src/game/core/vitals.ts`，系数集中在 `HIDDEN`。

**参考（只借机制，不拷代码）**：[alexcu/motive-simulator](https://github.com/alexcu/motive-simulator)（C，Don Hopkins《The Soul of The Sims》里动机代码的移植）和它的 Go 移植 [Flokey82/simmotive](https://github.com/Flokey82/simmotive)。两个仓库都没有许可证，所以只读机制。它的核心是：看得见的 Energy、Hunger、Hygiene 等动机，被隐藏的 Alertness（醒 / 睡）、Stress、Comfort 牵动——睡着时饱食和膀胱掉得慢、娱乐和压力被削减；压力大会让饥饿加快；吃东西会回一点精力。

| 借了 | 没借（原因） |
| --- | --- |
| 睡着时衰减变慢、精力不降 | 膀胱、舒适度、环境三项动机：游戏里没有对应的玩法，加了只是多几条要维护的数 |
| 压力牵动饥饿 | 心情分「现在 / 今天 / 本周 / 一生」四层平滑：本游戏心情是现算的，加时间层要改存档 |
| 内部量不显示、只在角色页「派生属性」里解释 | 压力过高随机「发脾气」：引擎随机数只来自 seed，额外的随机事件会改变所有既有结果 |

#### 体力的三种增加途径

| 途径 | 规则 | 来源 |
| --- | --- | --- |
| **时间自动恢复** | 睡觉（住旅馆、露营、回家睡、睡车）：睡着期间精力不降，醒来加的精力 × 恢复系数；「歇一会儿」+4 | 睡眠规则【新】；歇一会儿【现状】 |
| **医药 / 补给（临时）** | 外带咖啡 +20、电解质冲剂 +12、饮用水 +6（精力）；**复合维生素**（$18，新）：72 小时内健康自然恢复 ×2；急救包健康 +25、看医生健康 +60 | 维生素【新，待平衡】，其余【现状】 |
| **运动（永久）** | 体能、力量、游泳涨 → 体质涨 → 精力上限变高、干活更省力、睡觉回得更多 | 公式【新，待平衡】 |

精力在存档里仍是 0–100。上限只限制**增加**：精力本来高于上限（老存档、或者上限因为健康下降而变低）时，增加不会把它拉低，只是随时间正常衰减。

#### 隐藏属性

| 隐藏属性 | 公式 | 影响什么 | 来源 |
| --- | --- | --- | --- |
| 体质 | 体能 × 0.5 + 力量 × 0.3 + 游泳 × 0.2 | 下面三项；吸引力 | 【现状】派生属性 |
| 精力上限 | min(100, 80 + 体质 × 0.2)：体质 5 → 81、50 → 90、100 → 100 | 所有精力增加的天花板 | 【新，待平衡】 |
| 体力消耗系数 | 1 − 体质 / 250（0.6–1） | 活动和上班消耗的精力 × 它 | 公式【现状】，原来只用于真实地点训练；用于活动和上班【新】 |
| 恢复系数 | 0.75 + 健康 / 400 + 体质 / 400（0.75–1.25） | 睡觉回的精力 × 它 | 公式【现状】，原来只用于真实地点吃饭和看病；用于睡觉【新】 |
| 压力（页面上叫「身心紧绷」，和心情里的心事「压力」区分，见 mood.md） | clamp((40 − min(娱乐, 社交)) / 40, 0, 1) | 醒着时饱食衰减 × (1 + 0.25 × 压力) | 【新，待平衡】 |
| 睡眠 | 动作上的 `asleep` 标记 | 睡着时衰减倍率：精力 0、饱食 0.5、娱乐 0.5、社交 0.5、清洁 1；睡着时只看饱食是否见底 | 【新，待平衡】 |
| 状态系数 | 心情 × 健康 × 疲劳（0.3–1.5） | 训练收益、工资表现 | 【现状】 |

真实地点的训练、跑步、吃饭公式里已经乘过体力消耗或恢复系数，不再走 `bodyScaled()`，避免乘两次。

#### 相互关系

```
体能 / 力量 / 游泳 ──▶ 体质 ──┬─▶ 精力上限（高）
                              ├─▶ 体力消耗系数（低 = 省力）──▶ 活动、上班扣的精力
                              └─▶ 恢复系数（高）──▶ 睡觉回的精力
健康 ─────────────────────────┴─▶ 恢复系数；状态系数
饱食、精力 ≥ 50 ──▶ 健康自然恢复（维生素 ×2）     饱食或精力见底 ──▶ 掉健康
娱乐、社交 < 40 ──▶ 压力 ──▶ 饱食掉得快
睡着 ──▶ 精力不降、饱食 / 娱乐 / 社交减半、不算压力
需求（平均与短板）+ 特质 + 住处 + 心情状态 ──▶ 心情 ──▶ 检定、状态系数
```

## 2. 能力：怎么涨，要不要退步，要不要递减

### 2.1 成长公式【现状】

`engine.ts` 的 `growSkill()` 是能力变化的唯一入口：

```
实际增长 = 原值 × 特质成长倍率[k] × 心情状态成长倍率 × 0.35 × max(0, 1 − 当前值 / 110)
扣减（原值 < 0）不打折；结果钳制到 0–100
```

- **用进则长**：只有做事才涨，来源是活动、上班（`shift.skills`）、课程（`gain` 直接进 `growSkill`）、自驾（驾驶 + 公里 / 150，走土路另加生存 + 公里 / 300）、事件、帮 NPC 忙。
- **状态系数**【现状】：健身、游泳两个活动，和真实地点的训练、跑步、游泳，原值再乘 `efficiency.total`（心情 × 健康 × 疲劳，0.3–1.5）。其他活动不乘。
- 心情状态成长倍率：只有「专注」×1.25（自习得到，6 小时）。

### 2.2 上限递减【现状，不改】

递减已经有了，越高越慢：

| 当前值 | 递减系数 1 − 值/110 | 健身一次力量（原值 3，无特质、状态 1） |
| --- | --- | --- |
| 5 | 0.955 | +1.00 |
| 30 | 0.727 | +0.76 |
| 50 | 0.545 | +0.57 |
| 80 | 0.273 | +0.29 |
| 95 | 0.136 | +0.14 |

理论上永远到不了 110，被钳在 100。模拟里重复做同一件事的策略 180 天能到 96–100（见 balance-report 的能力表），所以「满级」是可达的。本批不改这条曲线。

### 2.3 要不要退步【提议，两个方案并列，不选】

现状：能力只涨不退（README、features.md §3.3 都写了「目前不会退步」）。

| | A：保持不退步（现状） | B：久不练会生疏 |
| --- | --- | --- |
| 公式 | — | 某项能力连续 `IDLE_DAYS`（建议 14）个游戏日没涨过：每周掉 `RUST`（建议 0.5），不低于保底 = max(出身起步值, 历史最高 × 0.6) |
| 要改的存档 | 无 | 新增 `skillDay: Record<SkillKey, number>`（每项最近一次涨的游戏日）；`sanitizeState` 要补；老存档按当前游戏日补齐，不会一上线就掉 |
| 好处 | 简单；玩家不会因为出门旅行被惩罚 | 给「换一种生活」一点代价，职业门槛重新有意义 |
| 坏处 | 180 天后多数主能力接近满分，检定和门槛逐渐失效 | 和「在路上」的核心玩法冲突：旅行一个月回来升不了职；要在角色页解释 |

结算点建议放在每周结算 `weeklyTick()` 里，和房租同一时刻，避免每次时间流逝都扫一遍。是否要做由用户定，数值交给 Codex。

### 2.4 街头没有成长渠道【提议，数据层】

现状：街头只有逛市集 +1 和几个事件选项涨。候选（只改数据，全部待平衡）：

- 逛市集街头 +1 → +1.5；
- 街头表演加街头 +0.5；
- 捡空瓶换押金加街头 +0.5；
- 真实地点的市集、二手店类动作加街头。

和 initial-stats.md 的 Codex 问题 2 合并处理。

## 3. 健康、心情、声望、麻烦值

### 3.1 健康（0–100）

| 变化 | 公式 | 来源 |
| --- | --- | --- |
| 饿 / 累见底掉血 | `− 1.2 / 小时 × 见底后的分钟数 / 60` | **【新 · 已落地】**计算方式；速度【现状】未改 |
| 吃饱睡足回血 | `+ 0.25 / 小时 × 饱食和精力都 ≥ 50 的分钟数 / 60`，每天最多 +6 | **【新 · 已落地，待平衡】** |
| 睡觉 | 住旅馆 +15、露营 +5、回家 15 + 舒适度、睡车按车型 | 【现状】 |
| 看病 | 诊所 +60（$80）；真实医院 35 × 恢复系数（$45） | 【现状】 |
| 急救包 | +25 | 【现状】 |
| 复合维生素 | 72 小时内自然恢复 × 2（心情状态「吃了维生素」的 `regen`） | 【新，待平衡】 |
| 受伤 | 事件 `health < 0` × 特质受伤倍率（皮糙肉厚 0.7） | 【现状】 |
| 晕倒后 | 设为 50 | 【现状】 |

**见底时间**（`vitals.ts` 的 `minutesTo`）：`见底分钟 = min(饱食 / 饱食衰减速度, 精力 / 精力衰减速度)`；`掉血分钟 = max(0, Δ − 见底分钟)`。

- 旧规则：只看这段时间**结束时**饱食或精力是否为 0，是就整段都掉。例如饱食 7 去露营 8 小时，旧规则掉 480 分钟的血（−9.6），新规则只掉见底后的 380 分钟（−7.6）。已经见底的情况两者相同。
- 回血门槛同理：`回血分钟 = min(Δ, (饱食 − 50) / 饱食衰减速度, (精力 − 50) / 精力衰减速度)`，低于 50 为 0。回血和掉血不会同时发生。
- 健康的作用【现状】：状态系数 `0.6 + 0.4 × 健康 / 100`、恢复系数 `0.75 + 健康 / 400 + 体质 / 400`。

### 3.2 心情（0–100，现算不落盘）【现状，不改】

```
心情 = round(需求平均 × 0.75 + 需求最低 × 0.25) + 特质 mood + 住处舒适度 + 生效中心情状态之和，钳制 0–100
档位：< 25 低落（检定 −10）· < 50 一般 · < 85 愉快（+5）· ≥ 85 亢奋（+10）
```

心情同时进状态系数 `0.7 + 0.6 × 心情 / 100`，所以影响训练收益和工资表现。
