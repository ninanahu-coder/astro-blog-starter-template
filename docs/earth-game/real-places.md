# 真实地点与公式模块

玩家本人拿着手机走到真实的餐馆、健身房、公园、图书馆、超市，打开定位，就能在游戏里做对应的事：吃饭补体力、花钱；上班赚钱、耗体力；健身耗体力、涨力量和魅力。

代码：`src/game/core/formulas.ts`（公式与派生属性）、`src/game/core/venues.ts`（真实地点引擎）、`src/game/data/venues.ts`（地点类型、动作、定位规则）。测试：`tests/earth/venues.test.ts`。

## 1. 数据来源：为什么是 OpenStreetMap 而不是 Google 地图

- 手机的定位（GPS）本身不属于哪家地图，浏览器的 `navigator.geolocation` 直接给出坐标，Google 地图 App 用的也是这个。
- “附近有哪些餐馆、健身房”这份**地点数据**不能用 Google Places：它的条款不允许把结果缓存进自己的数据库或和别家地图混用，按次计费，而且仓库规则（`AGENTS.md`）只接受 OSM / Wikidata / seed 来源。
- 所以地点数据只从 OSM 来：`npm run earth:fetch-venues` 经 Overpass API 按类型查询，原样转成 `tools/earth/openclaw/inbox/venues-<日期>.json`（坐标、名字、OSM 编号都不经人工或模型改写），再由 `npm run earth:venues` 校验写进 `src/game/data/wa.venues.json`。
- 当前数据：2026-11-13 采集的珀斯、弗里曼特尔中心 5 公里内 649 个地点（餐馆、快餐、咖啡馆、酒吧各 80，公园 80，健身房 70，诊所 71，超市 60，体育中心 30，图书馆 15，游泳池 3）。查询语句和统计在同目录的 `venues-2026-11-13.meta.txt`。
- 本该由 OpenClaw 采集，但现有 agent 没有一个同时能联网和写项目文件，所以改成确定性脚本；以后 OpenClaw 采集新地点时直接跑这个脚本即可。

## 2. 流程

```
手机定位 ──▶ 「附近」页：列出 1.5 公里内收录的地点和能做的事（本机算，只是预览）
           └─ 点某个动作 ──▶ 重新定位 ──▶ 游戏里不在这个地点就先「真实抵达」
                            ──▶ POST act { t:'venue', venue, op, lat, lon, acc }
                                 服务端带上现实时间 now ──▶ venueAction() 结算
```

服务端依次检查：

| 检查 | 规则（`FIX_RULES`） | 不通过时 |
| --- | --- | --- |
| 精度 | 定位误差 ≤ 150 米 | “到开阔处再试” |
| 速度（防瞬移） | 和上一次成功定位相比，相距超过 2 公里时推算速度不能超过 200 km/h | “定位跳得太快，N 分钟后再试” |
| 距离 | 离地点 ≤ 类型半径 + min(误差, 50 米)；餐馆 60 米、公园 250 米 | “你离 X 还有 N 米” |
| 游戏地点 | 游戏里也要在这个地点（界面会自动先做一次真实抵达） | “先用真实定位抵达 X” |
| 冷却 | 同一种动作按**真实时间**间隔，换一家店也算 | “N 分钟后可以再 X” |

现实时间只在服务端取（`Date.now()`），作为参数传进纯函数引擎；客户端发来的动作里没有时间字段，改不了冷却。

## 4. 公式

### 4.1 派生属性（二级属性）

借鉴经典 RPG「一级能力 → 二级属性」的做法，由已有的 7 项能力和状态现算，不落盘：

| 属性 | 公式 | 用在哪 |
| --- | --- | --- |
| 体质 | 体能 × 0.5 + 力量 × 0.3 + 游泳 × 0.2 | 下面三项 |
| 吸引力 | 魅力 + 体质 × 0.15 + (心情 − 50) / 10，清洁 < 30 时 −10 | 角色页展示；以后给社交检定用 |
| 体力消耗系数 | 1 − 体质 / 250（0.6–1） | 训练、运动、上班的体力消耗 |
| 恢复系数 | 0.75 + 健康 / 400 + 体质 / 400（0.75–1.25） | 吃饭回的体力、看病回的健康 |
| 状态系数 | 心情项 × 健康项 × 疲劳项，钳制 0.3–1.5 | 真实地点的训练收益和工作表现；游戏内「健身」「下海游泳」的能力成长 |

状态系数的三项：心情 0.7 + 0.6 × 心情 / 100；健康 0.6 + 0.4 × 健康 / 100；疲劳：体力 ≥ 40 时为 1，否则 0.5 + 0.5 × 体力 / 40。借鉴的是模拟人生类游戏里“情绪影响技能成长和工作表现”。

### 4.2 吃饭（借鉴农场经营类游戏的食物换算）

- 价格 = 8 × 档次^1.6 × 特质花费倍率：档次 1 $8、2 $24、3 $46、4 $74
- 饱食 = (20 + 15 × 档次) × 胃口；胃口 = max(0.2, 1 − 当前饱食 / 140)，吃撑了收益递减
- 体力 = 饱食回复 × 0.4 × 恢复系数；咖啡馆饱食 ×0.6，另加体力 +12
- 档次 ≥ 3 给心情状态「吃了顿大餐」（+8，12 小时），否则「吃得很满足」

对比游戏里原有的「吃顿饭」（$18，饱食 +55，不加体力）：去真实的店吃，同样的钱多回一些体力，作为跑一趟的回报。

### 4.3 训练（借鉴文字类 MMO 的健身房公式和超量恢复）

- 体力消耗 = 25 × 体力消耗系数；体力不到消耗 + 5 不能练
- 成长 = 基础值 × 场地质量 × 状态系数 × 恢复；基础值：力量 3、体能 1.5、魅力 0.8；场地质量：健身房 1、体育中心 0.8
- 恢复：每次练完都得到「肌肉酸痛」（12 小时，心情 −3）；身上有酸痛时再练只有一半效果。没酸痛时练完另得「练完很精神」
- 成长最后再经过统一的递减（`growSkill`：越接近满分涨得越慢），所以高属性练起来更难，和原公式一致
- 门票 $10

“心情越好练得越有效、属性越高越难涨、隔开练比连着练有效”这三条，对应的是那类健身房公式里“快乐值放大收益、属性越高收益越低、体力是训练的货币”。

### 4.4 真实上班

- 第一次点「打上班卡」，离开前在**同一地点**再点「打下班卡」，按两次之间的真实分钟计薪：至少 15 分钟，一次最多 8 小时，每个现实日最多 8 小时；上班卡超过 16 小时没打下班卡作废
- 时薪：有对应职业时（咖啡店 → 咖啡馆 / 餐馆 / 快餐店；救生队 → 游泳池）= max(当前等级工资 ÷ 班长小时, 零工时薪) × 1.05 到岗加成（`ON_SITE_BONUS`）；否则用类型的零工时薪（$21–24）
- 工资 = 时薪 × 小时 × 表现系数 × 能力加成；表现系数 = 0.7 + 0.3 × 状态系数；能力加成 = 1 + 相关能力 / 300
- 体力额外消耗 = 每小时 4 × 体力消耗系数（时间流逝的自然衰减另算），游戏时钟按真实时长前进
- 有职业且实地上满半个班：算作一个职业班次（表现系数 ≥ 1 记为表现好），可以升职；当天游戏里不能再上班

### 4.5 其他

- **自习**：得到「专注」（6 小时内所有能力成长 ×1.25）。心情状态新增了 `gain` 字段，`growSkill` 会乘上所有生效状态的倍率
- **跑步 / 游泳**：体力换体能（游泳另涨游泳、补清洁），收益乘状态系数
- **喝一杯**：$12 × 档次，社交 +40、娱乐 +20、魅力 +1.5 × 状态系数
- **采购**：$14 买 3 根能量棒 + 3 瓶水（便利店要 $27）
- **看病**：$45，健康 +35 × 恢复系数

## 5. 存档与隐私

新增字段：`fix`（最近一次成功定位，坐标保留 3 位小数，约 100 米精度，用于速度检查）、`venueCd`（各动作上次的现实时间）、`clockIn`（上班卡）、`realWork`（今天已计薪分钟）。

- 定位只在玩家点「定位」时取一次，不后台追踪；本机只放在内存里，不写 localStorage
- 存档里只留粗略坐标，不写进日志，不广播给其他玩家
- `sanitizeState()` 对这些字段做了范围和形状校验，旧存档补默认值

## 6. 已知限制与下一步

- **只覆盖珀斯和弗里曼特尔中心 5 公里**：其他地点要再跑采集脚本（`--locs=bunbury,albany --km=3`）。游泳池只有 3 个，OSM 上大多没标公共开放；OSM 的店铺可能已经关门而数据还没更新
- **定位可以伪造**：精度、距离、速度三道检查只能挡住粗糙的“瞬移”，挡不住慢慢伪造路线的人。Web 端拿不到系统级的模拟定位标记，真要防需要原生 App
- **没跟营业时间挂钩**：人在店里就默认开着；OSM 的 `opening_hours` 格式复杂，以后再接
- **经济影响只有推算**：数值模拟的机器人不会去真实地点。第六轮按 Codex 推算收紧了时薪和每日上限：无职业实地零工 8 小时约 $216，和游戏内零工时薪接近（见 `balance.md` 第六轮）
- **游戏内上班不乘状态系数**：心情已经通过检定影响工作表现，再乘会重复计算（第六轮 Codex 结论）。游戏内只有「健身」「下海游泳」的成长乘状态系数
