# 广告与商业化设计（第一版）

分支 `claude/earth-monetization`，2026-11-20。

**用户已定（2026-11-20）**：先做本地商户赞助，按「固定月费 + 每次核销」向商户收费。

代码做了两版：第一版是「赞助」标签的展示；第二版是核销（服务端核对定位、每天去重、每日上限）和对账单计算。商户付款走线下开发票，游戏里不接任何支付，也没有加任何广告 SDK。具体价格、和哪家商户签约，都要等用户决定。

本文涉及法律的部分只是整理公开资料，不是法律意见。正式上线前，要请澳洲执业律师审一遍。

## 0. 结论先行

| 优先级 | 模式 | 一句话 |
| --- | --- | --- |
| 1 | 本地商户赞助 | 跟「人到现场」玩法最契合，商户付的是到店客流的钱；不涉及玩家付费，合规面最小。**已定先做这一项**，展示和核销的代码已经写好。 |
| 2 | 外观内购 | 只卖家具外观和形象，不卖数值。需要先有支付渠道，并解决退款和未成年人的问题。 |
| 3 | 季票 / 会员（只含外观和便利） | 等外观内容够多以后再做，否则玩家会觉得不值。 |
| 暂缓 | 激励视频广告 | 要引入第三方广告脚本，涉及追踪、隐私，也影响加载速度。网页游戏的填充率和单价都不确定，收益可能很低。 |
| 暂缓 | 去广告 | 只有先做了激励视频之外的常驻广告，这一项才有意义。现在不建议做常驻广告。 |
| 不做 | 开箱、抽卡、付费随机奖励 | 见红线。 |

数值平衡的结论不由 Claude 下。下面各节「对平衡的影响」只列影响到哪些系统，要不要调、怎么调，按 AGENTS.md 交给 Codex 跑 `npm run earth:sim` 来分析。

## 1. 可选模式

### 1.1 本地商户合作（赞助打卡点和优惠券）

**玩法**：真实店铺（来自 `wa.venues.json`、`sa.venues.json`，OSM 来源）付费以后，在「出行 · 附近」的店铺卡片上：

- 标题旁边显示固定的「赞助」标签；
- 卡片里多一行优惠，例如「出示本页咖啡减 1 澳元」，写明使用条件和有效期，并注明「这是店铺付费推广」。

玩家人到店里，用现有的定位校验确认在店内，再打开优惠页给店员看。

| | |
| --- | --- |
| 优点 | 和「人到现场」的核心玩法完全一致。商户付费买的是真实客流，计费可以按核销次数，效果对商户可见。玩家不花钱，也不涉及玩家付费的法规（退款、未成年人付款、loot box 分级）。目标玩家是华人和留学生，很多华人商户本身就想吸引这个群体。 |
| 缺点 | 要人去谈、去签约，靠销售，扩张慢。核销要防刷，也要保证商户真的给了优惠，否则玩家会投诉到游戏头上。商户的饮食卫生、营业状态都不在我们控制之内。 |
| 对平衡的影响 | 第一版没有任何影响：赞助不改排序（仍按距离）、不改价格、不给经验或现金。如果以后想给「到赞助店打卡」加游戏内奖励，例如纪念章或图鉴，只能给外观或收集类的东西，不能给现金、能力成长、冷却缩短这类数值，并且要交给 Codex 做平衡分析。 |
| 开发量 | 展示（本轮已完成）：约 1 天。核销 + 商户后台 + 防刷：约 1–2 周，见第 5 节。结算对账（给商户开发票）：用现成的会计软件手工开，先不写代码。 |

### 1.2 激励视频广告

**玩法**：玩家自己选择看一段 15–30 秒的视频，换取一次小奖励。

| | |
| --- | --- |
| 优点 | 玩家不花钱，主动选择，体验上比插屏广告好。行业里很成熟。 |
| 缺点 | 必须引入第三方广告 SDK 或脚本。这和本仓库「不加第三方脚本」的原则相冲突，还会带来追踪 Cookie 和隐私告知的义务，首屏体积也会变大（`tests/earth/bundle.test.ts` 对首屏有上限）。网页上的激励视频填充率不稳定，按我们的玩家规模，收益可能很少。广告内容由广告网络投放，我们很难保证不出现博彩、酒类这类不适合未成年人的广告。 |
| 对平衡的影响 | 大。「看广告换奖励」本质上是用时间换数值，很容易变成变相的付费优势：广告奖励多了，就会逼着玩家去看。如果要做，奖励只能是外观类，或者每天封顶的少量便利，并且要先交给 Codex 跑模拟。 |
| 开发量 | 接入约 3–5 天，加上隐私告知、同意弹窗、年龄处理，约 1–2 周。 |

**建议**：暂缓，等玩家规模和隐私方案都清楚以后再评估。

### 1.3 外观内购（家具外观、形象）

**玩法**：用真钱直接买指定的外观，例如家具换皮、头像框、服装。价格直接标澳元，买之前就知道买到的是什么。

| | |
| --- | --- |
| 优点 | 不影响数值，最容易守住「不卖优势」的红线。玩家买的是明确的东西，没有概率。 |
| 缺点 | 要有美术产出，而且要持续出新。需要接支付（见第 4 节），还要处理退款、发票、GST，以及未成年人用家长的卡付款的问题。 |
| 对平衡的影响 | 要检查的一点：现在的家具（`src/game/data/furniture.ts`）可能带有数值效果。外观内购只能卖「换皮」，不能卖带效果的家具本体；换皮和原物品的效果必须完全一样。这一点要在代码里用测试锁住。 |
| 开发量 | 支付接入和服务端订单约 1–2 周，外观系统（换皮数据结构、展示）约 1 周，美术另算。 |

**定价原则**：

- 直接标澳元，含 GST。
- 不设中间的游戏代币。如果设了代币，玩家就看不清真实花了多少钱，ACCC 和新的不公平交易法规都在关注这类做法，见 3.2。
- 不做限时倒计时、「仅剩 X 件」这类制造紧迫感的设计。

### 1.4 季票 / 会员

**玩法**：按季付费，内容只能是外观奖励和便利功能，例如更多存档备注、额外的相册位。

| | |
| --- | --- |
| 优点 | 收入稳定，玩家觉得划算。 |
| 缺点 | 自动续费有额外义务：续费前提醒、取消要方便（具体义务要律师确认）。用微信支付做自动续费，在 Stripe 上还在私人预览，见第 4 节。季票内容要有足够产出，否则就是在卖空头支票。 |
| 对平衡的影响 | 如果季票里含有「经验加成」「冷却缩短」，就是在卖数值，违反红线，所以不能有。便利功能也要逐条看会不会变成优势。 |
| 开发量 | 在外观内购之上再加约 1–2 周，用来做订阅状态、续费提醒和取消入口。 |

**建议**：先做一次性购买的「季度外观包」，不做自动续费，等确实有需求再加订阅。

### 1.5 去广告

只有存在常驻广告（横幅、插屏）时，去广告才有意义。本方案不建议做常驻广告，所以这一项暂时不需要。

如果以后做了激励视频，它本来就是玩家自愿看的，没有「去」的必要。商户赞助的标签也不应该能付费去掉：它是给玩家的信息披露，不是打扰。

## 2. 红线（写进代码审查清单）

1. **不卖数值优势，不做 pay-to-win。** 任何真钱能买到的东西，都不能影响现金、能力、需求、冷却、成功率、工资、房租。外观和原物必须效果一致，用测试锁住。商户赞助不改排序、不给数值奖励（本轮已有测试：核心结算代码不得引用赞助数据）。
2. **不做开箱、抽卡、付费随机奖励。** 不允许花真钱、或者花能用真钱买到的东西，去换取随机的奖励。按澳洲现行分级规定，这类内容会让游戏至少被评为 M。我们不做，也就不会触发这条规定，见 3.1。游戏里已有的随机事件，例如天气、钓鱼，都不能和付费挂钩。
3. **未成年人保护。**
   - 玩家里有留学生，可能有 18 岁以下的中学生。在年龄验证方案定下来之前，付费功能默认只对自己声明满 18 岁的玩家开放，并提示需要监护人同意。
   - 酒吧、诊所不接受赞助（代码里已经限制：`SPONSOR_EXCLUDED_TYPES`）。
   - 不投放博彩、酒类、烟草、电子烟广告。
   - 不对孩子做针对性营销：AANA 儿童广告准则把 15 岁以下视为儿童。
4. **广告必须标明。** 赞助内容固定显示「赞助」二字，标签的样式在浅色和深色主题下对比度都要达标（`tests/earth/contrast.test.ts` 已覆盖 `--tint-amber` 这一对颜色）。卡片里写明「这是店铺付费推广」。不得把广告伪装成游戏事件、NPC 对话或玩家评价。
5. **不写追踪代码。** 不加第三方广告 SDK 或脚本。数据统计只用自家的、匿名的统计（见分支 `claude/earth-analytics`）。

## 3. 合规整理（需律师复核）

下面每一条都注明了来源和核对方式。「已打开核对」指本轮直接打开官方页面读过原文；「二手来源」指只看到媒体或律所的转述，没能打开官方页面，上线前要再核一次。

### 3.1 Loot box 分级（国家分级制度）

- 2024 年 9 月 22 日起，含有「与概率相关的游戏内购买」（如付费开箱）的电子游戏，最低分级为 M（不建议 15 岁以下）。含有模拟赌博（如赌场类玩法）的游戏，最低分级为 R18+。
- 如果概率玩法不能直接或间接用真钱换取奖励，就不在这条规定的范围内。
- 来源：澳洲分级委员会公告 <https://www.classification.gov.au/classification-ratings/new-classifications-for-gambling-content-video-games>（**二手来源**：本轮打开这个页面超时，内容来自搜索摘要和媒体报道，如 <https://www.gamedeveloper.com/business/games-featuring-paid-loot-boxes-will-soon-receive-a-mandatory-m-rating-in-australia>）。
- **对我们的意义**：只要守住红线第 2 条，就不会触发这条分级规定。注意：游戏里任何类似「转盘」「赌场」的小游戏都可能被认定为模拟赌博，就算不花钱也可能触发 R18+，所以都不要做。
- **同站风险（本轮发现，没有改动）**：同一个站点里有 `/baccarat`、`/baccarat-online` 两个百家乐页面，顶部导航也有入口。页面注释写的是「虚拟筹码、模拟支付、无真实扣款」，所以不属于真钱赌博，但它是典型的模拟赌博。如果「地球人生」将来要以游戏身份送审分级、上架应用商店，或者对未成年人开放付费，最好先让律师评估：同一个域名、同一个导航里有模拟赌博内容，会不会被一并考虑。最稳妥的做法是不要让游戏里出现指向这两个页面的链接。

### 3.2 澳洲消费者法（ACL）

- ACL 是《2010 年竞争与消费者法》（Competition and Consumer Act 2010）的附表 2。第 18 条禁止误导或欺骗性行为，第 29 条禁止虚假或误导性陈述。来源：<https://www.legislation.gov.au/C2004A00109/latest>（**本轮没有打开核对**，条号是常识性引用，上线前要核对原文）。
- **消费者保证**：数字商品也受 ACL 的消费者保证约束，有重大问题时不能一律写「概不退款」。（**要律师确认**数字内容的具体适用方式。）
- **滴漏定价和游戏代币**：澳洲正在立法禁止不公平交易行为，其中包括滴漏定价（drip pricing）。律所的分析认为，它可能适用于用游戏代币、复杂换算来掩盖真实花费的做法。生效日期有报道说是 2027 年 7 月 1 日，**未核对官方来源**。来源（二手）：Gilbert + Tobin <https://www.gtlaw.com.au/insights/game-on-unfair-trading-practices-and-online-gaming>、Allens <https://www.allens.com.au/insights-news/insights/2026/07/australias-new-unfair-trading-practices-regime-what-businesses-need-to-know/>、ACCC 价格展示页面 <https://www.accc.gov.au/consumers/pricing/price-displays>。
- **对我们的意义**：直接标澳元，不设代币；页面上显示的价格就是最终价格（含 GST）；商户优惠写清条件，「出示即减 1 澳元」就必须真能减。如果商户不兑现，要有下架机制，见 5.5。

### 3.3 广告标准（AANA）

- **AANA 道德准则第 2.7 条**：广告必须让相关受众能清楚地分辨出这是广告。这一条 2017 年 3 月 1 日生效，2021 年改过措辞。来源：AANA <https://aana.com.au/advertising-must-be-clearly-distinguishable-to-consumers/>（**二手来源**：只看到搜索摘要，条文原文要在 AANA 网站核对）。
- **AANA 儿童广告准则**：2023 年 12 月 1 日生效，适用于所有针对儿童的广告。准则里的「儿童」指 15 岁以下。来源：Ad Standards 的准则速览 <https://adstandards.com.au/wp-content/uploads/2024/05/Code-of-Ethics-at-a-glance.pdf.pdf>（**已打开核对**生效日期），15 岁的定义来自 AANA 页面 <https://aana.com.au/self-regulation/codes-guidelines/aana-code-for-advertising-marketing-communications-to-children>（**二手来源**）。
- **对我们的意义**：「赞助」标签和「付费推广」说明就是为了满足第 2.7 条。我们的玩家主要是成年留学生，但不能排除未成年人，所以赞助内容按「可能有儿童看到」的标准来审：不做酒类，不用名人或流行角色。

### 3.4 隐私

- **《1988 年隐私法》和澳洲隐私原则（APPs）**。年营业额不超过 300 万澳元的小企业，原则上可以豁免，但有例外，比如交易个人信息的企业。来源：OAIC <https://www.oaic.gov.au/privacy/privacy-guidance-for-organisations-and-government-agencies/organisations/small-business>（**本轮打开时被拒绝访问（403）**，门槛和例外要再核对）。不管是否豁免，都建议按 APPs 来做。
- **儿童网络隐私准则（Children's Online Privacy Code）**：《2024 年隐私及其他立法修正法》要求 OAIC 制定这份准则，必须在 2026 年 12 月 10 日前完成登记。征求意见稿 2026 年 3 月 31 日发布，生效日期还没确定。来源：OAIC <https://www.oaic.gov.au/privacy/privacy-registers/privacy-codes/childrens-online-privacy-code>、<https://www.oaic.gov.au/news/media-centre/oaic-releases-exposure-draft-of-the-childrens-online-privacy-code>（**二手来源**：只看到搜索摘要）。准则定稿后，要对照它检查游戏里的定位、统计和支付流程。
- **社交媒体最低年龄**：2025 年 7 月的规则把「唯一或主要目的是让用户一起玩网络游戏」的服务排除在 16 岁以下禁令之外。规则 2026 年 3 月修订过。来源：eSafety <https://www.esafety.gov.au/social-media-age-restrictions>（**二手来源**）。我们的游戏主要是游戏，但有在线频道。如果以后加了动态、发帖这类社交功能，要重新评估。
- **定位数据**：商户核销会用到定位，但只在服务端做比对，不交给商户。给商户的报表只有核销次数，不含玩家的身份、定位或名字。

### 3.5 GST

- 在澳洲卖数字商品，年营业额达到 7.5 万澳元就要注册 GST。（**本轮没有核对**，要会计确认。）用应用商店卖的话，商店会代收 GST；自己用 Stripe 收款，就要自己申报。

## 4. 支付渠道比较

只有外观内购和季票需要玩家付款，商户赞助是商户付钱给我们（开发票、银行转账就行，不需要接支付）。

费率都是「标准价格」，不含谈判后的定制价格。

| 渠道 | 费率 | 接入要求 | 适合我们吗 |
| --- | --- | --- | --- |
| **Stripe 银行卡** | 澳洲国内卡：2026-10-01 起 1.65% + 0.30 澳元（之前是 1.70% + 0.30 澳元）。国际卡：3.50% + 0.30 澳元，2027-04-01 起降为 2.80% + 0.30 澳元。来源：Stripe <https://support.stripe.com/questions/updates-to-card-pricing-in-australia-from-october-2026>（**已打开核对**）。需要换汇时，有媒体说另加 2%（二手来源：Wise <https://wise.com/au/blog/stripe-fees>）。 | 要有 ABN 或公司主体、澳洲银行账户。用托管的结账页（Checkout），服务端只收 webhook，前端不必加 Stripe 脚本。 | 适合。留学生大多有澳洲的银行卡。 |
| **Stripe 上的微信支付 / 支付宝** | 都是 2.9% + 0.30 澳元，需要换汇时另加 2%。来源：Stripe 澳洲本地支付方式价格页 <https://stripe.com/au/pricing/local-payment-methods>（**已打开核对**）。 | 澳洲的 Stripe 账户可以开通。微信支付只支持中国大陆的用户；要有完整的、能用的网站，清楚列出商品、价格和结账页；还要遵守微信支付的禁止类目规定。电脑上是扫码付款；文档里提到的手机流程是原生 App 拉起微信，**没有写手机网页里怎么付**，而我们玩家主要用手机网页，这一点要先测。微信支付不支持拒付（chargeback），退款要在 180 天内办理。微信支付的自动续费和小程序支付还在私人预览。来源：Stripe 文档 <https://docs.stripe.com/payments/wechat-pay>（**已打开核对**）。 | 适合作为第二种付款方式，但要先确认手机网页能用。 |

## 5. 商户合作的落地流程

### 5.1 店铺怎么对应

- 赞助只能挂在 `wa.venues.json`、`sa.venues.json` 里已经有的店铺上（`source: "osm"`），用店铺的 `id` 对应（例如 `osm-node-…`）。
- 如果商户的店铺不在 OSM 上，或者 OSM 上的位置、名字不对：请商户自己到 OpenStreetMap 上补充或更正（这是 OSM 社区的规则，我们不代改），再由 OpenClaw 下一轮采集带进来。**不能为了赞助手写店铺数据。** 这样也守住了 AGENTS.md「数据只来自 OSM、Wikidata、种子数据」的规定。
- 校验：`validateSponsors()` 会检查店铺存在、来源是 OSM、店铺类型允许（酒吧、诊所不行）、日期合法、一期不超过 92 天、同一家店同时只能有一条、文字里不能有网址或联系方式。

### 5.2 上架流程

1. **签约（线下）**：确认商户是这家店的经营者（ABN 查询、营业执照或租约）。签赞助协议，写明优惠内容、有效期、费用、不兑现时怎么处理。协议编号写进 `agreement` 字段，合同本身不放进仓库。
2. **审文案**：优惠不超过 40 字，条件不超过 80 字；不得有网址、电话、微信号；不得有夸大或误导的说法（例如「全珀斯最便宜」）；酒类、博彩、医疗相关的一律不接。
3. **写入数据**：在 `src/game/data/sponsors.ts` 加一条，跑 `npm test`（会用真实的店铺数据做校验）。
4. **上线、到期**：按珀斯日期自动生效、自动过期，到期不用手动下架。

商户数量多了以后，第 3 步可以改成商户后台加人工审核，见 5.5。

### 5.3 核销（第二版，已实现）

目标：商户能确认玩家真的在店里，而且这张优惠这个人今天还没用过；我们能统计核销次数，用来向商户收费。

1. 玩家在店铺判定范围内时，赞助卡片下方出现「使用优惠」按钮。点了以后手机重新定位，把坐标发给服务端（存档接口的 `action: 'redeem'`，和其他动作一样要同步码，也受同一个限流）。
2. 服务端 `redeemProblem()` 依次检查：赞助今天生效；店铺存在；定位可信，用的是和真实地点同一套 `fixProblem()`（精度不差于 150 米，和存档里上一次定位相比的移动速度不超过 200 公里/时）；人在店铺判定半径内。
3. 通过以后发一个 4 位核销码。码由「赞助编号 + 珀斯日期 + 玩家 id 的哈希」算出，同一个人同一天再点还是这个码，换一天就变。返回内容只有店名、优惠、条件、核销码和日期，不含玩家 id 或名字。
4. 玩家把核销卡给店员看。卡上有店名、优惠、日期和大号核销码，右上角的圆点一直在跳动，静态截图看得出来。
5. 服务端记账：同一个玩家、同一条赞助、同一个珀斯日期只记一次。每记一次，这条赞助当天和当月的计数各加一，三个键一次写入。商户设了每日上限（`dailyCap`）时，到上限就不再发码。
6. 核销**只读存档，不改存档**，不走 `applyAction()`，所以不影响任何游戏数值，也不会和其他动作冲突版本号。

**和计费有关的已知缺口（要用户决定）**：现在「核销一次」的定义是「玩家人在店里、点了使用优惠」，店员没有在系统里确认。所以玩家在店里点了却没真的用，也会计一次费。缓解措施有两个：每日上限，还有对账单里的数字和服务端记录是同一份。如果商户对计费有异议，下一步可以加「店员确认」：给每家店配一个店员 PIN，存在服务端、不进仓库，店员在玩家手机上输入 PIN，输对才计费。这要多做商户 PIN 的发放和重置，约 2–3 天。

### 5.4 防刷

- **定位作弊**：直接复用现有的定位校验（精度、距离、移动速度）。GPS 防作弊分支（`claude/earth-gps-anticheat-3d8db4`）合并以后，核销也自动受益。注意：核销不更新存档里的「上一次定位」，所以速度检查只和玩家上一次做真实地点动作或抵达时的位置比。
- **重复核销**：服务端按「玩家 + 赞助 + 珀斯日期」去重（已实现）。
- **商户账单失控**：每日上限由商户在协议里定，写进 `dailyCap`（已实现）。
- **小号刷**：每个小号都要有同步码、人要真的在店里，而且每个号每天只记一次。如果以后发现异常，再加门槛（例如账号满几天、做过几次真实地点动作），具体门槛看数据再定，本轮没做。
- **商户刷单**：收费是「固定月费 + 每次核销」，商户没有动机刷高核销次数；给商户看的数据和我们计费用的是同一份。某家店的核销异常集中时，人工复查。
- **玩家截图转发核销码**：卡片上的圆点在动，静态截图看得出来。转发录屏的情况挡不住，要靠店员 PIN（见 5.3 的已知缺口）。

### 5.5 商户后台（以后再做）

- 商户只能看到：自己的赞助状态、每天的核销次数。看不到任何玩家的身份、定位或名字。
- 商户可以提交新的优惠文案，但要人工审核后才能上线。
- 投诉通道：玩家可以在优惠卡片上反馈「店家没兑现」。累计到一定次数就自动暂停这条赞助。

### 5.6 收费方式（已定：固定月费 + 每次核销）

- 每条赞助在 `fee` 字段写两个数，单位是澳分、含 GST：`monthly`（月费）和 `perRedeem`（每次核销的费用）。具体价格按每份协议填，本轮不定：既没有本地同类产品的可靠公开报价，也没有我们自己的客流数据。
- **对账单**：`statementFor(赞助, 'YYYY-MM', 当月核销次数)`。月费按这个月里赞助生效的天数折算，四舍五入到分；再加上「核销次数 × 单次费用」。比如月费 300 澳元，12 月只生效 21 天，就收 300 × 21 / 31 ≈ 203.23 澳元，再加核销费。整月都生效就收整月。
- **怎么拿到数字**：`GET /api/earth/sponsor-report?month=YYYY-MM`，请求头带 `Authorization: Bearer <令牌>`。返回每条赞助当月的生效天数、核销次数、月费部分、核销部分和合计，不含任何玩家信息。令牌是 Workers 的机密 `EARTH_SPONSOR_TOKEN`，至少 32 个字符。**没配置这个机密时，接口直接返回 404。** 配置要用户自己跑 `wrangler secret put EARTH_SPONSOR_TOKEN`，令牌不能写进仓库。
- **开发票和收款**：按对账单，用会计软件手工给商户开税务发票，商户银行转账。游戏和服务端都不接支付。
- 折算规则（按天折算）、四舍五入方式、GST 怎么写在发票上，都要会计确认。
