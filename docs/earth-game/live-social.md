# 地球人生 · 玩家互动与现实节日

> 第 24 批（分支 `claude/earth-live-social`，2026-11-20）。这份文档写两件事：同地点、同时段的玩家还能一起做什么，以及节日怎么跟真实日历同步。第 6 节是这一批实际落地的部分，其余是设计，标了「待做」的还没写代码。
>
> 功能总览见 [features.md](features.md)（在分支 `claude/earth-feature-spec`，未合并），规则细节见 [core-design.md](core-design.md)。标「待平衡」的数值还没经过 Codex 分析。

## 1. 玩家是谁，决定了什么

玩家是在西澳、南澳的华人和留学生，主要用手机。由此定下几条：

- **同一个城市的真人**。游戏里的「同地点」常常就是现实里的同一座城。所以隐私比别的联机游戏更要紧：任何功能都不能让别人推出你现实中在哪、住哪、几点出门。
- **碎片时间**。不能要求两个人同时在线很久。每个互动要么几秒钟做完（表情、送礼），要么能异步（留言、挂单、周目标）。
- **熟人少、陌生人多**。默认对陌生人只开放低风险的互动，越往深越要双方都主动。

## 2. 互动性：同地点、同时段能一起做什么

### 2.1 已经有的（main e429bcd）

| 互动 | 同步 / 异步 | 现在的规则 |
| --- | --- | --- |
| 在线状态、本地频道、表情 | 同步 | 按区域一个在线频道；只看到同地点的人；聊天 120 字，每连接 5 秒 20 条 |
| 共同事件（组队） | 同步，几分钟内 | 同地点 2 人以上，每人选分工，团队分达标就成功；每种每人每 5 个游戏日一次；8 种 |
| 送礼、二手摊 | 半同步（挂单 30 分钟） | 只交易物品不转钱；价格在商店价 50%–150%；每天送出、收下各 5 次 |
| 地点留言板 | 异步 | 每地 20 条；不能带网址、联系方式；每人每天 3 条，同地一天一条 |
| 全服周目标 | 异步 | 每个现实周一个目标，全服累计，达成后出过力的人各领一次 |
| 净资产排行榜 | 异步 | 全服前 20 名 |
| 常遇见的人 | 异步 | 一起做过事、交易过的人，最多记 30 个 |

### 2.2 缺什么

1. **没有自我保护手段**：不能屏蔽、不能举报。对陌生人开放了聊天、表情、送礼和留言，却没有办法拒绝某个人。——**这一批补上（第 6.2 节）。**
2. **聊天没有联系方式过滤**：留言板拦电话、网址，在线频道不拦，等于有一个口子能发电话、微信号和坐标。——**这一批补上。**
3. **同时段的理由少**：除了共同事件，两个人同时在一个地方没有额外好处。现实节日是天然的「同时段」——大家在同一个真实日子里赶同一个活动。——**这一批先做「到场纪念」，组队加成待做（2.3 第 2 条）。**
4. **帮忙只对 NPC**：玩家之间没有「帮一把」的轻量互动。

### 2.3 设计（按建议顺序）

1. **屏蔽、举报**（已做，见 6.2）。
2. **节日同场加成（待做）**：现实节日进行中，在活动地点做共同事件，团队分额外 +5（待平衡）；周目标在节日周换成「节日到场人数」。依赖第 6.1 节的现实活动数据，不需要新的服务端状态。
3. **帮一把（待做）**：对同地点在线的玩家点「帮一把」，对方下一次检定 +3（待平衡），每人每天能帮 3 次、被帮 3 次。不转物品不转钱，没有可刷的东西。双方都记进「常遇见的人」。适合陌生人之间的第一步。
4. **互赠礼物的回礼（待做）**：收下礼物后 24 小时内可以回一件，回礼不占每日 5 次的额度。让送礼变成来回，而不是单向。
5. **好友（待做）**：双方都在「常遇见的人」里、一起做过 3 次以上事，才能互加好友。好友之间才开放：跨地点看到对方在哪个游戏地点、私聊。陌生人一律没有私聊。
6. **地点排行榜（待做）**：每个地点按「这个月来过几次」排前 10，只显示名字和头像。按游戏地点算，不按真实位置算。

**不做的**：偷东西、PK、抢地盘（新玩家反感，也容易变成骚扰）；按真实距离找附近的人（隐私）；玩家之间直接转钱（洗钱和诈骗风险）。

### 2.4 防骚扰和隐私规则

这些规则对所有现有和以后的互动都适用：

**不暴露真实位置**
- 别的玩家能看到的只有**游戏地点**（「珀斯」「弗里曼特尔」），永远不显示坐标、真实店铺、距离或「附近多少米」。
- 存档里的真实定位（`fix`，3 位小数约 100 米）只发给本人，不进任何广播、榜单、留言或交易单。
- 真实地点（店铺）上的动作、实地上班都不向别人显示「某人在某店」。
- 聊天、留言都拦坐标（去掉分隔符后是长串数字）、电话、网址和社交账号。
- 以后做好友、地点排行榜时同样只用游戏地点；排行榜不显示「最近在哪」。

**身份**
- 对外只用 id 的哈希前缀（12 位十六进制）标识玩家；真实 id 和同步码只在服务端。屏蔽、举报的对象由服务端按哈希或留言查实，客户端传不了别人的真实 id，也拿不到。
- 名字只能是 12 个字以内的普通字符，不显示个人资料。

**屏蔽**
- 屏蔽后：看不到对方的聊天、表情、留言、挂单；对方送不了你东西（提示「对方现在收不到礼物」，不说是被屏蔽）。
- 对方**不会收到通知**，也查不到自己被谁屏蔽。
- 每人最多屏蔽 50 人；可以在「我 · 设置」里解除。
- 共同事件大厅、排行榜还不按屏蔽过滤（待做）：共同事件是双方都主动加入的，排行榜只有名字。

**举报**
- 能举报一个人、一句聊天或一条留言；原因五选一（刷屏或广告、骚扰辱骂、联系方式、约线下见面或打听住址、其他）。
- 举报后自动屏蔽对方。被举报的人不知道是谁举报的。
- 留言的原话由服务端从留言板取；聊天不落盘，原话由举报人提交，只作参考。
- 每人每天最多举报 5 次；同一人同一天对同一人只算一次。
- 最近 7 个现实日里有 3 个不同的人举报同一人（待平衡），这个人的留言先对其他所有人隐藏，本人仍能看到自己的。
- 举报记录存在服务端（`report:<哈希>`，每人最多 50 条），目前没有管理界面，要用 wrangler 查看（待做：管理员处理流程、封禁）。

**未成年人**：游戏没有年龄登记。私聊、好友这类更深的功能上线前，要先定是否要年龄确认（待用户定）。

## 3. 节日实时性：跟真实日历同步

### 3.1 两套日历，互不影响

| | 游戏日历里的节日（已有） | 现实活动（这一批新增） |
| --- | --- | --- |
| 数据 | `src/game/data/festivals.ts`，9 个原创节日 | `src/game/data/live-events.ts`，真实的艺术节和公众假期 |
| 按什么时间 | 游戏时钟（`state.clock`，一年 4 季 × 28 天） | 现实时间（服务端时钟） |
| 每个玩家看到的 | 各人不同（游戏时钟跟着自己的动作走） | 所有人同一刻看到同样的状态 |
| 效果 | 节日专属体验、节日气氛 | 到场纪念（一次性）；以后加同场加成 |

**为什么不把游戏日历改成跟现实同步**：游戏时钟跟着动作走，一个现实日里可能过好几个游戏日，开局固定在第 1 年春季第 1 天 08:00（`character.ts` 的 `START_CLOCK`）。改成现实时间会让所有按游戏日的规则（周结算、房租、冷却、心愿、天气）跟着变，而且 2026-11-18 用户已经定过「游戏日历也不和现实日期同步」（见 [plan-50.md](plan-50.md) 第 8 批的说明）。所以现实活动是**另外一层**，只看现实时间，不碰游戏日历。

两者重叠时（比如现实的珀斯艺术节期间，游戏日历刚好也在过天鹅河烟火夜）各算各的：节日气氛这个心情状态同种只保留一个，不会叠加。

### 3.2 收录的活动和来源

全部在 2026-11-20 用 `curl` 直接取官方页面全文核对，不用搜索摘要。只收官方已公布确切日期的；没公布的年份不预填，不按往年推算。

| 活动 | 日期（当地） | 地点 | 来源 |
| --- | --- | --- | --- |
| Perth Festival 2027 | 2027-02-05 – 02-28 | 珀斯 | https://www.perthfestival.com.au/frequently-asked-questions/ （「The Festival dates are 5 – 28 Feb 2027」） |
| Adelaide Fringe 2027 | 2027-02-19 – 03-21 | 阿德莱德 | https://avr.adelaidefringe.com.au/blog/events/key-dates （「Festival Dates: 19 February - 21 March」） |
| Adelaide Festival 2027 | 2027-02-26 – 03-14 | 阿德莱德 | https://www.adelaidefestival.com.au/ （页头「26 FEB - 14 MAR 2027」） |
| WOMADelaide 2027 | 2027-03-05 – 03-08 | 阿德莱德 | https://www.womadelaide.com.au/info/faqs/ （「Friday 5 to Monday 8 March」） |
| 西澳公众假期 2026-12 至 2027-12（11 个，含补假日） | 见数据文件 | 西澳全州 | https://www.wa.gov.au/service/employment/workplace-agreements/public-holidays-western-australia |
| 南澳公众假期 2026-12 至 2027-12（15 个，含平安夜、跨年夜 19:00–24:00 和补假日） | 见数据文件 | 南澳全州 | https://www.safework.sa.gov.au/resources/public-holidays |

数据规则（写在 `live-events.ts` 文件头，测试里也查）：

- 每条必须有 `source`（https，域名在官方名单里）和 `checked`（核对日期）。公众假期必须用本州政府页面。
- 日期和钟点都写**当地时间**，区间 `start` 含、`end` 不含。补假日分开写（比如西澳 2026 年节礼日是 12 月 26 日和 28 日，27 日不是假期）。
- 艺术节绑一个游戏地点；公众假期不绑地点，整个州都算。
- 不收：只有媒体报道、官方没公布日期的活动；需要门票的具体场次；按往年规律推算的年份。

**和数据来源规则的关系（2026-11-20 用户已同意）**：AGENTS.md 要求数据只来自 OSM / Wikidata / 种子数据，那条规则针对的是地点（POI）。节日日期 OSM 和 Wikidata 都没有（Wikidata 没有 2027 届的日期），这里按「种子数据 + 官方来源网址」录入，是事实性的日期，不抄页面文字（描述是自己写的）。用户 2026-11-20 同意节日日期按这种方式录入。

**维护**：每年 10–11 月，各艺术节公布下一届日期后，由 OpenClaw 采集候选（官方网址 + 原文摘录），Claude 核对后加进数据文件，Codex 审查。公众假期以州政府页面为准，政府页面一般提前两年公布。

### 3.3 时区

| 州 | 标准时间 | 夏令时 | 规则来源 |
| --- | --- | --- | --- |
| 西澳（珀斯） | UTC+8 | 不实行 | — |
| 南澳（阿德莱德） | UTC+9:30 | UTC+10:30，10 月第一个星期日 2:00（标准时间）起，到次年 4 月第一个星期日 3:00（夏令时）止 | Daylight Saving Regulations 2024 (SA) 第 4 条（legislation.sa.gov.au） |

两个切换点换算成 UTC 都是那个星期日的**前一天 16:30**。实现在 `src/game/core/live.ts`：纯函数，自己按规则算偏移，不依赖运行环境的时区库（Cloudflare Workers 和手机浏览器的时区数据版本可能不同）；测试里再拿 Node 的 IANA 时区库在 2026–2028 年每半小时逐点比对一遍。

注意：同一个 UTC 时刻，两州可能不在同一天。比如 UTC 2026-12-25 15:30，珀斯是 25 日 23:30（圣诞节），阿德莱德是 26 日 02:00（建州日）。每个活动只按自己所在州的时间判断。

### 3.4 到点自动上线和下线

- 服务端结算动作时用自己的时钟（`EarthWorld.saveNow`：时钟回拨时沿用这个存档上次落盘的时间，不倒退）。客户端发来的任何时间都不用。
- 活动状态是纯函数 `liveStatus(活动, now)` 现算的，不存「开关」，所以没有定时任务，也不会出现「忘了下线」。
- 界面用服务器返回的时间（`clockSkew` 校准过的 `srvNow()`）预先显示「进行中 / 几天后开始」，按钮可不可以点只是提示，能不能领以服务端结算为准。
- 跨过结束时刻的那一刻起，服务端拒绝领取（「这个活动已经结束了」）。

## 4. 数值（全部待平衡）

| 数值 | 现在 | 位置 |
| --- | --- | --- |
| 艺术节到场纪念 | 娱乐 +20、声望 +3、节日气氛心情 | `LIVE_REWARD.festival`（core/live.ts） |
| 公众假期到场纪念 | 娱乐 +10、声望 +1、节日气氛心情 | `LIVE_REWARD.holiday` |
| 举报自动隐藏留言 | 7 个现实日内 3 个不同的人 | `REPORT_HIDE_BY`、`REPORT_WINDOW_DAYS`（core/safety.ts） |
| 每天举报次数 | 5 | `REPORTS_PER_DAY` |
| 屏蔽上限 | 50 人 | `BLOCK_MAX` |

到场纪念每个活动只能领一次。现有数据（2026-12 至 2027-12）一共 4 个艺术节、26 个公众假期，两州的假期大多同一天，一个人同一时刻只能在一个州，所以实际能领的次数少于 30。是否合适请 Codex 在平衡分析里看。

## 5. 接口

- 动作：`{ t: 'live', id }`，走 `act`，由 `applyAction` → `claimLive(state, region, id, now)` 结算（`now` 是服务端时间）。
- `safety { op: 'block', peer | note, rev }`、`safety { op: 'unblock', hash, rev }`、`safety { op: 'report', peer | note, reason, quote?, rev }`：服务端查实对象后用 `applyBlock`（core/actions.ts）改存档，版本号加一。
- 在线频道新增两种消息：客户端 → 服务端 `{ t: 'mute', ids }`（整份替换屏蔽名单，最多 50 个合法哈希）；服务端 → 发送者 `{ t: 'notice', msg }`（聊天被拦时）。
- 存档新增 `live: string[]`（领过的活动 id，最多 200 个）和 `blocked: Record<哈希, { name, avatar, day }>`（最多 50 个），旧存档读出来是空的。

## 6. 第一版落地（这一批）

### 6.1 现实活动

- `src/game/data/live-events.ts`：4 个艺术节 + 26 个公众假期，全部带来源。
- `src/game/core/live.ts`：时区和夏令时、当地时间换 UTC、活动状态、日历、日期标签、领取规则。纯函数，`now` 由调用方传。
- 今天页新增「现实里的节日和假期」卡：进行中的和 30 天内要开始的（只列所在州的，进行中的都列），每条带官方来源链接和「到场」按钮。

### 6.2 屏蔽与举报

- `src/game/core/safety.ts`：屏蔽名单、举报记录、自动隐藏的规则。
- 服务端：`safety` 接口；留言列表按屏蔽和举报过滤；挂单列表按屏蔽过滤；送礼双向检查屏蔽；在线频道按 `mute` 过滤聊天和表情；聊天按 `contactError` 拦网址、电话、账号、坐标。
- 页面：社交页每个在线的人有「屏蔽」「举报」；聊天每句有「举报」；留言板别人的留言有「屏蔽」「举报」；「我 · 设置」新增「已屏蔽的人」。
- `core/notes.ts` 的联系方式检测拆成 `contactError()`，留言板和聊天共用，留言板的提示文字不变。

### 6.3 测试和变异检查

新增 `tests/earth/live.test.ts`（11 项）、`tests/earth/safety.test.ts`（7 项），`bundle.test.ts` 补了首屏量法。变异检查：把下面每处代码或数据改坏，确认对应测试会失败，跑完还原。

| 改坏的地方 | 结果 |
| --- | --- |
| 南澳夏令时结束按标准时间算（3:00 → 2:00） | 失败 2 项 |
| 夏令时开始晚一小时 | 失败 2 项 |
| 「第一个星期日」算成下一个星期日 | 失败 1 项 |
| 珀斯按 UTC+9 | 失败 7 项 |
| 南澳夏令时写成 UTC+10 | 失败 4 项 |
| 南澳不实行夏令时 | 失败 4 项 |
| 结束那一刻还算进行中（`<` 改 `<=`） | 失败 2 项 |
| 开始那一刻不算（`>=` 改 `>`） | 失败 1 项 |
| 整天活动少算一天 | 失败 3 项 |
| 珀斯艺术节开始日期错一天 | 失败 3 项 |
| 阿德莱德杯挪到星期日 | 失败 2 项 |
| 节礼日补假写成连续三天 | 失败 2 项 |
| 不检查活动地点 / 可以重复领 | 失败 1 / 2 项 |
| 客户端带的时间一路透传到结算 | 失败 1 项 |
| 举报隐藏门槛 3 改 2 / 窗口边界 `>` 改 `>=` / 同日重复举报不拦 / 举报不限次数 | 各失败 1–2 项 |
| 留言不按屏蔽过滤 / 不按举报隐藏 / 送礼不查对方屏蔽 / 挂单不按屏蔽过滤 | 各失败 1 项 |
| 聊天不查屏蔽 / 不查联系方式 / 坐标不算联系方式 | 失败 1 / 1 / 2 项 |
| 体积测试只量入口 / 动态 import 也算 | 失败 1 / 2 项 |

只改「客户端时间透传」的一半（只改解析或只改结算）时测试不失败：单改一半是等价变异（解析时丢掉了 `now`，或结算时不读它），不是漏洞；两半一起改才是真漏洞，测试能抓到。

### 6.4 首屏体积

这一批让首屏脚本从约 393KB 长到约 406KB（日期数据和时区规则约 7KB，屏蔽举报界面约 6KB），超过了原来 400KB 的上限，**上限提到 420KB（2026-11-20 用户已同意）**。

试过把现实活动改成按需加载，结果首屏实际要下载的反而更多（约 409KB）：拆包后共用模块进了单独的 chunk，入口文件变小，旧的测试只量入口，所以会误报通过。这一批顺带把体积测试改成「入口 + 它静态 import 的所有 chunk」。
