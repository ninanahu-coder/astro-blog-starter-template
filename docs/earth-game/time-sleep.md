## 1. 游戏时钟

### 1.1 现状

| 项 | 规则 | 位置 |
| --- | --- | --- |
| 时钟 | `state.clock` = 从第 1 天 00:00 起的游戏分钟数；只有动作会推进（回合制），**和真实时间无关** | `core/time.ts`、`engine.ts` 的 `advance()` |
| 开局 | `START_CLOCK = 8 × 60`：所有角色都从第 1 天 08:00 开始，所以「开局第几天」= `dayOf(clock)` | `character.ts` |
| 显示 | `formatClock(clock)` →「第 N 天 HH:MM」；顶栏用 `dateLabel`（季 + 日）+ 星期 + 钟点 + 时段 | `character.ts`、`earth.astro` |
| 时段 | 玩法时段按钟点：清晨 5–8、白天 8–17、傍晚 17–20、夜晚 20–5 | `time.ts` 的 `period()` |
| 天色 | 画面明暗按真实日出日落（经纬度 + 游戏日期映射到现实日期），和玩法时段不一致时顶栏补一句「天已经黑了」 | `sky.ts` 的 `skyPhase()`、`phaseNote()` |
| 日历 | 一年 4 季 × 28 天；第 1 天是春季第 1 天、周一；游戏季映射到南半球现实季节（春 = 9–11 月） | `time.ts`、`sky.ts` 的 `realDayOfYear()` |
| 时区 | 游戏钟点就是当地钟点：东经 129° 以西按 AWST（UTC+8），以东按 ACST（UTC+9:30，南澳夏令时 +10:30） | `sky.ts` 的 `tzMinutes()` |
| 周结算 | 每跨过一个结算日（`nextWeek`，每 7 个游戏日）付房租、物业费、房贷、车险 | `engine.ts` 的 `weeklyTick()` |
| 真实时间 | 只有这几处用现实时间：每日奖励（珀斯时间的现实日）、全服周目标（现实周）、真实地点打卡冷却、上班卡；都由服务端传 `now`，core 不读时钟 | `daily.ts`、`weekly.ts`、`venues.ts` |

**结论（现状即设计，不改）**：游戏时间和真实时间是两条独立的轴。游戏时间只由玩家的动作推进；现实时间只决定「每天能领一次」「这周的全服目标」这类节奏。
这样手机玩家断线、隔几天再上线，不会回来发现角色饿晕、房租被扣——对以手机碎片时间为主的玩家这是故意的。

### 1.2 本批改动

- `START_CLOCK`、`formatClock` 不变。
- 新存档字段 `rest.wake` 记最近一次醒来的游戏时钟；开局是第 1 天 07:00（`START_CLOCK − 60`），刚醒一小时。

### 1.3 和 `activity-attrs` 分支的关系（未合并）

那个分支把 `advance()` 改成调 `passTime()`：睡着时精力不降、饱食减半，掉血只算见底后的分钟；睡觉恢复的精力还要乘「恢复系数」并受精力上限限制。
本批**没有动 `advance()`**，睡眠质量是乘在「一觉的效果」上的（`sleepFx`），两边是两层，合并时叠加：

```
醒来精力 = 睡前精力 − 睡着时的衰减（attrs：0）+ 100 × 睡眠质量（本批）× 恢复系数（attrs）  ≤ 精力上限（attrs）
```

**合并冲突提示**（写在这里，不改别的分支）：

| 位置 | 本批 | attrs |
| --- | --- | --- |
| `engine.ts` 的 `sleepHome()`、`sleepInVehicle()`、`performActivity()` | 效果改为经 `sleepFor()`（内部 `sleepFx` 再 `applyEffect`） | 同一行包了 `bodyScaled()`、标 `asleep` |
| 解决办法 | `sleepFor()` 里改成 `applyEffect(state, bodyScaled(state, { ...sleepFx(fx, sq.q), asleep: true }), region)`，三个调用点不再各自包 | — |
| 测试 | 本批把三处「睡醒精力 = 100」改成「= 100 × 睡眠质量」 | attrs 改成「= 精力上限」；合并后要改成两者取小 |

## 2. 作息和睡眠质量

### 2.1 现状

| 睡在哪 | 效果 | 位置 |
| --- | --- | --- |
| 回家睡（免费） | 8 小时；健康 15 + 住处舒适度，精力 +100，清洁 50 + 舒适度 × 2，娱乐 5 + 舒适度；床、浴室家具另加；舒适度 ≥ 3 或有床位家具 →「睡了个好觉」 | `engine.ts` 的 `sleepHome()` |
| 睡车（露营车） | 8 小时，按车型的 `sleep` 效果（精力 +85） | `sleepInVehicle()` |
| 住旅馆（$90） | 8 小时，精力 +100，健康 +15，「睡了个好觉」 | `data/activities.ts` |
| 露营（免费） | 8 小时，精力 +70，健康 +5，「星空下醒来」 | 同上 |

几点睡都一样，熬多久都没有额外后果（只有精力见底时掉血）。

### 2.2 新：睡眠质量 q

每一觉开始时算一次（`core/sleep.ts` 的 `sleepQuality()`，数值在 `data/sleep.ts`）：

```
q = clamp( (床 − 噪音 − 时差小时 × 0.05) × (夜里入睡 ? 1 : 0.85), 0.4, 1.1 )
```

| 因素 | 取值（全部【新，待平衡】） | 依据 |
| --- | --- | --- |
| 床 | 住处 0.9 + 舒适度 × 0.01，有床位家具（好床垫、大床）+0.1；露营车 0.85；旅馆 0.95；帐篷 0.8 | 舒适度、家具是现有数据，直接复用 |
| 噪音 | 地点类型：城市 0.06、港口 0.04、矿区 0.04、小镇 0.01，其余 0 | 按 `LocationKind` 查表，不针对单个地点 |
| 时差 | 见 §2.3 | |
| 几点睡 | 入睡钟点在 [20:00, 03:00) 算夜里，其他时候 × 0.85 | |

q 的作用：

- 一觉恢复的**精力和健康**（只缩放增加的部分）乘 q；其他需求、扣的部分不动（`sleepFx()`）。
- q < 0.75：挂「没睡好」（沿用已有的 `rough-night`，−2 心情 8 小时），并且不发效果里写的「睡了个好觉」。
- 回家睡、住旅馆、露营、睡车都走这条规则；回家睡和睡车之后家具额外加成照旧，不乘 q。

算例（住珀斯合租房间、无家具，精力 20 去睡，`activity-attrs` 未合并时睡 8 小时先衰减 24）：

| 情形 | q | 醒来精力 |
| --- | --- | --- |
| 22:00 睡 | (0.9 − 0.06) = 0.84 | 0 + 84 = 84 |
| 10:00 睡 | 0.84 × 0.85 = 0.71 | 0 + 71 = 71，挂「没睡好」 |
| 22:00 睡，有好床垫 | 0.94 | 94 |
| 22:00 住旅馆 | 0.89 | 89 |
| 22:00 在皮纳克尔斯（野外，无噪音）露营 | 0.8 | 露营本来只 +70，乘 q 后 +56 |

注意露营那一行：露营原本精力只 +70，现在再乘 0.8 → +56。这是本批对穷角色影响最大的一处，交给 Codex 看（§7 问题 1）。

### 2.3 新：时差

`ORIGIN_TZ`（`data/sleep.ts`）记每种出身「来澳洲前生活地」的时区：

- **【假设，待用户确认】** 留学生、背包客按从 UTC+8 的华语地区飞来算；矿区轮班工、冲浪手按本来就住在澳洲算（`null`，没有时差）。
- 时差小时 = |当地时区 − 老家时区|，每过一个游戏日倒回 1 小时（「大约一天调一个时区」是常见经验说法，不是精确结论）。
- 西澳和国内都是 UTC+8，所以**只有开局落地南澳的人有时差**：游戏开局对应现实 9 月，南澳 UTC+9:30，差 1.5 小时，第 2 天剩 0.5，第 3 天归零。
- 不新增存档字段：所有角色都从第 1 天开始，`dayOf(clock)` 就是来澳第几天。

### 2.4 新：熬夜和补觉（睡眠债）

存档新字段 `rest: { wake, debt }`（见 §5）。

| 规则 | 公式（数值【新，待平衡】） |
| --- | --- |
| 醒了多久 | `clock − rest.wake` |
| 熬夜记债 | 入睡时醒着超过 16 小时，超出部分每小时记 1 小时债；债上限 24 小时 |
| 睡觉还债 | 每睡 1 小时还 `q × 0.5` 小时：熬掉的觉只能还一半，正常睡一夜（q≈0.85）还约 3.4 小时 |
| 整觉醒来 | `wake = 醒来时刻`，醒着的时间清零 |
| 补觉（新动作，在家 2 小时） | 精力 +30 × q；同样按 q 还债；「醒了多久」往回拨 3 × 2 = 6 小时，最多拨到 16 小时（超出的部分已经记过债，不重复记） |
| 心情 | 醒来时还欠 ≥ 4 小时：挂「熬夜没缓过来」（新，−5 心情 12 小时） |
| 晕倒住院 | 住院 12 小时算睡过：`wake = 出院时刻`，欠的债不免 |

算例：第 1 天 07:00 醒，一直玩到第 2 天 07:00（醒 24 小时）回家睡（q = 0.71，白天）：
记债 8 小时，还 8 × 0.71 × 0.5 = 2.8，剩 5.2 → 挂「熬夜没缓过来」；之后每晚按时睡（q 0.84）各还约 3.4 小时，两晚还清。

熬夜目前**只有心情代价**（加上本来就有的精力见底掉血）。更重的后果见 §4 提议。

## 3. 日程表

### 3.1 现状

| 时间约束 | 规则 |
| --- | --- |
| 上班 | 每天一班；开工窗口 `career.start`（如咖啡店 6–11 点），窗口内才能开始；上完一班花 `minutes`（6–10 小时） |
| 课程、证书 | 按营业时间 `hours`，随到随上，不报名、不排课 |
| NPC | 有每周日程（`npcPlan`），在场才能互动；没有「约会」这种预约 |
| 学历课程 | 分支 `claude/earth-education-career`（未合并）加了上课时间 |

所以「冲突」只会以一种形式出现：做了一件长的事，回来发现开工窗口已经关了，要等到明天。

### 3.2 新：今日日程和冲突提醒（只提示，不拦）

`core/schedule.ts`：

- `agenda(state, region)`：今天的上班（状态：已完成 / 现在能开工 / 稍后 / 已错过，不在工作地点时写在哪）+ 睡觉（几点入睡算按时、已经醒了多久、再过多久算熬夜、欠多少觉）。
- `timeConflict(state, minutes)`：做一件要 `minutes` 分钟的事之前，如果
  - 今天的班还没上、开工窗口还开着或没到，做完就过了窗口 →「做完就过了 11:00，赶不上今天咖啡店的班」；
  - 做完就醒了超过 16 小时 →「做完就开始熬夜了」。
- 页面：主页加一张可折叠的「🗓️ 今日日程」卡；地点页活动列表的说明后面加 ⚠ 提醒；睡觉类活动和住处一栏显示这一觉的睡眠质量和原因。

不拦动作：上班窗口、营业时间照旧由各自的规则把关；本批只把「会错过」提前说出来。

### 3.3 提议（没做）

- **约会 / 预约**：和 NPC 约定「周六 10 点在弗里曼特尔集市见」，记进日程；到点不在场扣关系。要新存档字段（约定列表，带游戏时刻和地点），和 `claude/earth-social-npc`（NPC 日程交集）、`claude/earth-live-social`（节日互动）一起设计，避免两边各做一套「约」。
- **学历课程排课**：`claude/earth-education-career` 合并后，把它的上课时间也放进 `agenda()`，冲突提醒多一条「赶不上上课」。
- **矿区轮班（FIFO）**：education-career 文档里提过「连续 N 天每天必须上班」的排班；如果做，`agenda()` 显示排班周，`timeConflict` 在跨区出行时提醒。

## 4. 提议：更重的熬夜后果、跨州时差

只写设计，交给用户和 Codex 决定做不做：

| 提议 | 内容 | 要改什么 |
| --- | --- | --- |
| 熬夜影响上班表现 | 欠觉 ≥ 4 小时时上班检定 −5，或上班扣的精力 × 1.2 | `workShift()`；数值要 Codex 先模拟 |

## 5. 离线期间怎么算时间

**【现状，本批不改】**

- 游戏时钟不随现实时间走：离线多久，回来时角色还停在离线前那一刻，需求不衰减、房租不扣。
- 断网时点的动作进离线队列（`ui/queue.ts`，最多 5 个、24 小时内有效），联网后按顺序交给服务器结算；本批把「在家补觉」加进可排队的动作（和回家睡同类：不看真实位置、不看真实时间）。
- 每日奖励、全服周目标按现实日 / 现实周，离线不会补发，也不会断连续天数以外的东西。

**为什么不做「离线也走时间」**：玩家主要用手机碎片时间玩，离线推进会让回来的第一屏全是坏消息（饿晕、欠租、错过上班）。本游戏的节奏由动作决定，现实时间只决定「每天能领一次」这类节奏，这条和 §1.1 一致。

**【提议】** 回来时显示「你离开了 N 天」的欢迎卡（只统计现实时间，不改游戏状态），顺带提醒今天的每日奖励和全服目标——属于 `claude/earth-onboarding` / `claude/earth-main-ui` 的界面，不在本批做。
