# 地图与底图系统设计（v42）

> 标记说明：**【现状】** 是 main（e429bcd）上已有、本文只做记录的行为；**【v42 已做】** 是本分支 `claude/earth-map` 落地的第一版改动；**【提议】** 是还没做、等用户决定的方向。
> 凡是涉及新增依赖、付费瓦片服务、自建瓦片服务器的，一律是【提议】，本分支没有动。

## 1. 两种地图

| | 手绘示意图 `#map` | 真实底图 `#basemap` |
| --- | --- | --- |
| 实现 | 内联 SVG，`earth.astro` 的 `renderMap()` | MapLibre GL（`maplibre-gl@6.16.0`，已在依赖里），`src/game/ui/basemap.ts` |
| 内容 | 区域轮廓（手工简化多边形）、路线、跨区域出口、地点圆点、「你在这里」脉冲、天气图标、在线人数、夜里星星 | OpenFreeMap 的 OSM 矢量图，上面叠同样的地点标记（按钮）和路线（GeoJSON 虚线） |
| 投影 | `geo.ts` 的 `makeProjection()`：按区域中纬度修正的等距圆柱 | Web 墨卡托（MapLibre 自带） |
| 何时显示 | 一直画；底图没准备好时就是它 | 准备好后盖在 SVG 上（`#map-wrap.real`） |

**【现状】切换方式**
- 不是并列的两个选项，而是「底图可用就用底图，否则退回手绘图」。判断在 `canUseBasemap()`：设置开着（`prefs.basemap`，默认开）+ `navigator.onLine` + 浏览器有 WebGL + 本次没失败过。
- 玩家可在「我 · 设置」里关掉真实地图；设置文案写明「图块向 OpenFreeMap 请求」。
- 手绘图始终先画好，所以加载中、失败、离线时界面不空。

**【提议】** 出行页地图右上角加一个「手绘 / 真实」小切换（只改 `prefs.basemap`），省得去设置页找。属于 UI 改动，和 `claude/earth-main-ui` 的出行页样式有重叠，建议等它合并后再做。

## 2. 瓦片来源、费用、配额、许可与署名

**【现状】**
- 样式：`https://tiles.openfreemap.org/styles/liberty`（`BASEMAP_STYLE`）。数据是 OpenStreetMap，矢量切片按 OpenMapTiles 架构。
- 费用和配额（来源：openfreemap.org 首页，2026-11-20 查阅）：公共实例免费，不需要注册和 API key，不用 cookie；官方说公共实例对地图浏览量和请求数**没有限制**；没有 SLA，不提供个人支持。离线批量下载另有条件（每次 ≤3000 个瓦片或 50 MB、≤4 并发、独立 User-Agent），本游戏没有做离线下载。
- 许可：OSM 数据是 ODbL，必须署名。OpenFreeMap 要求署名，MapLibre 会从样式里自动带上署名控件。
- 署名展示：`attributionControl: { compact: true }`。MapLibre 的 compact 模式加载时是**展开**的，地图被拖动后才收成 ⓘ 按钮，点 ⓘ 能再展开（MapLibre 源码 `attribution_control.ts` 的 `_updateCompact` / `_updateCompactMinimize`）。
  - OSMF《Attribution Guidelines》（osmfoundation.org/wiki/Licence/Attribution_Guidelines）允许交互地图的署名在用户与地图交互后、或 5 秒后收起，前提是收起后仍有 ⓘ 之类的入口能看到许可信息。现状符合这一条。
  - 页面宽度上限 560px，MapLibre 在 ≤640px 时本来就会自动用 compact，所以 `compact: true` 实际不改变行为。

**OSM 官方瓦片政策（不适用，但要知道）**
来源：OSMF《Tile Usage Policy》 https://operations.osmfoundation.org/policies/tiles/ （2026-11-20 查阅，页面未标更新日期）。要点：
- 署名要明显，不能藏在 UI 下面、开关后面或屏幕外；
- 禁止抓取用户没在看的瓦片（预取、批量下载、做离线包），`tile.openstreetmap.org` 不允许离线使用；
- 要有能识别应用的 User-Agent，网页流量要带 Referer，不能用过严的 Referrer-Policy；
- 遵守缓存头，读不了缓存头时每个瓦片至少缓存 7 天；
- 没有 SLA，影响服务时可能被直接封禁。

本游戏**没有**请求 `tile.openstreetmap.org`，所以这条政策不直接约束我们；但它说明了两件事：① 不能为了「离线地图」改去批量抓 OSM 官方瓦片；② 如果以后换瓦片来源，署名要求不会变松。

**【提议】（都需要用户决定，本分支没做）**
| 方案 | 好处 | 代价 |
| --- | --- | --- |
| 维持 OpenFreeMap 公共实例（推荐） | 免费、无 key、已经在用 | 无 SLA；它挂了就退回手绘图（已有兜底） |
| 自建 OpenFreeMap / PMTiles（Cloudflare R2 放西澳+南澳范围的切片） | 可控、可离线缓存、不依赖第三方可用性 | 要存储与流量费；需要新增 `pmtiles` 依赖；切片要定期更新 |
| 商业瓦片（MapTiler、Stadia、Mapbox 等） | 有 SLA、样式多 | 要 key、要钱、有配额；key 暴露在前端要做域名限制 |

## 3. 离线与加载失败的兜底

**【现状】**
- 地图库只在第一次要画真实地图时动态加载（`loadMapLibre()`，单独打包），不进首屏。
- 地图库下载失败、或地图 `load` 之前收到 `error`（断网、样式请求失败、瓦片服务挂了），`createBasemap` 调 `onState('failed')`，页面设 `basemapFailed = true`，退回手绘图。加载好之后个别瓦片出错不算失败。
- 离线事件（`offline`）会重画地图，`canUseBasemap` 返回 false，退回手绘图。
- Service Worker 只缓存应用外壳，不缓存瓦片。

**【v42 已做】联网后自动重试一次**：以前断网导致底图失败后，`basemapFailed` 一直为 true，只能去设置里关了再开。现在 `online` 事件里如果 `basemapFailed` 为 true，就清掉并（在出行页时）重画一次。设置里关掉的不会被打开（`canUseBasemap` 仍看 `prefs.basemap`）。每次联网只触发一次，不会循环重试。

**【提议】** 在 Service Worker 里对**已经看过的**瓦片做有上限的运行时缓存（比如 LRU 200 个、7 天），离线时能看最近浏览过的范围。这不违反 OpenFreeMap 的条件（不是批量预取），但要改 `public/earth/sw.js`，和性能优化分支有关，建议协调后再做。

## 4. 跨区（西澳、南澳）的缩放与导航

**【现状】**
- 世界由区域拼成（`areas-base.ts`：`AREAS = [WA_BASE, SA_BASE]`），画面按玩家所在地点的区域画（`areaOf(state.loc)`）。
- 手绘图：每个区域一套投影（`projOf` 缓存）；跨区域路线（`CROSS_ROUTES`：珀斯—阿德莱德航线、卡尔古利—锡杜纳公路）画成从本区域伸出去的一小段，带「✈️ 阿德莱德（南澳大利亚）」标签和可点的热区。
- 真实底图：按区域的地点范围 `basemapBounds()` 建图；换区域时销毁重建。

**【v42 已做】真实底图上的跨区域出口**：以前底图只把跨区域路线画成一条伸出屏幕的虚线，没有可点的目标，也没有文字，玩家在真实地图上不知道能去南澳。现在：
- `exitPoint(a, b, bounds)`：从本区域端点沿连线朝另一区域走，停在底图范围（往里收 6%）的边上；目的地本来就在范围内时就放在目的地。
- 出口标记是带 `data-loc=<目的地 id>` 的按钮，点击走页面原有处理，和手绘图出口一样弹出目的地卡片。
- 内容：「✈️/🛣️ 目的地（区域）」，图标对读屏隐藏；读屏念「去阿德莱德（南澳大利亚）的航线」。往东的出口锚在右边（圆点在右、字往左），避免文字出界。

**【v42 已做】读屏说明跟区域走**：`#basemap` 的 `aria-label` 以前写死「西澳真实地图」，在南澳也这样念。现在由 `mapLabel(area.name, true)` 按当前区域生成，SVG 也改用同一个函数。

**【提议】**
- 「看全澳」视图：底图缩小到两个区域的并集，方便规划跨区出行。需要决定是否允许在非本区域地点上点击（规则层允许，只是现在的 UI 只画本区域）。
- 区域切换按钮（只看，不移动）：在底图上看另一个区域。

## 5. 地图上显示什么

| 内容 | 状态 | 说明 |
| --- | --- | --- |
| 游戏地点（西澳 22 个、南澳 13 个） | 【现状】 | 圆点 + 名字 + 天气 + 在线人数；你在这里 / 没去过 / 选中有不同样式 |
| 路线、跨区出口 | 【现状】，底图出口【v42 已做】 | |
| 打卡点 POI（`wa.pois.json`，11 个） | 【现状】不上地图 | 在「附近」页按定位列出 |
| 真实店铺（`*.venues.json`，西澳约 1570、南澳约 900，来自 OSM） | 【现状】不上地图 | 数据在「附近」页打开时才下载 |
| GPS 主要路线 | 【提议】 | `claude/earth-gps-route` 分支在做，需要在地图上画；建议用底图的 GeoJSON 图层（同 `game-routes` 的做法），手绘图只画起终点连线 |
| NPC 位置 | 【提议】 | 只能画在游戏地点上（NPC 本来就只有游戏地点），按「该地点有 N 位熟人」显示，不需要新坐标 |
| 其他玩家 | 【现状】只显示每个游戏地点的人数（👥N） | 见第 6 节 |
| 动物出没 | 【提议】 | `claude/earth-pets-wildlife` 在做；同样只按游戏地点聚合 |

**【提议】真实店铺上底图**：只在玩家所在地点、缩放到城市级别（zoom ≥ 12）时显示，用 GeoJSON 源 + `circle` 图层（WebGL 画，不建 DOM），点击后跳到「附近」页对应条目。数据仍然只来自 OSM（`AGENTS.md` 要求）。注意 venues 数据要懒加载，不能为了地图把它拉进首屏。

## 6. 隐私

**【现状】**
- 广播给其他玩家的只有**游戏地点 id**（`world.ts` 的 `move` 消息是 `{ id, loc }`，loc 是「珀斯」这类地点），没有经纬度。
- 存档里的 `fix` 只记最近一次真实定位、坐标保留 3 位小数（约 100 米），用于服务器核对到店和移动速度，**不广播、不显示**。
- 地图上的「👥N」只是每个游戏地点的人数。

**原则（必须保持）**：地图上永远不显示其他玩家的真实位置、真实坐标、轨迹或「距离你 X 米」。将来如果做 GPS 路线或店铺打卡的多人显示，也只能聚合到游戏地点或店铺，且人数少于 2 时不显示具体店铺（防止从「这家店有 1 个人」推出某人在哪）。

## 7. 性能

**【现状】**
- 地图库动态导入，不进首屏（`basemap.test.ts` 有测试守着）。
- 标记是 DOM 按钮，每个区域 ≤22 个 + 出口 ≤2 个；内容没变时不碰 DOM（第 35 轮）。
- 手绘图每次 `renderMap()` 整个重写 `innerHTML`，地点少，开销可接受。
- 只在「出行」页画地图。

**v42 的增量**：首屏脚本只多了 `exitPoint`、`mapLabel` 和出口分支几十行，地图库本身没变。

**【提议】**
- 标记超过约 50 个（比如上真实店铺）时改用 GeoJSON 图层，不再一个标记一个 DOM。
- 离开出行页一段时间后 `dropBasemap()` 释放 WebGL 上下文（手机上 WebGL 上下文数量有限）。要和性能分支确认指标后再做。

## 8. 无障碍

**【现状】**
- SVG 是 `role="img"`，底图是 `role="region"`，两者的说明都写着「下面的列表是同样的内容」——地图下面的目的地列表能完成同样的操作，读屏用户不用地图。**这句话必须保留**（v42 抽成 `mapLabel()`，测试守着）。
- 底图标记是真按钮，有 `aria-label`（地点名 + 你在这里 / 没去过 + 人数），天气图标 `aria-hidden`。
- 手势：`cooperativeGestures`（单指滚页面，双指移地图），提示文案已汉化；关了旋转。

**【v42 已做】** 底图 `aria-label` 跟区域；出口标记有读屏文案。

**【现状】** 下面的列表（`panelGo()` 的 `travelOptions`）已经包含从当前地点出发的跨区路线，并标「去南澳大利亚 · 」（第 43 轮），所以出口标记在列表里有对应项，「同样的内容」成立。

## 9. 深色模式

**【现状】**
- 页面跟随系统 `prefers-color-scheme`，`:root` 有浅色、深色两套 token。
- 手绘图用 token 着色，深色下自然变暗；夜晚（游戏内天色 `p-night`）另有一套夜色。
- 底图以前**只在游戏夜晚**用滤镜压暗（`invert(0.92) hue-rotate(180deg) brightness(0.85)`），系统是深色模式时白天仍是一张亮白地图。

**【v42 已做】** 系统深色模式下，底图画布也用同一个滤镜压暗；标记标签保持白底深字，两种模式都可读。出口标记用固定深蓝字（`#1d4fa8`），在白底标签上对比度足够。

**【提议】** 用 OpenFreeMap 自带的深色样式（如 `dark`）代替 CSS 反色，颜色更自然、文字更清楚。代价是深/浅切换时要 `setStyle()` 并重加路线图层；样式名需要先核实 OpenFreeMap 当前提供哪些。
