# 地球人生：威胁模型与安全审查（v40）

- 分支：`claude/earth-security`，基于 `main` e429bcd（2026-11-20）。
- 范围：`src/game/server/world.ts`（Durable Object `EarthWorld`：云存档、权威结算、在线频道、共同事件、送礼/二手摊、留言、周目标），`src/worker.ts` 的路由入口，`src/pages/earth.astro` 客户端，`src/game/ui/transfer.ts` 同步码，部署配置 `wrangler.json`，依赖（`npm audit`）。
- 不在范围：百家乐（`BaccaratTable`）、博客页面、其他分支上还没合并的功能（只在第 6 节列出看到的问题）。
- 验证方式：读代码 + 本地测试替身（内存假存储、假 WebSocket）。**没有对线上环境做任何测试**。表里「已验证」指有本地测试复现或覆盖；「代码确认」指读代码能确定、但没写测试；「未验证」指推断，没有证据。

## 1. 系统和资产

| 资产 | 存在哪里 | 被拿到 / 被改的后果 |
| --- | --- | --- |
| 同步码 `id.key` | 客户端 `localStorage`、二维码、剪贴板；服务端只存 `sha256(id:key)` | 拿到就能完全控制这个角色（读档、行动、送礼把东西送走） |
| 角色存档 | DO 存储 `save:<id>` | 数值被改 = 作弊；丢失 = 进度没了 |
| 全服共享状态 | `rank:*` 排行榜、`week:*` 周计数、`notes:*` 留言、内存里的大厅和挂单 | 灌榜、刷周目标、刷屏 |
| 服务可用性 | 每个区域一个 DO 实例（200 连接上限）、`@SAVES` 单实例承载所有存档 | 一个实例被占满或拖慢，所有人受影响 |

## 2. 入口和信任边界

```
浏览器 ──HTTPS POST /api/earth/save（JSON，id+key 在请求体）──▶ Worker ──▶ DO '@SAVES'
浏览器 ──WSS /api/earth/ws?region&id&name&avatar&loc──────────▶ Worker ──▶ DO '<区域>'
浏览器 ◀─静态资源（/earth/ 页面、图片、地图瓦片走第三方）── Cloudflare 静态资源（public/_headers 生效）
```

- 不可信：请求体所有字段、WebSocket 握手参数和每条消息、`CF-Connecting-IP` 以外的所有请求头、客户端上报的 GPS 坐标和精度。
- 可信：DO 存储里的数据（但读出后仍过 `sanitizeState()`）、服务器时钟（有回拨保护）。
- 客户端完全不可信：它只发「动作」，存档由服务端 `applyAction()` / `applyCoop()` / `applyTrade()` 结算。

## 3. 问题清单

严重性按「在这个游戏里实际能造成什么」评：高 = 能稳定获利或让服务不可用且门槛低；中 = 能获利/骚扰/拖垮但有门槛或影响有限；低 = 理论上可能或影响很小。

| 编号 | 类别 | 问题 | 严重性 | 复现条件 | 状态 |
| --- | --- | --- | --- | --- | --- |
| S-01 | 定位伪造 | `main` 上的 `gps` 动作不带精度、不查移动速度：伪造一个坐标就能瞬间「真实抵达」任何城市（免车费免时间）并刷 POI 打卡奖励 | 高 | 已登录角色；改客户端或直接 POST `act {t:'gps', lat, lon}` 填目标城市坐标 | 代码确认。**已在 `claude/earth-gps-anticheat-3d8db4`（83257f9）修复**（加精度和瞬移检查），本分支不重复改，合并那个分支即可 |
| S-02 | 定位伪造 | 精度 `acc` 是客户端自报的，模拟定位 App 可以同时伪造坐标和精度 | 中（残余） | 手机装模拟定位 App，或直接改请求 | 代码确认。浏览器端没有可信定位证明，服务端只能做合理性检查（距离、速度、精度上限）。接受为残余风险，奖励设计上不要让 GPS 打卡比正常出行更赚 |
| S-03 | 存档篡改 | 客户端改本地存档后提交 | — | — | **不成立**（已验证）：没有上传存档的接口，`action: 'upload'` 返回 400 且不改存档（`server.test.ts`「入口保护的状态码」）；本机缓存只用于离线显示，联网后一律以服务器为准；`publicState()` 不发种子 |
| S-04 | 资源滥用 | 在线频道每个区域 200 个连接，但不分来源：一个人开 200 个 WebSocket 就能占满整个区域，别人连不上（返回 region full） | 中 | 一台机器循环建 WebSocket 连 `/api/earth/ws?region=wa&id=随便6位以上` | 已验证、**已修**：同一来源在一个区域最多 6 个连接，第 7 个返回 429；断开即释放 |

| S-06 | 聊天刷屏 | 聊天只受「每个连接 5 秒 20 条消息」的总限流，等于每秒 4 句；多开连接再乘上去 | 中 | 一个连接循环发 `{t:'chat'}` | 已验证、**已修**：同一来源 10 秒最多 6 句（多个连接合计），多出的直接丢掉；心跳、移动不受影响 |
| S-07 | 聊天 XSS | 聊天、名字、头像、留言、挂单、榜单插进 HTML | — | — | **不成立**（代码确认）：服务端去控制字符、限长；客户端所有来自网络的字符串都过 `esc()`，提示条用 `textContent`；`s.avatar` 没转义但服务端只认白名单里的头像。抽查方法：搜 `${p\|c\|n\|o\|r\|m.name/text/avatar}` 的未转义插值，命中的都是静态数据或 `textContent` |
| S-08 | 限流可被重置 | 存档接口的限流表超过 5000 条时**整表清空**：攻击者换 5000 个地址发一轮请求，所有人（包括他自己）的计数归零。IPv6 一台设备就能随手换出无数个地址 | 中 | 有一段 IPv6 前缀，换着源地址发请求 | 已验证、**已修**：IPv6 按 /64 计数；表满时先清过期的，再丢计数最少的一成，正在刷的来源的计数留着 |

| S-11 | 凭证猜测 | 暴力猜同步码 | — | — | **不成立**（代码确认）：key 是 24 位 `[a-z0-9]`，用 `crypto.getRandomValues` 生成（取模有轻微偏差），约 124 bit；id 约 77 bit。限流 90 次/分钟/来源，比对的是哈希且用常量时间比较 |
| S-12 | 凭证泄露 | 真实 `id` 出现在 WebSocket 握手 URL 里，Cloudflare 开了 `observability`，请求 URL 可能进 Workers 日志 | 低 | 能看日志的人 | 未验证（没看控制台）。只有 id 没有 key 读不了档；AGENTS.md 也明确允许握手带 id。后续可以改成握手只带 id 的哈希 + 服务端签发的短期令牌 |
| S-13 | 凭证泄露 | 同步码在二维码链接里 | — | — | **不成立**（代码确认）：放在 `#` 后面，不发给服务器、不进 Referer；页面读完立刻 `history.replaceState` 抹掉 |
| S-14 | 账号存在性 | 不存在的 id 返回 404「云端没有这个存档」，key 错返回 403，可以判断某个 id 是否存在 | 低 | 知道或猜到一个 id | 已验证（现有测试）。id 有 77 bit 随机性，枚举不现实；暂不改，免得影响「换设备时提示没有这个存档」的体验 |
| S-15 | 刷奖励 | 小号通过送礼、二手摊（价格 50%–150%）把钱和东西转给大号 | 中（残余） | 多个角色在同一地点 | 代码确认。S-05 把批量建号压下来了；每日送出次数有 `giveBlocked` 上限。是否加「新角色 N 天内不能交易」属于玩法取舍，交给用户/Codex 定 |

## 4. 依赖漏洞（`npm audit`，2026-11-20）

本站几乎所有页面都是构建时预渲染的静态页，Worker 运行时只跑自己写的 DO 代码和 Astro 的 404 兜底；`astro:assets` 图片处理、`define:vars`（除 staff 页）、服务端岛、MDX 动态渲染都没用到。所以大部分告警在构建机或开发服务器上，不在线上请求路径里：

| 包 | 最高等级 | 在不在线上请求路径 | 判断 |
| --- | --- | --- | --- |
| astro 5.16.9 | 严重（AVIF 图片优化 RCE，<7.2.8） | 构建时；本站不处理用户上传的图片 | 构建期风险，低 |
| astro（其余 13 条：XSS、SSRF、base 路径绕过等） | 高 | 大多针对 SSR 渲染用户输入；本站页面全预渲染 | 低，未验证 |
| @astrojs/cloudflare 12.6.12 | 高（image-binding SSRF） | 没开图片绑定 | 低 |
| devalue、undici、ws、miniflare、wrangler、vite、esbuild、postcss、sharp、svgo、js-yaml、smol-toml、nanoid、zod… | 高 | 构建、开发服务器、部署工具 | 构建机/开发机风险，低 |
| @astrojs/rss | 中（XML 注入） | `/rss.xml` 构建时生成，内容是自己写的博客 | 低 |

修复需要 Astro 5 → 7、Cloudflare 适配器 12 → 14 两个大版本，属于破坏性升级，**本分支不做**。建议单独开一个分支：独立 `node_modules` 里升级，跑全部测试和 `npm run check`，再在预览环境真机过一遍。

## 6. 其他分支上看到的问题（只读，没改）

- **`claude/earth-economy`（1bcf8a8）理财买卖：结算价信任存档里的 `quotes` 字段**（中，潜在）。`assetPrice()` 有 `state.quotes` 就用它的最后一个价；`sanitizeState()` 会保留合法形状的 `quotes`。现在服务端存档里不会有这个字段（只有 `publicState()` 的副本里有），所以目前打不出来；但只要以后任何路径让客户端提供的对象进了存档（例如导入存档、存档同步分支的 `carryUnknown` 保留未知字段、某次把 `publicState()` 的结果误写回），玩家就能把价格写成 0.0001 低价买入、再写高价卖出，无限刷钱。建议：服务端结算前强制去掉 `quotes`（`applyAction` 入口或 `sanitizeState` 的服务端模式），并加一条测试「存档里带 `quotes` 时按种子价结算」。同日买卖必亏手续费、份数和金额的取整方向都对玩家不利，没看到别的刷钱路径（代码确认，未写测试）。
- `claude/earth-gps-anticheat-3d8db4`：覆盖 S-01，建议尽快合并。
- `claude/earth-live-social`：覆盖 S-19 的大部分；它改了 `onMessage` 里 `chat` 分支，本分支的聊天限流放在 `switch` 之前单独一行，合并时不冲突。
