# 爱好与收集（第 45 批，分支 `claude/earth-hobbies`）

把散落的「钓鱼、拍照、图鉴、相册」收拢成一套爱好系统和统一的收集册。
标记：**【现状】** main 上已有的；**【v45 已做】** 本分支落地的；**【提议】** 还没做，等讨论或别的分支。
所有新数值都是 **待平衡**：Claude 按直觉定的初值，等 Codex 跑模拟、写分析后再调（AGENTS.md：Claude 不下平衡结论）。

## 1. 现状盘点【现状】

| 内容 | 位置 | 怎么玩 | 奖励 | 存档 |
| --- | --- | --- | --- | --- |
| 钓鱼 | `data/fish.ts`、`engine.ts` 的 `fishingAt` / `goFishing` | 要鱼竿；按地点、季节、时段、天气筛 12 种鱼；风暴天不能钓；生存能力降低空手几率 | 钓到当场卖钱（$5–60） | `fish`：鱼种 → 条数 |
| 摄影任务链 | `data/photo-quests.ts`、`photoQuestNow` / `takeQuestPhoto` | 8 个任务按顺序，指定地点、时段、天气点「拍照」 | $30–80、声望 +2–4，整条 +5 | `photoQuest` |
| 野生动物图鉴 | `data/wildlife.ts`、`animalsAt` / `recordAnimal` | 抵达时按几率看见；哈希不推进种子 | 每组集齐声望 +4 | `dex`、`dexSets` |

问题：钓鱼没有「规定」这件在澳洲真实存在、华人新移民常踩的坑；钓到什么都卖钱；拍照只有一条任务链，做完就没了；
几个收集各自一张卡片，没有统一的进度、稀有度和奖励；这些玩法对心情、能力、社交都没有持续的作用。

## 2. 爱好框架【v45 已做】

六个爱好：📷 摄影、🎣 钓鱼、🐦 观鸟、🌱 园艺、🧶 手工、🪕 乐器（`data/hobbies.ts` 的 `HOBBIES`）。

| 规则 | 数值（待平衡） | 代码 |
| --- | --- | --- |
| 熟练度：当天第一次做 +3，再做 +1，上限 999 | `HOBBY.xpFirst` / `xpRepeat` / `xpMax` | `session()` |
| 等级：0 / 10 / 30 / 60 / 100 起，入门、熟手、行家、高手、大师 | `HOBBY.levels` | `hobbyLevel()` |
| 同一天反复做同一件事，心情收益 ×1、×0.5、×0.25（体力消耗不打折） | `HOBBY.repeat` | `repeatMult()` |
| 当天第一次做：心情状态「沉浸在爱好里」+4，8 小时 | `moodlets.ts` 的 `hobby-flow` | |
| 同好 NPC 此刻在场：一起做，好感 +2、社交 +6 | `HOBBY.palGain` / `palSocial`，各爱好的 `pals` | `palsHere()` |

递减的理由：防止玩家在一个地方连刷同一个爱好回娱乐；也让「今天钓一会、拍一组、回家种点菜」比只做一件事更划算。

## 3. 钓鱼规定【v45 已做】

### 3.1 规则

- 钓到鱼后先量尺寸（`fishCm`：按鱼种的体长区间，两个均匀数取平均；**只读种子做哈希、不推进种子**，所以加了尺寸不改变别的随机结果）。
- 再按所在州、所在地点查规定（`fishRuleAt`：分区规定优先，其次这个州的通用规定），`judgeCatch` 按顺序判：
  禁捕或禁渔季 → 不够最小尺寸 → 当天同种鱼已经带满。任何一条不满足就**放生**：不卖钱、不计数量，但仍记进鱼种图鉴（`fish` 条数 +1）和最大尺寸。
- 当天带走的数量记在 `hobby.bag`，换一个游戏日清零。
- 没有查到规定的鱼种，界面显示「规定待核实」，游戏里不限。
- 执照：游戏只有岸钓，按两州规定岸钓都不需要执照，所以不做执照物品；钓鱼卡片显示所在州的执照说明和来源。
  【提议】以后加「出海钓」时做西澳的船钓执照（RFBL），并按 DPIRD 的规定，西海岸生物区船钓底层鱼到 2027 年春都禁止。
- 熟练度：每级让空手权重 −3（`FISH_EMPTY_PER_LEVEL`）。

## 5. 存档【v45 已做】

按 `save-sync.md` §5：新增一个字段 `hobby`（`HobbyState`），`createCharacter` 给空值，`sanitizeState` 一行 `cleanHobby(r.hobby, knownLocs)`。

```
hobby: {
  xp: { 爱好id: 0–999 }, day: 游戏日 | −1, today: { 爱好id: 次数 }, bag: { 鱼id: 条数 }, best: { 鱼id: cm },
  birds: [鸟id], works: { 地点id: 0–100 }, plants: [植物id], bed: { plant, day } | null, made: [手工id], got: ['birds:half' …]
}
```

- `cleanHobby`：旧存档没有给空的；只留认识的 id（爱好、鱼、鸟、植物、手工、地点）；数值钳到范围；不读原型链上的键；`got` 只认 `收集册:half|full` 的形状；幂等。
- 曲目不存，按乐器熟练度现算（`songsKnown`）。
- 大小：塞满所有地点、鸟、鱼也在 4 KB 以内（测试检查）。
- 没改 `SAVE_VERSION`，没改已有字段。`fish` 的含义从「钓到过（都卖了）」变成「钓到过（含放生）」，形状不变。

## 6. 动作与安全【v45 已做】

- 新动作 `{ t: 'hobby', id }`，`parseAction` 只认摄影、观鸟、园艺、手工、乐器五个 id（钓鱼仍走 `{ t: 'fish' }`）；结算走 `applyAction`。

## 8. 模拟

`npm run earth:sim -- --days=180 --runs=100`：本分支和最新 main（`0fc4d46`，含经济、属性公式）的报告**逐字相同**。

原因：模拟机器人不钓鱼、不拍照、不做任何爱好，也不会集齐收集册；新加的鱼体长用哈希、不推进随机种子；
`fish.ts` 只给南澳加了地点，机器人不去南澳；新物品尤克里里机器人不买。所以这一版对现有策略的收入、心情、破产率没有影响。

这也说明现在的模拟**看不出爱好系统的平衡**。【提议】请 Codex 给模拟加两种策略再看：
「休闲玩家」（每天钓鱼 + 随手拍 + 园艺，看娱乐需求是不是太容易满、钓鱼收入放生后够不够补贴生活）、
「收集玩家」（专门跑收集册，看多少天能收齐、声望奖励占总声望的比例）。递减倍率、熟练度节奏、里程碑声望等都等这份分析再调。
