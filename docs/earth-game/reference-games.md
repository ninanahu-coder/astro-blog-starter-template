# 参考：经典虚拟游戏的设定，哪些值得借鉴

> 说明：以下是我凭对这些游戏的了解整理的，没有逐条核对资料，个别细节可能随版本不同。
> 目的是借鉴**玩法机制**。不使用这些游戏的名称、角色、美术、文案或关卡。

## 1. 经典游戏各自最核心的设定

| 游戏 | 最核心的设定 | 为什么有效 |
| --- | --- | --- |
| 模拟人生系列 | 需求条（饥饿、精力、卫生、社交、娱乐等）；技能与职业阶梯；人际关系；**愿望与恐惧**（角色自己冒出短期心愿）；性格特质；带时限的心情加成；人生阶段与衰老；建造与装修 | 角色“自己想要东西”，玩家永远有下一件小事可做 |
| 侠盗猎车手：圣安地列斯 | 能力**用进废退**（体力、肌肉、驾驶、肺活量）；声望；通缉星级；买房产收租；健身房、理发、换装；地盘 | 做什么就变成什么，成长不靠菜单 |
| 动物森友会系列 | **与现实时间同步**；四季与节日；可分期的无息房贷；博物馆式收集（鱼、虫、化石）；每日小事；访问别人的岛 | 每天上线十分钟就有收获，没有失败惩罚 |
| 星露谷物语 | 每季 28 天的日历；节日；NPC 有各自**最爱 / 喜欢 / 讨厌**的礼物和每周日程；好感度分心级并解锁剧情；“社区中心”式的打包收集目标 | 日历带来节奏，NPC 有个性，收集有阶段性大奖 |
| 宝可梦 GO | **真实位置**就是游戏地图；地标打卡点；真实天气影响内容；每日首次奖励与连续七天奖励；限时社区活动 | 把出门变成玩法，现实世界自带新鲜感 |
| 第二人生 | 玩家创造内容；土地所有权；虚拟货币经济 | 世界由玩家建成，经济是真的 |
| 哈宝旅馆 / 摩尔庄园一类 | 自己的房间可以布置并**让别人来参观**；家具收集与交换；公共场所闲逛 | 布置是为了被看见 |
| QQ 农场 / 开心农场 | 计时成熟；**去好友家互动**（帮忙、偷菜）；异步社交 | 不同时在线也能互动，天天有理由回来 |
| 电子宠物 | 需要定时照顾；疏于照顾有后果 | 责任感带来牵挂 |
| 大富翁类 | 买地收租；机会与命运卡 | 资产积累加随机事件，起伏明显 |

## 3. 还缺什么，按建议优先级排

### 第一档：投入小，对“每天想回来”帮助最大

**1. 短期心愿（借鉴“愿望”系统）**
角色每天冒出 2–3 个小心愿，比如“想吃顿好的”“想去海边”“想见见米娅”“想涨工资”。完成给心情和少量声望，过期自动换新。

- 解决的问题：现在玩家打开游戏不知道该做什么，只能自己看需求条。
- 实现：数据驱动。一张心愿表，每条写触发条件和完成条件；存档加一个当前心愿列表。

**2. 日历、季节与节日（借鉴 28 天一季和节日）**
游戏内一年分四季，每季若干天；固定日期有节日，比如布鲁姆的珍珠节、玛格丽特河的冲浪赛、西南的野花季、珀斯的天空烟火夜。节日当天当地有专属体验和事件。

- 解决的问题：现在每一天都一样，时间只是数字。
- 实现：`core/time.ts` 加季节函数；事件和体验加“季节 / 日期”条件。现有的“野花季”事件可以直接改成只在春天出现。

**3. 每日首次奖励与连续登录（借鉴每日奖励）**
每个现实日第一次上线、第一次打卡、第一次上班各有小奖励；连续 7 天有一份大的。

- 解决的问题：留存。
- 注意：服务端要记现实日期，这是引擎里第一次用到真实时间，要放在服务端层，不能进纯函数引擎。

### 第二档：让世界更像活的

**4. 带时限的心情加成（借鉴“心情状态”）**
做过的事留下几小时到几天的状态，比如“刚看过鲸鲨：心情 +10，持续 2 天”“睡了个好觉”“被雨淋了”。心情由这些状态叠加，界面上能看到每一条来自哪里。

- 解决的问题：现在心情只是需求条的平均数，玩家不知道为什么高、为什么低。

**5. NPC 更有个性（借鉴最爱礼物和日程）**
礼物分“最爱 / 喜欢 / 一般 / 讨厌”四档；NPC 在不同日子出现在不同地点；好感度每升一档解锁一段小剧情或一个专属互动。

**6. 真实天气（借鉴真实天气影响内容）**
接澳洲气象局开放数据。下雨时海滩活动受限、室内活动加成；高温天内陆出行更累；特定天气才出现的事件。

- 这一项之前已经在待办里。和第 2 项的季节配合效果最好。

### 第三档：社交，工作量大

**7. 参观别人的家（借鉴房间参观和好友互访）**
玩家可以去别的玩家的住处看看，留言或帮个小忙（比如帮忙浇花，双方各得一点好处）。不同时在线也能互动。

- 解决的问题：现在装修和买房只有自己看得到。
- 我的建议是只做“帮忙”，不做“偷”。偷菜式玩法容易让新玩家反感。

**8. 外观与换装（借鉴理发、服装）**
头像现在只是一个表情符号。换装是经典的花钱去处，也让别人看得出你是谁。

- 依赖美术资源，适合等 ComfyUI 出图接通后再做。

**9. 人生阶段（借鉴衰老与世代）**
角色随游戏年份变老，能力上限变化，最后退休并把一部分资产传给下一个角色。

- 这是很大的设计决定，会改变整个游戏的节奏，建议放到很后面。

## 4. 不建议借鉴的

| 设定 | 原因 |
| --- | --- |
| 抽卡、付费变强 | 破坏现在“做什么就变成什么”的基调 |
| 疏于照顾就永久惩罚（宠物死亡式） | 手机游戏玩家会断线几天，回来发现一切都毁了就不会再玩。我们现在晕倒只罚医药费，这个尺度合适 |
| 偷取其他玩家的东西 | 容易引发报复和流失 |
| 虚拟货币与现实货币兑换 | 涉及金融和博彩监管，另外会招来刷钱 |
| 完全由玩家创造内容 | 需要内容审核，现阶段承担不了 |

## 5. 进度

**第一档三项已实现**：日历、季节与节日；短期心愿；每日奖励与连续登录。规则见 [core-design.md](core-design.md) 的「日历、心愿与每日奖励」一节，对经济的影响见 [balance.md](balance.md) 第五轮。第二、三档未做。

## 6. 当初建议的顺序（已完成）

先做第一档的三项，顺序是：**日历与节日 → 短期心愿 → 每日奖励**。

- 日历是另外两项的基础：心愿可以引用节日（“想去看珍珠节”），每日奖励也要用到日期。
- 三项都主要是加数据，引擎改动小，可以用现有的模拟器验证不会打乱经济。
- 做完之后，这个游戏才从“可以玩”变成“每天想回来看看”。
