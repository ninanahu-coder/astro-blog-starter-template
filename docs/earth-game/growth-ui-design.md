# 养成与留存：游戏风格和界面设计方案（草案）

> 状态：设计草案，未实现。所有数字都标 **待平衡**：按 AGENTS.md，数值先交 Codex 分析，再由用户拍板，我不做平衡判断。
> 画面在设计稿「地球人生 · 手机客户端草图」第四排「养成版」。

## 0. 一句话

现在的「地球人生」更像一个**生活模拟器**：系统多，但玩家看不到“我在长大”。这份方案不加新数值系统，而是把已有系统**收拢成一条看得见的成长线**，再用 AIGC 让每天打开都有一点新东西。

## 1. 参考：主流游戏的“语言”和 GitHub 上能借的东西

| 来源 | 借什么 | 不借什么 |
| --- | --- | --- |
| 主流养成手游（通行证、日常、图鉴、红点） | **三层循环**：一局几分钟、每天回来、每周/每季有大目标；红点只标“有奖可领”；进度永远可见 | 抽卡、体力购买、付费变强（[reference-games.md](reference-games.md) 第 4 节已否决，这里不变） |
| [HabitRPG/habitica](https://github.com/HabitRPG/habitica)（GPL-3.0，开源习惯养成 RPG） | 现实行为 → 经验与等级；**宠物/坐骑养成**；连续天数；组队任务 | 断签掉血这类惩罚；GPL 代码不拷，只借机制 |
| [a16z-infra/ai-town](https://github.com/a16z-infra/ai-town)（MIT，生成式智能体小镇） | NPC **记忆流**：记住和你最近几次交往，台词由模型生成 | 让模型决定结果（会破坏纯函数引擎和平衡） |
| [neph1/LlamaTale](https://github.com/neph1/LlamaTale)、[ssube/taleweave-ai](https://github.com/ssube/taleweave-ai) | 角色对其他角色的“好感倾向”影响说话方式；地点描述可以由模型补写 | 动态生成地点（违反“只用 OSM / Wikidata / 种子数据”） |
| [pmotschmann/Evolve](https://github.com/pmotschmann/Evolve)（放置类） | **离线收益**和“转生（prestige）就是留存循环”；第一次转生要来得比你想的早 | 指数级数字膨胀 |

## 2. 养成框架：一条主线 + 四条支线

已有系统几乎都能挂上去，**引擎改动小**。

| 养成线 | 玩家看到的 | 用到的现有系统 | 要新增的 |
| --- | --- | --- | --- |
| **人生等级**（主线） | 头像外圈的经验环、Lv 和称号，升级有全屏结算 | `level()`：10 级称号，从「新来的」到「土生土长」 | 升级弹窗；每级解锁一样东西（新地点类型、家具槽、旅伴技能）**待平衡** |
| **人生树**（能力） | 三棵分支：职业 / 生活 / 探索，节点亮起 | `skills` 七项能力、职业阶梯、特质 | 只是把现有能力按阈值画成节点；节点奖励是称号或外观，**不加数值** |
| **旅伴**（宠物养成） | 一只跟着你旅行的本地动物，会长大、换表情、学小技能 | 野生动物图鉴 `dex`、出行 `trips` | 新数据：旅伴成长阶段 4 段，按「一起去过的地点数」成长 **待平衡**；原创形象，不用任何现有游戏角色 |
| **明信片图鉴**（收集） | 每个真实地点 × 季节 × 天气一张 AI 明信片，稀有度来自**天气和时段**，不来自付费 | 打卡 `checkins`、拍照 `photos / stormPhotos / rainPhotos`、季节、天气 | 明信片表（见第 4 节）；图鉴分区完成给称号 |
| **季节手册**（通行证） | 每季 28 档，免费，只有一条线 | 周目标 `weekly`、心愿 `wishes`、节日 | 档位奖励是外观、家具、旅伴装饰；**不卖、不加付费线** |

### 2.1 三层循环

| 层 | 时长 | 玩家做什么 | 拿到什么 |
| --- | --- | --- | --- |
| 一局 | 3–8 分钟 | 看「今日三件事」→ 出行/打卡/上班 → 领明信片 | 经验、今日明信片、旅伴成长 |
| 每天 | 每个现实日 | 签到、心愿、今日 AI 日记 | 连续天数、季节手册经验 |
| 每周 / 每季 | 7 天 / 28 天 | 周目标、节日活动、图鉴分区 | 称号、外观、季末回顾卡 |

### 2.2 粘性手段，以及刻意不做的

**要做：**
- **今日三件事**：从心愿和周目标里挑 3 件，做完全部再给一次额外奖励。打开游戏就知道该干嘛。
- **离线收益**：房租和投资在离线时继续累积，回来先领一次。这已经是规则，只差一个“欢迎回来”的结算画面。
- **断签保护**：每周自动给 1 张补签卡，断一天不清零。比惩罚更留人。
- **回流礼**：7 天没上线，回来送一份“这周的世界发生了什么”的 AI 回顾，加一张补签卡。
- **红点克制**：红点只标“有奖可领”和“有人找你”，不标“有新内容”。

**不做：** 抽卡、体力购买、限时付费礼包、排行榜上的现金奖励、断签清零。

## 3. 界面风格

沿用现有设计稿的 token（米白底 `#f5f2ec`、主蓝 `#1d5fd1`、暖橙 `#c2541b`、PingFang SC），深色模式照旧配对。新增四个“游戏化”元素：

1. **经验环**：头像外圈的环形进度，和需求环同一画法。
2. **成长卡**：圆角 18、白底、左侧是插画或缩略图，右侧是进度。不用渐变铺底，不用左边框色条。
3. **奖励结算**：底部弹起的结算卡，列出“这次得到了什么”，按钮只有一个。
4. **红点**：只有暖橙一种颜色；数字只用在“可领奖励数”。

底部导航从五个改为「今天 / 出行 / 成长 / 社交 / 我」。「附近」并入「出行」的一个分页，「成长」作为新的一级入口。**这个改动需要用户确认**，因为它改变现有的信息结构。

## 4. AIGC 怎么接，才不破坏规则

原则：**AI 只生产“表现”，不生产“规则”**。核心引擎保持纯函数，模型的输出不进 `src/game/core`。

| 用途 | 怎么生成 | 何时生成 | 成本与风险控制 |
| --- | --- | --- | --- |
| **明信片插画** | 本地 ComfyUI 或 gpt-image-2：地点名 + 季节 + 时段 + 天气 → 一张图 | **离线批量预生成**，按 地点 × 4 季 × 4 时段 × 3 天气 建库，玩家只是“解锁”已有的图 | 不按玩家实时出图；每张人工抽检后上架；图上不出现文字和真实店名 |
| **NPC 台词** | 结果先由引擎按规则算好（好感档、送礼反应），模型只按“结果 + 最近 3 次交往摘要”改写台词 | 服务端，按需生成，缓存 | 失败或超时就用现有固定台词；台词过 `esc()`；不让模型改变好感或金钱 |
| **人生日记** | 当天的行动日志 → 一段 100 字左右的第一人称日记 | 游戏内一天结束时 | 只读日志，不写状态；可关闭 |
| **季末回顾卡** | 本季数据 + 4 张最好的明信片 → 一张可分享的竖图 | 季末 | 分享图里不带玩家真实位置，只带游戏地点名 |

需要的新东西：明信片表（`data/postcards.json`：地点、季节、时段、天气、图片地址、来源说明）；服务端的台词和日记接口，接 MiniMax（五个站的聊天机器人已经在用它）。

## 5. 建议的落地顺序

1. **只动界面**：经验环、升级弹窗、今日三件事、欢迎回来结算。全部用现有数据，不改规则。
2. **明信片图鉴**：先给珀斯和弗里曼特尔预生成一批，验证出图质量和存储成本。
3. **旅伴**：新数据，交 Codex 做数值分析后再定成长曲线。
4. **季节手册 + AI 日记 / NPC 台词**：涉及服务端和模型调用，放最后。

## 6. 需要用户拍板

- 底部导航是否改成「今天 / 出行 / 成长 / 社交 / 我」。
- 旅伴用哪种动物（建议短尾矮袋鼠、鸸鹋或针鼹三选一，形象全部原创）。
- 明信片出图走本地 ComfyUI 还是 gpt-image-2。
- 季节手册是否保持永久免费（建议是）。
