# 地球人生 —— 底层代码设计：人物属性与基本元素

本文说明游戏最底层的数据模型和数值规则。代码在 `src/game/core/` 与 `src/game/data/`，测试在 `tests/earth/`。

## 1. 分层

```
data/      纯数据：地点、路线、互动、事件、特质、物品（策划改这里）
  ↓ 只被读取
core/types.ts       所有结构的类型定义
core/attributes.ts  派生属性：心情、检定分、星级、等级、特质/物品修正系数
core/character.ts   创建角色、存档校验 sanitizeState()
core/engine.ts      动作：出行 / 互动 / 事件 / 打卡 / 买 / 用
  ↓ 返回新的 PlayerState
pages/earth.astro   只渲染和接收输入；server/world.ts 校验请求、调用引擎做权威结算并存储
```

三条硬规则：

1. **引擎是纯函数**：动作函数接收旧状态、返回新状态，不改入参，不读时钟，随机数只来自 `state.seed`。同一份代码在手机、测试和服务端上结果一致；实际结算以服务端为准。
2. **只存原始值，派生值现算**：心情、星级、等级、检定分都不进存档，避免存档里出现互相矛盾的字段。
3. **内容即数据**：所有数值变化都用同一个 `Effect` 结构描述；特质只是一组修正系数。加内容不需要改引擎。

## 2. 人物属性（`PlayerState`）

### 2.1 原始属性（存档里的字段）

| 分组 | 字段 | 范围 | 说明 |
| --- | --- | --- | --- |
| 身份 | `id` `name` `avatar` `origin` `traits` | — | 出身决定开局；特质创建时选 2 个，之后不可改 |
| 生活需求 | `needs.hunger/energy/hygiene/fun/social` | 0–100 | 随游戏时间下降；饱食或精力为 0 时持续掉健康 |
| 能力 | `skills.stamina/strength/driving/swimming/charisma/survival/street` | 0–100 | 靠行为成长，边际递减：增长 = 原值 × 特质倍率 × 0.35 × (1 − 当前值/110) |
| 收藏 | `collected` `courseDays` `photos` | — | 已完成的体验；每门课最近一次上课的游戏日；天气相册（`地点|天气`，抵达时按当天天气收集，只是收藏） |
| 状态 | `cash` `health` `respect` `heat` `vehicle` | 见下 | 现金 ≥0；健康 0–100；声望 ≥0；麻烦值 0–100 |
| 车辆里程 | `car` | 0–1000 万公里 | `{ km, since }`：这辆车开了多少公里、离上次保养多少公里；`since ≤ km`，没车时都是 0，换车、卖车清零 |
| 证书 | `certs` | — | 已考到的职业证书 id，跟人走，换工作不丢 |
| 摄影任务 | `photoQuest` | 0..任务数 | 摄影任务链做到第几个；等于任务总数表示全部拍完 |
| NPC 联动 | `duos` | id 列表 | 已触发的 NPC 联动剧情 |
| 主线剧情 | `story` | `{ ch, done }` | 第几章（等于章数表示全部写完）；本章各目标的进度，进下一章时清空 |
| 每日摘要 | `dayMark` / `yday` | `{ day, at, cash, respect, places }` / `{ day, days, from, to, cash, respect, places }` 或 `null` | 今天开始时的记号（`at` 是记下的那一分钟）；动作跨过午夜时（`core/recap.ts` 的 `rollDay`，在 `applyAction` / `applyCoop` 钳制数值之后）把上一段日子的变化记进 `yday`，界面只在之后那一天显示「昨天回顾」。跨午夜的那个动作数值和日志都算在 `yday` 里：回顾日志取 `from` 之后到 `to` 为止，不按午夜切 |
| 鱼获 | `fish` | 每种 ≥1 | 钓到过的鱼：鱼种 id → 条数 |
| 图鉴 | `dex` `dexSets` | — | 见过的野生动物 id；已发过奖的图鉴分组（集齐时记下，以后加新动物不收回、不重复发） |
| 物品 | `inventory` | 每种 1..上限 | `itemId → 数量` |
| 职业 | `job` | — | `{ career, loc, level, shifts, good, lastDay }`：雇主、工作地点、等级、本级已上班次与表现好的班次、最近上班日 |
| 住房 | `home` | — | `{ type, loc, furniture }`：房型、所在地点、各槽位的家具 |
| 周结算 | `nextWeek` | — | 下一次周结算的游戏日 |
| 心情状态 | `moodlets` | — | `{ id, until }[]`：带时限的心情加减，到 `until`（游戏分钟）失效 |
| 心事结算 | `mind` | — | `{ day, low }`：最近结算到哪个游戏日、连续几天心情低落（0–30）。第 43 批，见 [mood.md](mood.md) |
| 心愿 | `wishes` `wishDay` | — | 今天还没完成的心愿 id；这批心愿生成于哪个游戏日 |
| 每日奖励 | `daily` | — | `{ day, streak }`：最近领取的现实日序号（珀斯时间）、连续天数 |
| 房产 | `properties` | — | `{ id, loan, rented, missed }[]`：剩余贷款、是否出租、连续欠款周数。住在自有房里时 `home.owned` 指向它 |
| 关系 | `relations` | 分数 −100..100 | `npcId → { score, last, seen, known }`：分数、每种互动最近一次的游戏日、已触发的剧情门槛、已知送礼反应的物品 |
| 世界进度 | `loc` `clock` `visited` `checkins` `seen` `pending` | — | 位置、游戏分钟、到访次数、打卡、一次性事件、待处理事件 |
| 系统 | `seed` `rev` `journal` | — | 随机数状态、云同步版本号、最近 40 条日志 |

### 2.2 派生属性（`attributes.ts`，现算）

| 属性 | 公式 | 作用 |
| --- | --- | --- |
| 心情 | `平均需求 × 0.75 + 最低需求 × 0.25 + 特质加值 + 住处 + 心情状态`，钳制 0–100 | 短板效应；`moodBreakdown()` 给出每一项来源，角色页逐条显示 |
| 心情档 | <25 低落（检定 −10）· <50 一般（0）· <85 愉快（+5）· ≥85 亢奋（+10） | 影响所有检定 |
| 检定分 | `能力值 + 特质加值 + 最高一件装备加值 + 心情加值` | 事件选项判定：`检定分 + 随机 0–60 ≥ 难度` |
| 通缉星级 | `floor(麻烦值 / 20)`，0–5 星 | ≥3 星（麻烦值 ≥60）到达新地点必被盘查 |
| 等级 | 声望阈值 0/10/25/50/90/150/240/360/520/720 | 1–10 级，对应称号“新来的”到“西澳之子” |

### 2.3 特质修正系数（`TraitMods`）

| 字段 | 类型 | 作用点 |
| --- | --- | --- |
| `gain` | 乘数 | 能力**增长**时（扣减不受影响） |
| `decay` | 乘数 | 需求随时间下降的速度 |
| `check` | 加值 | 检定分 |
| `cost` | 乘数 | 出行费用、商店价格 |
| `heat` | 乘数 | 麻烦值**上涨**时 |
| `hurt` | 乘数 | 健康**扣减**时 |
| `mood` | 加值 | 心情 |

两个特质的乘数相乘、加值相加。互斥关系写在 `conflicts`，必须双向（测试会检查）。现有 10 个特质见 `data/traits.ts`。

| 房产 `PropertyDef` | `data/properties.ts` | 地点、自住房型、房价、物业费、出租周租金 | 4 套；每人每套只能买一次 |
| 心情状态 `MoodletDef` | `data/moodlets.ts` | 名称、加减值、持续小时、缓解的心事（`relieves`） | 29 种；效果里写 `moodlet` 或由引擎在升职、晕倒、被收房等时刻发放；同种刷新不叠加；第 43 批加了孤独、思乡、压力三种心事（每日结算，见 [mood.md](mood.md)） |
| 节日 `FestivalDef` | `data/festivals.ts` | 地点、季节、开始日、持续天数 | 9 个；节日期间当地开放专属体验，到场加娱乐 |

| 物品 `ItemDef` | `data/items.ts` | 价格、携带上限、售卖地点、`use` 或 `passive` | 消耗品用掉减一；装备持有即生效，同技能只取最高一件 |

### `Effect` 的结算顺序（`applyEffect`）

付出在前、收获在后：

1. 付出：扣现金、扣声望、麻烦值上涨（× 特质 `heat`）、用掉的物品
2. 能力成长（× 特质 `gain`）。这是唯一在时间流逝前结算的收获，途中晕倒也保留
3. 时间流逝：需求按衰减率 × 特质 `decay` 下降，饿着或累着会掉健康，健康归零即晕倒
4. 没晕倒才结算的收获：得到的现金、声望、麻烦值下降、换座驾、得到的物品（钳制到携带上限）
5. 周结算（这段时间跨过了结算日才有）。排在收获之后，所以这一班的工资能用来付刚到期的房租和房贷
6. 需求增减、心情状态
7. 健康（扣减 × 特质 `hurt`），归零则在最近的医院醒来，付医药费 $100 + 现金的 10%（最多 $500）

途中晕倒（第 3 步）时：第 4 步的收获不发，第 5 步的周结算照做，然后送医，第 6–7 步不再结算；动作返回 `collapsed: true`，不发工资、不计班次、不完成心愿。住院会再过 12 小时，之后再补做一次周结算（第 7 步受伤直接晕倒时也一样）。

先流逝时间再加需求，保证“睡 8 小时”之后精力是满的。

## 4. 动作接口（`engine.ts`）

| 函数 | 作用 | 会被拒绝的情况 |
| --- | --- | --- |
| `travel` | 沿路线前往相邻地点，抵达时可能触发事件 | 有待处理事件、无路线、缺四驱、钱不够 |
| `performActivity` | 在当前地点做一件事 | 有待处理事件、地点不符、前置条件不满足 |
| `resolveEvent` | 选择事件选项并结算 | 选项不存在 |
| `gpsCheckIn` | 用真实坐标抵达地点、领取打卡奖励 | 不在任何地点半径内、没有新东西可领 |
| `shopAt` / `buyItem` | 查看 / 购买当前地点商品 | 买不到、钱不够、已带满 |
| `useItem` | 使用消耗品 | 没有、是装备 |
| `careersAt` / `applyJob` / `workShift` / `quitJob` | 找工作 / 应聘 / 上班 / 辞职 | 条件不够、不在工作地点、不在开工时段、今天上过班、太累 |
| `homesAt` / `rentHome` / `sleepHome` / `leaveHome` | 看房 / 租房 / 回家睡觉 / 退租 | 钱不够首周租金、不在住处 |
| `dealerAt` / `buyVehicle` / `sellVehicle` / `sleepInVehicle` | 车行 / 买车（旧车折抵）/ 卖车 / 车里过夜 | 不在车行、车行没开门、钱不够、车不能睡人 |
| `garageAt` / `serviceVehicle` / `breakdownChance` | 修车厂 / 保养 / 现在每趟自驾抛锚的几率 | 没车、这里没有修车厂、不营业、刚保养过、钱不够 |
| `coursesAt` / `takeCourse` | 课程 / 上课 | 不在开课时间、今天上过、钱不够、太累 |
| `certsAt` / `takeCert` / `careerPay` | 能考的证书 / 考证 / 含证书加薪的每班工资 | 已经有了、不在上课时间、钱不够、太累 |
| `experiencesAt` / `doExperience` | 体验 / 参加体验 | 不在开放时间、钱不够 |
| `furnitureAt` / `buyFurniture` / `sellFurniture` | 家具 / 添置 / 卖掉 | 没有住处、不在住处、钱不够 |
| `cookAtHome` / `relaxAtHome` | 在家做饭 / 放松 | 不在住处、缺对应家具 |
| `propertiesAt` / `buyProperty` / `sellProperty` | 在售房产 / 买房（全款或贷款）/ 卖房 | 人不在当地、钱不够、已拥有 |
| `moveIntoProperty` / `toggleRentOut` / `repayLoan` | 搬进自有房 / 出租或停租 / 提前还贷 | 没有这套房、没有贷款、金额无效 |
| `netWorth` | 净资产 | — |
| `npcsAt` / `interactNpc` | 查看在场 NPC / 聊天、送礼（可指定物品）、帮忙、专属互动 | TA 不在、今天做过了、背包空了、太累、关系不够、冷却中 |
| `npcPlan` | NPC 某天的去处和时段 | — |

所有动作返回 `{ ok, state, msg }`。

客户端不直接调用这些函数。`core/actions.ts` 定义了动作协议：`parseAction()` 把网络输入校验成 `GameAction`，`applyAction()` 分发给上表的函数，由服务端（`server/world.ts`）执行并保存。

共同事件（`core/coop.ts`、`data/coop.ts`）不走 `applyAction()`：它要同时改好几个人的存档，不是某一个客户端发来的动作。服务端凑齐人后调用 `applyCoop()`，它对每个成员做团队检定（每人的随机数来自自己的种子），再按 `applyAction()` 一样的收尾（清理心情、钳制数值、版本号加一；跨过午夜时换新心愿，共同事件本身不算任何心愿）。每个成员的 `coopDays[id]` 记下开始那天，同一种每个游戏日一次。玩家之间的交易同理不走 `applyAction()`：服务端锁住双方存档后调用 `applyTrade()`（规则在 `core/trade.ts`），双方各自版本号加一。`coopsAt()` / `coopBlocked()` 给界面和服务端共用：地点（`locs/tags/kinds`）、天气、时间不对、今天做过或有待处理事件就不能参加。

## 5. 人际关系

每个 NPC 可以做四种互动。聊天、送礼、帮忙每种每个游戏日一次：

| 互动 | 花费 | 关系 | 其他 |
| --- | --- | --- | --- |
| 聊天 | 30 分钟 | 魅力检定（检定分 + 随机 0–60 ≥ 45）成功 +7，否则 +3 | 社交 +18、娱乐 +5、魅力 +0.5 |
| 送礼 | 10 分钟 + 背包里任意一件物品 | 看 TA 的反应：最爱 +15、喜欢 +9、一般 +3、讨厌 −8 | 最爱给心情状态「礼物送到了心坎上」，讨厌给「送错了礼物」；送过一次就记住 TA 对这件东西的反应 |
| 帮忙 | 2 小时、精力 18（精力低于 25 时不能帮） | +9 | 声望 +1、力量与体能 +0.5 |
| 专属互动 | 各 NPC 不同 | +2 | 关系达到门槛才解锁，每隔几天一次，见下表 |

送礼时可以指定物品；不指定时自动挑背包里 TA 反应最好的（最爱 > 喜欢 > 一般，不会自动送讨厌的）。

关系档位：有过节 <0 · 陌生人 0 · 认识 10 · 朋友 30 · 好友 60 · 挚友 90。

**剧情**：每个 NPC 在 10 / 30 / 60 / 90 各有一段小剧情，关系第一次达到门槛时触发，各一次；一次涨分跨过好几档时全部触发。60（好友）那段带主要回报（钱、能力或物品），其余是小加成或心情状态。

**日程**：NPC 有常驻地点和作息，另外可以按星期、季节、节日去别处（如米娅周六去罗特尼斯岛、周日在弗里曼特尔集市摆摊；比尔在赛马周整天在赛马场）。日程按顺序取第一条满足今天条件的。跨午夜的作息（如戴夫的 20:00–6:00）在凌晨时沿用前一天的安排。界面会显示不在场的 NPC 今天去了哪里。

**专属互动**：

| NPC | 名称 | 解锁 | 间隔 | 效果 |
| --- | --- | --- | --- | --- |
| 米娅 | 米娅的早餐 | 朋友 30 | 每天 | 饱食 +25、精力 +10、心情状态 |
| 南希 | 留你吃晚饭 | 朋友 30 | 2 天 | 饱食 +50、社交 +20 |
| 比尔 | 老酒吧请客 | 好友 60 | 2 天 | 娱乐 +20、社交 +20 |
| 老杰克 / 琳达 / 里奥 / 萨姆 / 戴夫 / 由纪 | 跟船出海、护林员小路、私教冲浪课、带你浮潜、讲路书、珍珠鉴别课 | 好友 60 | 3 天 | 1–3 小时，对应能力 +1～1.5 和娱乐 |

旧存档迁移：没有 `seen` 的关系按当前分数把已经越过的门槛记为看过（不补发回报），旧的 `bonded` 视为看过 60 那一段。

**联动剧情**（`data/npc-duos.ts`）：

- 两位 NPC 之间有现成交集（会在集市、岛上碰面，同一行当，同一片海岸）的，配一段联动剧情，共 8 段。
- 两人好感都达到门槛（目前都是 40，待平衡），和其中任何一位互动后触发，各一次，记进 `duos`。
- 效果不花时间（钱、声望、需求、心情），触发时直接结算；途中晕倒的互动不会走到这一步。
- 「人际关系」页下方显示已触发的剧情，没触发的只显示是哪两位、要多少好感。

## 6. 职业与住房

**职业**：7 种（咖啡店、海滩救生队、旅游公司、矿业公司、货运公司、酒吧、农场），每种 3 级。

- 在符合条件的地点应聘，只能有一份工作，跳槽会清零进度。
- 每天在工作地点、开工时段内上一个班，消耗时间和需求，按等级发工资。
- 每个班做一次表现检定（职业对应的能力，难度按等级 55 / 70 / 85），表现好多发 20% 奖金。
- 本级上满 8 个班、其中 5 个表现好、且满足下一级的能力和声望要求时自动升职，声望 +3。
- 职业证书：每种职业一张，考到后这份职业每班工资 × (1 + 加薪比例)。真实地点打卡时，先在职业时薪和零工时薪里取高的，再乘证书加成，所以在哪家店都是完整的加成。考证途中晕倒不发证、不收学费（按没报名结算）。

**住房**：

| 房型 | 周租 | 心情 | 可租地点 |
| --- | --- | --- | --- |
| 合租房间 | $160 | +0 | 城市、港口、城镇、海岸、矿区 |
| 一居室公寓 | $320 | +5 | 城市、港口、城镇、海岸 |
| 海景小屋 | $650 | +10 | 有海滩的地点 |
| 房车营地 | $90 | +2 | 海岸、公园、内陆、城镇；要有能睡人的车 |
| 海景公寓 | $480 | +7 | 有海滩的地点 |

- 每周结算一次（全局结算日，每 7 天）：扣房租和车辆保险保养。租房时先付到下一个结算日的房租（按天折算）。
- 结算时付不起房租，房子被收回，家具半价折现；付不起车辆保险不收车，麻烦值 +8。
- 家具：床、厨房、浴室、娱乐、装饰五个槽位。炊具解锁在家做饭（$6），音响解锁在家放松（免费）。搬走时家具半价折现。
- 回家睡觉免费，精力回满，清洁、娱乐、健康的恢复量随舒适度提高。
- 只能有一处住处，搬家时旧住处直接退掉，已付租金不退。
- 派生属性：住处心情 = 房型舒适度 + 家具舒适度 + 凑齐的成套家具加成；每周固定开销 = 房租 + 车辆保险。
- 车辆保养：自驾累计里程，离上次保养超过 5000 公里后每趟自驾抵达按几率抛锚（刚超过时 10%，之后每多 1000 公里 +5 个百分点，超出约 8000 公里封顶 50%）。事件先后：警察盘查 → 首次到访的签名事件 → 抛锚 → 普通到达事件；被盘查的那趟不判抛锚，首次到访有签名事件时这趟的抛锚让给它。修车厂保养后「离上次保养的里程」`since` 清零，总里程 `km` 保留。考证、等保养途中晕倒：按没报名结算，不收费，住院费和途中的周结算都按手上原有的钱算。

## 7. 房产与贷款

公式集中在 `core/finance.ts`，常量在 `FINANCE`：

| 项目 | 规则 |
| --- | --- |
| 首付 | 房价的 10% |
| 每周还款 | 利息（剩余贷款 × 0.1%）+ 本金（房价 × 0.5%，约 180 周还清） |
| 卖房 | 到手 = 房价 × 95% − 剩余贷款 |
| 出租 | 每周收租金；5% 概率空置；1/12 概率维修，花费房价的 0.2%–0.6% |
| 欠款 | 当周付不起物业费 + 还款：记一次欠款，利息计入本金。连续欠款超过 2 周，按房价的 85% 强制卖出 |
| 收益上限 | 全款出租的期望年化净收益 ≤ 4%（`expectedYield()`，测试检查每套房） |
| 净资产 | 现金 + 车辆残值 + 家具折现 + Σ（房价 × 95% − 贷款） |

每周结算的顺序：房租（住自有房不交）→ 每套房依次结算租金、维修、物业费与还款、断供 → 车辆保险。

自住：`moveIntoProperty()` 把 `home` 设为 `{ type, loc, furniture, owned }`，之后和租的房子一样可以添家具、回家睡觉。出租和自住互斥。

## 8. 日历、心愿与每日奖励

**日历**（`core/time.ts`）：一年 4 季，每季 28 天，共 112 个游戏日；游戏第 1 天是第 1 年春季第 1 天。

- 事件可以写 `seasons`，只在这些季节出现（野花季只在春天，热浪只在夏天，冬季风暴只在冬天）。
- 节日每年固定日期举行。体验写了 `festival` 的只在节日期间开放，并计入「节日」收藏片区。
- 片区称号集齐时记进存档 `areas`：以后给片区加了新体验，已获得的称号不收回，补齐也不重复发 +5 声望。旧存档按现在的清单或 `AREA_HISTORY` 里的旧清单迁移；以后给片区加体验时，要把加之前的清单补进 `AREA_HISTORY`。
- `inSpan()` 判断某一天是否在节日期间，以及离下次开始还有几天。

**地点小知识**（`data/facts.ts`）：

- 每个地点 3 条真实小知识，第 1、2、3 次到访依次解锁；不存档，按 `visited` 现算（`placeFacts()`）。
- 资料由 OpenClaw 采集，Claude 按来源逐条核对后改写成 50 字以内；原始结果在 `tools/earth/openclaw/inbox/facts-2026-11-17.json`。加地点时要同时补 3 条，测试会检查。

**摄影任务链**（`data/photo-quests.ts`）：

- 8 个任务按顺序给出，每个指定地点，可选时段、天气、季节。条件都满足时在「今天」页点「拍照」，花 20 分钟，得钱和声望；拍完整条链额外声望 +5（都待平衡）。
- 天气按「地点 + 游戏日」固定，天气不对只能改天再来；测试保证每个任务一年里都有拍得到的日子。

**钓鱼**（`data/fish.ts`）：

- 要带鱼竿（随身装备，生存检定 +2）。地点有任一鱼种的出没条件（`locs`、`kinds`、`tags`）才显示钓鱼；鱼种还可以限定季节、时段、天气。风暴天钓不了。
- 钓一次 90 分钟，精力 −8、娱乐 +12、生存 +0.5。用一次存档种子抽结果：空手的权重 = max(15, 45 − 生存检定 × 0.4)，其余按鱼种权重。钓到的当场按价钱卖给鱼铺，记进 `fish`。
- 数值都待平衡；鱼种分布待 OpenClaw 核实。平衡模拟里的策略不钓鱼，所以模拟结果不变。

**野生动物图鉴**（`data/wildlife.ts`）：

- 每种动物写了出没地点（`locs`、`kinds`、`tags` 任一命中）、可选的季节和时段，以及每次抵达看见它的几率（待平衡）。
- 抵达一个地方时，在这里此刻可能出现、还没见过的动物里按顺序逐个判定，最多新记一只。判定用 `unit(种子|时钟|地点|动物)` 这个哈希，只读种子、不推进它，所以加图鉴不改变到达事件和平衡模拟的结果。
- 事件写了 `animal` 的，抽到这个事件就把动物记进图鉴（短尾矮袋鼠、鲸鲨、海豚等地标事件，以及路上的袋鼠）。
- 分海洋、陆地、飞鸟三组，一组集齐声望 +4（待平衡），记进 `dexSets`，只发一次。

**心愿**（`core/wishes.ts`）：

- 每个游戏日第一次成功行动后生成 3 条，随机数来自存档的种子；需要工作或住处的心愿只在有的时候出现。
- 判定在 `applyAction()` 里统一做：成功的动作如果满足某条心愿，娱乐 +12、声望 +0.5，并从列表里移除。
- 过了当天，没完成的直接换掉，没有惩罚。

**主线剧情**（`data/story.ts`、`core/story.ts`）：

- 按章推进，每章几个小目标；「今天」页顶上显示当前章的引子和目标清单。
- 状态目标看存档现在的样子判断（去过某地、去过几个地方、有工作、有住处、现金、某位 NPC 好感），做到的那一刻记下，之后丢了也不收回。
- 动作目标用和心愿一样的 `WishDone` 描述哪种动作算一次，可以要求做 n 次；在真实地点做对应的事也算。
- 判定在 `applyAction()` 里，紧跟心愿之后；途中晕倒不算。一章的目标全部做到就发奖励（只有钱、声望、心情，待平衡），直接入账、不花时间，然后进下一章；同一个动作不会同时算进两章。
- 不用随机数。奖励会让平衡模拟里能做完这一章的角色多一点钱，报告已重新生成。

**每日奖励**（`core/daily.ts`，由服务端按真实时间触发）：

- 以珀斯时间 0 点为界，每个现实日第一次读取存档或行动时发放。
- 金额：连续第 1 天 $30，每多一天 +$10，到 $90 封顶；每连续满 7 天当天另加 $150 和声望 +2。断一天从第 1 天重新算。
- 这是引擎里唯一用到真实时间的地方。真实日期由服务端算好传给纯函数 `claimDaily()`，引擎本身仍然不读时钟。

## 9. 存档兼容

存档格式版本仍是 `v: 1`。新增字段由 `sanitizeState()` 补默认值：旧存档里的 `home.paidUntil` 会迁移成 `nextWeek`。其余缺少的字段按空值读取：`traits` 空列表、`inventory` 空背包、`relations` 空关系、`job` 和 `home` 为空。未知 NPC 的关系丢弃。非法特质组合整体丢弃，背包里未知物品丢弃、数量钳制到上限。测试覆盖了这些情况。

## 10. 怎么加内容

- **新特质**：在 `data/traits.ts` 加一条，只用 `TraitMods` 里已有的字段。需要新类型的修正时，先在 `attributes.ts` 加一个乘数函数，再在引擎对应位置调用。
- **新物品**：在 `data/items.ts` 加一条，二选一：`use`（一个 `Effect`）或 `passive`（检定加值）。
- **新节日**：在 `data/festivals.ts` 加一条，并在 `data/experiences.ts` 加至少一个带 `festival` 的体验（测试会检查）。
- **新心愿**：在 `data/wishes.ts` 加一条，`done` 只能用已有的动作类型（含 `newplace`、`photo`）。
- **新房产**：在 `data/properties.ts` 加一条；租金和物业费要让 `expectedYield()` 落在 0–4%，否则测试不过。
- **新职业 / 新房型**：在 `data/careers.ts` / `data/housing.ts` 加一条。
- **新 NPC**：在 `data/npcs.ts` 加一条，填常驻地点和作息、日程（可选）、送礼喜好（至少一件最爱，同一件物品只能在一档）、剧情（必须有 60 那段）、专属互动（可选）。
- **新互动 / 新事件**：见 `docs/earth-game/README.md`。和天气有关的两个可选字段和一项约束：
  - `weather: ['storm']`：只在这些天气出现。普通互动在天气不符时列表里不显示、引擎也拒绝；事件在天气不符时不会被抽到（和 `seasons` 一样）。
  - `exposed: 'sea'`：要下海或出海，风暴天做不了。可以写在普通互动、事件选项、NPC 专属互动上；事件里有这种选项时必须还有别的选项（测试会检查）。
  - 天气 id 必须是 `data/weather.ts` 里有的（测试会检查）。
- 昼夜：事件可写 `periods: ['dawn' | 'day' | 'dusk' | 'night']`，按抵达时刻所在时段过滤（`core/time.ts` 的 `period()`：清晨 5–8，白天 8–17，傍晚 17–20，夜晚 20–5）；互动仍用 `hours`。真实世界有固定时间的事（弗里曼特尔午后海风、猴子米亚早上喂海豚）再加 `hours: [开, 关)` 整点，比时段更精确，用 `isOpen()` 判断。
- **新成就**：在 `data/achievements.ts` 加一条，选一个已有的指标（`metric`）和目标值；成就由存档现算，不发奖励。
- 改完运行 `npm test`，数据自洽性测试会检查 id 重复、互斥是否双向、物品是否可用等。
