## 1. 心情是怎么算的【现状】

心情不进存档，每次用到时现算（`core/attributes.ts` 的 `moodBreakdown()` / `mood()`）：

```
心情 = round(需求平均 × 0.75 + 需求最低 × 0.25)   ← 五项需求：饱食、精力、清洁、娱乐、社交
     + 特质 mood（「没心没肺」+8）
     + 住处舒适度（房型 + 家具 + 成套家具）
     + 生效中心情状态（moodlets）的加减之和
     钳制到 0–100
```

| 心情档（`moodTier`） | 范围 | 检定加值 |
| --- | --- | --- |
| 低落 | < 25 | −10 |
| 一般 | 25–49 | 0 |
| 愉快 | 50–84 | +5 |
| 亢奋 | ≥ 85 | +10 |

心情还进状态系数 `0.7 + 0.6 × 心情 / 100`（`formulas.ts` 的 `efficiency()`），影响训练收益和工作表现；进魅力外观（`(心情 − 50) / 10`）。

## 2. 心情的来源和衰减

### 2.1 来源【现状】

| 来源 | 怎么来 | 怎么走 |
| --- | --- | --- |
| 需求 | 吃、睡、洗澡、玩、社交把需求补上去 | 每分钟按 `DECAY` × 特质倍率往下掉（`engine.ts` 的 `advance()`） |
| 特质 | 创建角色时选定 | 永久 |
| 住处 | 租房、买家具 | 退租、被收房、卖家具 |
| 心情状态（moodlets） | 活动、事件效果里写 `moodlet`；引擎在升职、晕倒、被收房、交朋友等时刻发放 | 到 `until` 一下子失效；同种再得只刷新时长，不叠加；存档最多 12 条 |

### 2.2 衰减【现状】

- 心情本身没有「衰减」这个量：需求往下掉、心情状态到点失效，心情跟着变。
- 心情状态是**阶梯式**：到期前满额生效，到期那一刻直接消失。

### 2.3 衰减的提议【提议】

- **渐弱**：给 `MoodletDef` 加可选的 `fade: true`，最后 1/3 时长里加减值线性减到 0。只对新状态开，旧状态不变。没做的原因：会改变所有现有心情状态的手感和模拟结果，应先由 Codex 看本批心事的影响再定。
- **适应**：同一种正面状态在短时间里反复得到时效果打折（例如 24 小时内第二次「吃得很满足」只给一半）。需要在存档里记次数，没做。

## 3. 心情状态（moodlets）体系

### 3.1 数据结构【现状 + 新·已实现】

`data/moodlets.ts` 的 `MoodletDef`：

| 字段 | 含义 | |
| --- | --- | --- |
| `id` `name` `icon` | 标识、显示名、图标 | 现状 |
| `value` | 心情加减 | 现状 |
| `hours` | 持续的游戏小时 | 现状 |
| `gain` | 生效期间能力成长倍率（「专注」×1.25） | 现状 |
| `relieves` | 缓解的心事 id 列表 | **新·已实现** |

`relieves` 的两个作用（`engine.ts` 的 `addMoodlet()` 和 `core/mind.ts` 的 `settleMind()`）：

1. 获得这个状态时，顺带清掉列出的心事；
2. 它还生效时，每日结算不再触发那种心事。

## 4. 心事：孤独、思乡、压力【新·已实现，待平衡】

规则在 `core/mind.ts`，数值在 `data/mind.ts`。

### 4.1 什么时候结算

每个**游戏日结算一次**：动作结束时发现跨过了午夜（`applyAction()` 和 `applyCoop()` 的收尾里调用 `settleMind()`）。存档新字段 `mind.day` 记最近结算到哪一天，同一天不会重复结算。一次动作跨好几天（住院、长途）也只结算一次。

不用随机数：结果完全由当时的存档决定，不消耗 `seed`，不会改变别的检定结果。

每种心事算一个分数，到门槛就给对应的负面状态（24 小时），并在日志里写一句话。当时有能缓解它的状态（§3.3）就不触发。

### 4.2 孤独

```
分数 = clamp((40 − 社交) / 40, 0, 1) × 特质倍率 − 0.15 × 朋友数（最多算 2 位）
门槛 0.25（没有朋友、没有特质时相当于社交 < 30）
```

朋友 = 好感 ≥ 30（「朋友」档）的 NPC。特质：独行侠 ×0.5。

### 4.3 思乡

```
分数 = 出身权重 × 到达天数曲线 × 特质倍率 − 0.15 × 朋友数（最多 2 位）
门槛 0.5
```

| 出身 | 权重 |
| --- | --- |
| 留学生 | 0.8 |
| 背包客 | 0.5 |
| 矿区轮班工 | 0.4 |
| 冲浪手 | 0.3 |

| 到达后第几天 | 曲线 |
| --- | --- |
| 0–6 | 0.3（新鲜期） |
| 7–41 | 1.0 |
| 42–89 | 0.75 |
| 90 起 | 0.4 |

曲线形状参考「文化适应」常见的描述（新鲜 → 低谷 → 慢慢适应），具体天数是游戏取的整数，不是研究结论。特质：没心没肺 ×0.8。

结果：留学生第 7–41 天，即使有两位朋友（0.8 − 0.3 = 0.5）也会想家，需要隔天给家里打视频或找人聊聊；第 42–89 天有一位朋友就不会。冲浪手任何时候都不到门槛。

### 4.4 压力

```
分数 = 满足的压力来源权重之和 × 特质倍率
门槛 0.4
```

| 来源 | 条件 | 权重 |
| --- | --- | --- |
| 房租 | 现金 < 每周固定开销（房租 + 车 + 房产） | 0.4 |
| 没钱 | 现金 < $50 | 0.3 |
| 身体不好 | 健康 < 40 | 0.3 |
| 麻烦 | 麻烦值 ≥ 60（会被盘查） | 0.3 |
| 累坏了 | 精力 < 20 | 0.2 |

单独一条「付不起下周开销」就会触发；其他来源要两条叠加。特质：没心没肺 ×0.6。

> 和 `claude/earth-activity-attrs`（已在 main）的关系：那个分支在 `core/vitals.ts` 加了一个隐藏的 `stress()`（娱乐、社交低于 40 时让饱食掉得快），是身体系数，不进心情。合并时把「我 · 派生属性」里那一行改叫「身心紧绷」，和这里心事的「压力」分开。

## 5. 低落时的表现【现状 + 新·已实现】

- 【现状】心情 < 25 是「低落」档：所有检定 −10，状态系数降到 0.85 以下。
- 【新·已实现】每日结算时心情 < 25 就记一天低落（`mind.low`，跨多天按天数累计，上限 30），心情回到 25 以上就清零。
- 【新·已实现】连续 2 天及以上（`lowSpell()`）时，心情页显示「已经连续 N 天心情低落」和恢复建议，自动展开现实求助渠道（§7）。
- **不额外惩罚**：低谷期不再叠加任何数值惩罚。低落档本身的检定 −10 已经够了，再加只会让玩家更难走出来。

## 6. 恢复方式【新·已实现】

| 方式 | 游戏里怎么做 | 缓解 |
| --- | --- | --- |
| 社交 | 和 NPC 聊天、送礼、帮忙；共同事件；交到朋友后孤独、思乡分数都会降 | 孤单（通过 `new-friend`、`warm-moment`、`gift-loved` 等） |
| 运动 | 健身、游泳、真实地点训练 | 压力（`pumped`） |
| 爱好 | 娱乐类活动、体验 | 孤单、压力（`good-time`、`experience`） |
| 睡眠 | 回家睡、露营 | 压力（`great-sleep`、`camp-calm`） |
| 寻求帮助 | 心情页「找人聊聊」：30 分钟，不花钱 | 三种都缓解（`talked-it-out`） |
| 联系家人 | 心情页「给家里打个视频」：40 分钟，不花钱 | 想家（`called-home`） |

两个新动作是 `GameAction` `{ t: 'mind', op: 'call' | 'talk' }`，在哪里都能做，有待处理事件时不行，走 `applyAction()` 权威结算。它们只给心情状态，不加社交需求，所以不能拿来白刷社交。
