# 玩家之间的交易与拍卖（`claude/earth-player-trade`）

> 状态标记：【现状】= 本分支开工前 `main`（4f9c9e5）已有的；【已落地·第一版】= 本分支实现了并有测试；【提议】= 只写了设计，没实现。
> 所有新数值都**待平衡**，Claude 不下平衡结论，交给 Codex 模拟后再定。

## 1. 目标和红线

- 玩家之间能**面交**（同一地点、当面）和**异步挂单**（不用同时在线），交易物品和游戏币。
- 一个**拍卖行**。
- **手续费**作为货币回收手段。
- **防刷、防作弊**：交易原子化（不能复制物品）、新号限制、每日上限、异常价格检测、服务端权威记账。
- **红线**：
  1. 不能用真钱交易游戏币（RMT）。游戏里没有任何「直接转钱」的入口，钱只作为某件物品的价款流动，而且价款有上下限（第 4 节）。界面上明确写禁止 RMT，并提示常见骗局。
  2. 防诈骗：任何交易都由服务端一次结算，不存在「我先给钱你再给货」；界面提示不要相信场外转账、代充、索要同步码。

### 1.1 和 `features.md` 第 3 条「不能直接转钱」的关系

`features.md` 定的是「同一地点的玩家能送礼摆摊，但不能直接转钱」。本分支**保留这条**：新增的所有入口都要求「钱的另一边一定有物品」，并且钱数限定在那些物品商店价的 0.5–2 倍。所以「交易游戏币」在这里的意思是「用游戏币买卖物品」，不是「把钱转给别人」。纯转钱（含「给你一瓶水外加 $500」这类变相转钱）一律拒绝，见 `swapShapeBlocked()`。

## 3. 设计

### 3.1 三种交易方式

| 方式 | 同时在线 | 托管 | 手续费（待平衡） | 状态 |
| --- | --- | --- | --- | --- |
| 送礼、二手摊 | 要（同一地点） | 不托管，成交时锁双方存档 | 无 | 【现状】不改 |
| **面交换物**（🤝） | 要（同一地点） | 不托管，成交时锁双方存档 | 带钱时收钱一方付 5%（至少 $1） | 【已落地·第一版】 |
| **交易所 · 一口价寄卖** | 不要 | 物品挂出即托管 | 挂单费 2%（至少 $1，不退）+ 成交佣金 8%（至少 $1，从卖家到手里扣） | 【已落地·第一版】 |
| **交易所 · 拍卖** | 不要 | 物品挂出即托管，出价的钱即托管 | 同上 | 【已落地·第一版】 |

交易所是全服的（不分地点），面交和二手摊是同一地点的。

### 3.2 托管和邮箱：为什么不会复制物品

核心规则（`core/exchange.ts` 开头注释）：

1. **物品挂出就离开卖家背包**，存在拍品记录 `lot:<id>` 里；同一次 put 写卖家存档和拍品。所以同一件东西不可能既在背包里又在交易所里。
2. **出价的钱当场从出价人现金里扣走**，记在拍品的 `bid` 上；被超过时，上一位的钱进他的邮箱 `mail:<id>`（和新出价同一次 put）。
3. **不碰对方存档**：一口价买下时，买家的东西直接进背包，卖家的货款进卖家的**邮箱**；拍卖到期结算只写邮箱。卖家/买家下次打开交易所时自己领（`claim`）。这样每次写入只需要锁住发起请求的那一个存档。
4. **一次 put 全写或全不写**（Durable Object 单次多键 put 的保证）：本人存档 + 拍品 + 对方邮箱 + 额度 + 账本 + 回收的手续费 + 请求编号记录，在同一个 put 里。写失败时内存里的拍品也不改（写成功才改内存）。
5. 拍品删除用**作废标记**（`{ gone: true }`）写在同一个 put 里，再尽力删除键；读取时跳过作废的。

守恒不变量（测试里每一步都检查）：

- 全服某件物品的数量 = 所有背包 + 所有邮箱 + 所有在挂的拍品。
- 全服现金 = 所有存档现金 + 所有邮箱现金 + 所有拍品上的托管出价 + 累计回收的手续费（`sink:<日>`）。

### 3.3 并发

| 场景 | 怎么保证 |
| --- | --- |
| 两人同时买同一件 | 交易所的所有改动在 `marketChain` 里排队（每个请求还持有本人的存档锁）。第二个请求进队时拍品已经作废，返回 404 |
| 卖家撤回和买家买下同时到 | 同上，只成一个 |
| 同一人同时发两笔花钱的请求 | 存档锁让两笔串行；第二笔带的版本号已经落后，409 不执行 |
| 拍卖到期结算和出价同时到 | 结算在每个交易所请求开头、在队列里做；到期的拍品先结算掉，之后的出价看到「已经结束了」 |
| 面交同一单被同时收下两次 | 沿用现状的 `taking` 冻结 + 双方存档锁；第二次 404 或 409 |
| 邮箱被结算写入和本人领取同时改 | 两者都在 `marketChain` 里 |

不会死锁：`marketChain` 里的任务从不等存档锁；存档锁的持有者才会进 `marketChain`。

### 3.4 重放和断网重交

- 交易所的每个改动请求必须带 `nonce`（客户端生成，8–32 位小写字母数字；页面用现成的 `newOp()`）。服务端在 `mops:<id>` 记住最近 16 个编号和结果，和存档同一次写入。
- 同一编号再来：不执行，返回第一次的结果（`dup: true`），**即使带着新的版本号**（断网时第一次其实成功了，客户端同步后重交的情况）。
- 被规则拒绝的请求也记下编号：重交得到同样的拒绝，不会因为条件变了而「后来又成功了」。
- 没有编号的改动请求直接拒绝。版本号不对返回 409，和 `act` 一样。

### 3.5 服务端权威记账

服务端存储里的键（都只在 `'@SAVES'` 实例里，不发给客户端）：

| 键 | 内容 |
| --- | --- |
| `lot:<12位hex>` | 拍品（含卖家、最高出价人的真实 id；发给客户端前经过 `lotView()`，只给「是不是我的」「我是不是最高价」） |
| `mail:<真实id>` | 邮箱（货款、退款、拍到的东西、撤回时背包放不下的东西），最多 30 封；超过时只合并现金，物品宁可超上限也不丢 |
| `xq:<id哈希>` | 今天的交易额度：笔数、付出金额、和每个对手的笔数、计过笔数的拍品 |
| `since:<真实id>` | 建号的现实日（新建角色时和存档一起写；老存档没有这条，按老号处理）。合并 main 时从 `born:` 改名：`born:` 是统计的注册日（按 id 哈希，玩家关了统计不记） |
| `tx:<现实日>:<12位hex>` | 账本：每笔成交一条，只记双方 id 哈希、物品、价款、手续费、可疑标记 |
| `sink:<现实日>` | 当天回收的手续费合计 |
| `mops:<真实id>` | 最近处理过的交易所请求编号 |

注销账号（`deleteAccount`）：他挂的拍品撤下，已经有人出价的全额退回出价人邮箱；他是最高出价的拍品清掉出价（托管的钱随账号删除）；`mail`、`mops`、`since`、`xq` 一起删。账本只有哈希，保留。

### 3.6 接口

```
market { op: 'list' }                                        在售/在拍（最多 60 件，按结束时间）、我挂的、我的邮箱、今天的额度、新号提示
market { op: 'sell', kind: 'fixed'|'auction', item, price, hours, rev, nonce }
market { op: 'buy', lot, rev, nonce }
market { op: 'bid', lot, amount, rev, nonce }
market { op: 'cancel', lot, rev, nonce }                     拍卖有人出价后不能撤
market { op: 'claim', rev, nonce }                           领邮箱：钱全领，东西按背包空位领
trade  { op: 'swap', to, toName, give: { items: [{item,n}], cash }, want: { items, cash } }   发起面交（to 是在线状态里的 id 哈希）
trade  { op: 'accept' | 'decline' | 'cancel', offer, rev }  沿用现状
```

## 4. 数值（全部待平衡）

| 名字（`EXCHANGE.*`） | 值 | 作用 |
| --- | --- | --- |
| `minRealDays` | 3 | 建号满 3 个现实日才能用交易所、带钱的面交 |
| `minGameDays` | 5 | 游戏里至少过了 5 天（挡建号后立刻睡觉刷天数之外的情况；主要靠上一条） |
| `dailyDeals` | 8 | 每人每现实日最多 8 笔（挂单、一口价买入、对一件拍品第一次出价各算一笔；同一件拍品加价不重复算） |
| `dailyVolume` | 1500 | 每人每现实日最多付出 $1500（买入、出价、面交付款；被超过退回的出价不退额度） |
| `pairDaily` | 2 | 同一对玩家每现实日最多 2 笔 |
| `maxLots` | 4 | 每人同时挂着最多 4 件 |
| `fixedHours` / `auctionHours` | 48 / 6 或 24 | 寄卖有效期；拍卖时长 |
| `listFeeRate` | 2% | 挂单费，至少 $1，不退 |
| `commission` | 8% | 成交佣金，至少 $1，从卖家到手里扣 |
| `swapFee` | 5% | 面交带钱时收钱一方付，至少 $1 |
| `priceMin` / `priceMax` | 0.5 / 2 | 价格硬区间（商店价倍数），超出直接拒绝 |
| `flagLow` / `flagHigh` | 0.6 / 1.5 | 软区间：成交价超出时在账本记 `price-low` / `price-high` |
| `bidStep` | 5% | 加价至少 5%、至少 $1 |
| `snipeMin` / `maxExtends` | 5 分钟 / 6 次 | 结束前 5 分钟内出价顺延 5 分钟，最多顺延 6 次 |
| `mailMax` | 30 | 邮箱上限 |

手续费都**向上取整**（对回收有利），但不超过价款本身。

## 5. 防刷、防作弊、防 RMT

| 风险 | 做法 | 状态 |
| --- | --- | --- |
| 复制物品 | 托管 + 一次 put + 队列（3.2、3.3）；测试里并发 6 轮检查物品总数 | 【已落地·第一版】 |
| 重放请求（断网重交、抓包重发） | 请求编号 + 版本号（3.4） | 【已落地·第一版】 |
| 小号把钱倒给大号（S-15） | 不能纯转钱；价款限定商店价 0.5–2 倍；新号 3 天不能带钱交易；同一对玩家每天 2 笔；每天付出 $1500；手续费 | 【已落地·第一版】 |
| 估算：一对小号/大号每天最多倒多少钱 | 唯一的路是「大号挂高价，小号买」。每笔最多比商店价多付 1 倍；同一对每天 2 笔；最贵的可交易物品是冲浪板（商店价 $350）。所以每天最多多付 2 × $350 = $700，大号扣 8% 佣金后实得 $1288 − 商店价值 $700 的板 ≈ 净多 $588；还受小号每天付出 $1500、新号 3 天的限制。多个小号可以叠加（每个小号各算一对）。是否够紧要 Codex 结合建号限流（每来源每小时 20 个）模拟 | 【提议】数值待平衡 |
| 异常价格 | 硬区间直接拒绝；软区间写进账本 `flags`（`price-low`/`price-high`）供人工复核 | 【已落地·第一版】 |
| 自买自卖刷周目标 / 榜单 | 交易所成交和面交都**不计入**全服周目标（只有现状的送礼、二手摊按 `trade` 目标计）；钱和东西只在存档、托管、邮箱之间流转，不凭空增加 | 【已落地·第一版】 |
| 最后一秒抢拍 | 结束前 5 分钟出价顺延 | 【已落地·第一版】 |
| RMT（真钱买游戏币） | 游戏内无纯转钱入口；价款上限 2 倍商店价，最多每天 $1500；界面写明禁止 RMT（`ui/market.ts` 的 `SAFETY_TIP`）；账本可查 | 【已落地·第一版】 |
| RMT 处罚 | 发现后「清空交易所里的东西并停用交易」（界面这么写了），但还没有管理员工具 | 【提议】见第 7 节 |
| 诈骗（先付钱不给货） | 所有交易一次结算，没有「一方先给」的步骤；面交卡片显示双方内容并提示当面核对 | 【已落地·第一版】 |
| 诈骗（骗同步码） | 界面提示「任何人都不会找你要同步码」 | 【已落地·第一版】 |
| 挂单刷存储 | 每人 4 件、全服 600 件、邮箱 30 封、挂单费 | 【已落地·第一版】 |

## 9. 数值模拟

`npm run earth:sim -- --days=180 --runs=100`：模拟器是单人机器人（`tools/earth/balance/sim.ts`），不经过服务端，也不做玩家之间的交易，所以本分支**不改变模拟结果**（和 `main` 4f9c9e5 逐字节对比，见第 9.1 节）。交易所对经济的影响（手续费回收量、倒钱上限）需要另写多人模拟，列入 Codex 任务。

### 9.1 对比结果

2026-11-20 在本机分别跑了两次：本分支（`claude/earth-player-trade`）和 `main` 4f9c9e5（`git archive` 导出到临时目录），命令都是 `npm run earth:sim -- --days=180 --runs=100`。两份输出各 81 行，`diff` **完全相同**。所有策略的第 7/30/60 天现金、日均净收入、期末净资产、买房天数、晕倒次数、升职天数、破产天数占比都没有变化（例如咖啡店上班族日均净收入 $71、期末净资产 $28,067；什么都不干的对照组破产天数 91%）。

原因：模拟器只调用 `applyAction()` 走单人机器人策略；交易所和面交只在服务端 `handleMarket()` / `handleTrade()` 里，单人模拟碰不到。本分支也没有改工资、物价、衰减等已有数值。所以**这次模拟不能说明交易所对经济的影响**。要评估的话需要一个多人模拟（几类玩家按策略挂单、出价、倒钱），看：每日手续费回收量（`sink`）占总投放的比例、价格带和额度下小号倒钱的上限、拍卖成交价分布。列入给 Codex 的后续任务。
