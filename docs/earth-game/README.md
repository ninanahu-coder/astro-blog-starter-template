# 地球人生 / Terra Life —— 游戏框架说明

在真实地图上生活的在线人生模拟。第一阶段以**西澳大利亚**为试点，第 9 批（2026-11-18）加入**南澳大利亚**：
生活需求（吃、睡、清洁、娱乐、社交）+ 开放世界式能力成长（体能、力量、驾驶、游泳、魅力、生存、街头）+
**到达地点触发事件** + 同地点玩家互动 + **手机多端云同步**。

- 试玩入口：`/earth`（手机优先）
- 本地运行：`npm run preview`（需要 Durable Object，所以用 wrangler 而不是 `astro dev`）
- 测试：`npm test`

> 这是原创设定。生活模拟与开放世界属性成长只是玩法类型上的参考，不使用任何现有游戏的名称、角色、美术或关卡。

## 1. 四个工具的分工

| 角色 | 工具 | 负责什么 | 产物落在哪里 | 不做什么 |
| --- | --- | --- | --- | --- |
| 逻辑 + 前端 | **Claude Code** | 类型、规则引擎、Durable Object、`/earth` 页面、测试；按 Codex 的分析报告实施调参 | `src/game/`、`src/pages/earth.astro`、`tests/earth/` | 不手写大批量数据、不生成图片、不自己下平衡分析结论 |
| 数据采集 | **OpenClaw** | 按任务书采集 POI、地点和节日的真实资料（OSM / Wikidata） | `tools/earth/openclaw/inbox/*.json` → `src/game/data/wa.pois.json` | 不改代码；只交 JSON |
| 检查与分析 | **Codex** | 审 PR（规则正确性、安全、数据许可）；跑数值模拟并写平衡分析；分析 OpenClaw 的数据。任务书 [codex-tasks.md](codex-tasks.md) | PR 审查评论；`docs/earth-game/balance.md` 的分析小节 | 不写逻辑和前端；调参只提建议 |
| CGI 素材 | **GPT image 2**（备选远程 ComfyUI） | 35 个地点主视觉、84 个事件插图、17 个 NPC 头像 | `public/earth/cgi/*.webp` + `manifest.json` | 不参与逻辑；缺图时前端自动用占位图 |

Claude Code ──▶ src/game/** + earth.astro + tests ─────────────┤
                                    Codex 跑 earth:sim ──▶ balance.md 分析 ──▶ Claude Code 按报告调参
                                                               │
src/game/data/* ──▶ prompts.mjs ──▶ 远程 ComfyUI ──▶ cgi/*.png ─┘
```

## 2. 代码结构

```

  core/engine.ts      规则引擎：travel / performActivity / resolveEvent / gpsCheckIn（纯函数、确定性）
  core/geo.ts         距离、地图投影、真实坐标 → 游戏地点
  core/formulas.ts    派生属性（体质、吸引力、状态系数……）与真实地点动作的公式
  core/venues.ts      真实地点：附近列表、定位检查、吃饭/训练/打卡上班等结算
  core/board.ts       旧版净资产排行榜的记录格式（rank:<h> 仍兼容它）
  core/leaderboard.ts 排行榜与赛季：五个维度、同意上榜、异常值复核、赛季结算（见 leaderboard.md）
  data/leaderboard.ts 排行榜与赛季的数值（赛季长度、复核线、比赛积分、奖励档位，均待平衡）
  core/achievements.ts 成就：由存档现算的里程碑（不进存档、不发奖励）
  core/weather.ts     天气：由地点和游戏日确定（人人一样），风暴天取消海上的活动
  core/sky.ts         天象：气温、日出日落（含南澳夏令时）、潮汐、山火季、紫外线，只做显示
  core/disasters.ts   自然灾害（第 43 批）：山火、洪水封路、气旋、热浪、停电的预警（AWS 三级），封路、户外关闭、停工、停电做饭；保险理赔接口（见 disasters.md）
  data/achievements.ts 成就表（选指标和目标值即可加一条）
  data/areas-base.ts  区域注册表：AREAS、跨区域路线、mergeAreas 合成世界

  data/changelog.ts   游戏内更新日志（「我 · 更新」页）
  data/wa.pois.json   打卡点（OpenClaw 写入）
  data/venues.ts      真实地点的类型、动作和定位规则

  data/activities.ts  地点互动表（数值调参都在这里）
  data/events.ts      到达事件表（加事件只加数据，不写逻辑）

设计原则：

1. **规则是纯函数**。`engine.ts` 不碰 DOM、不碰网络，随机数种子存在存档里。同一份代码前端跑、测试跑，服务端也用它做权威结算（已完成）。
2. **内容是数据**。新地点、新互动、新事件都是往数组里加一条；`Effect` 一种结构描述所有数值变化。
3. **不可信输入一律过 `sanitizeState()`**。本地存档、云端存档、别的设备传来的状态都先校验再用。

## 3. 玩法设定

### 初始属性

| 类别 | 字段 | 说明 |
| --- | --- | --- |
| 生活需求（0–100，随时间下降） | 饱食、精力、清洁、娱乐、社交 | 饱食或精力归零会持续掉健康 |
| 能力（0–100，越用越高；目前不会退步） | 体能、力量、驾驶、游泳、魅力、生存、街头 | 影响事件检定、行车速度、可做的互动 |
| 状态 | 现金、健康、声望、麻烦值、座驾 | 麻烦值 ≥ 60 会被盘查；健康归零会在最近的医院醒来，付医药费 $100 + 现金的 10%（最多 $500）；会生病和受伤，可看 GP、药房、急诊，按 Medicare / OSHC / 自费付钱（[health.md](health.md)，数值待平衡） |

四种出身（背包客 / 矿区轮班工 / 留学生 / 冲浪手）决定起始现金、座驾和能力侧重。各出身的定位、设定理由、新出身候选和特质搭配见 [initial-stats.md](initial-stats.md)（数值待平衡）。

### 到达事件

- 每次抵达一个地点都会掷一次事件；**首次到访**且当地有“签名事件”（如罗特尼斯岛的短尾矮袋鼠、埃克斯茅斯的鲸鲨）时必定触发。
- 事件按 `locs / tags / kinds / arrivedBy` 匹配地点和到达方式，选项可带能力检定（`能力值 + 0~60 随机 ≥ 难度`）。
- **真实定位打卡**：手机本人到了某个地点的半径内，可以直接“抵达”并触发事件；400 米内的 POI 首次打卡加声望。

### 出行

公路（无车坐巴士、有车自驾并涨驾驶）、越野土路（需四驱）、渡轮、航班。时间流逝会带动需求衰减，所以长途前要吃饱睡好。

第 32 批加了市内公交（Transperth、Adelaide Metro）、区域火车（Transwa）、步行，渡轮改按真实票价；设计、票价出处和提议见 [transport-design.md](transport-design.md)。

### 天气、相册与成就

- **天气**（`core/weather.ts`）：每个地点每个游戏日一种，由「地点 + 日期」哈希确定，所有玩家看到的一样，可以预报（地点卡显示明天的天气）。冬季风暴最多。风暴天下海、浮潜、冲浪、出海都做不了——普通互动、事件选项、NPC 专属互动里标了 `exposed: 'sea'` 的都受影响；海滩上会多出「看风暴」。自然灾害（第 43 批）按天气和火险推出预警，会封路、关户外活动、停工，设计见 [disasters.md](disasters.md)。下雨天城镇、港口、海岸、公园和海岛有专门的小事件；不下雨的夜里内陆和公园可以「看星星」。
- **昼夜**：按游戏时刻分清晨（5–8）、白天、傍晚（17–20）、夜晚四个时段。顶栏底色、地图夜色和星星跟着当地真实的日出日落走（第 37 轮，见「天象」），不跟这四个时段；两者不一致时顶栏时段名后面补一句实际天色，例如冬天 18:30「傍晚（天已经黑了）」。有的事件只在某个时段抵达时出现（清晨港口的渔船、傍晚海滩的日落、天黑后公路上的袋鼠、珀斯的河边夜景）；海滩清晨可以「看日出」。
- **天气相册**（存档字段 `photos`）：抵达一个地点时按当天天气收一张照片（地点 × 天气，35 个地点共 175 张），只是收藏，不发奖励。
- **成就**（`core/achievements.ts`）：由存档现算的里程碑（19 个），不进存档、不发奖励。

## 4. 手机界面

| 今天 | 第 15 批按设计稿「主界面 · 五栏导航定稿」重排：场景顶栏左上人物名牌（头像外圈是升级进度环，点了去成长页）、右上现金和天气、地点名牌下写时间；页面依次是 6 个需求环、「下一步」、今天的心愿（三列小卡）、四个快捷动作（从最缺的需求起挑这里能补它最多的事，只是入口，完整列表照旧），再往下是 6 条需求、「下一步」建议（按最缺的需求、周结算、上班、心愿排优先级）、昨天回顾（跨日后显示上一天的变化）、新手指南（前三天分步解开，见 `data/guide.ts`）、周结算预警、当前地点的互动、NPC、工作、住处、商店等 |

| 社交 | 认识的人今天在哪、同地点玩家与本地频道（含快捷短语）、净资产排行 |
| 我 | 概况（档案、心情、能力、派生属性）、资产（工作住处、背包）、关系、日志（按天分组）、更新（游戏内更新日志，按批次列出玩家能感受到的变化；没看过的批次在标签上标「新」，已读记在本机 `earth.news.v1`，见 `data/changelog.ts`、`ui/news.ts`；第 48 轮）、设置（字号三档、动画跟随系统/减少/正常、音效（Web Audio 现场合成，默认关，见 `src/game/ui/sound.ts`）、真实地图开关（默认开）、新手指南/昨天回顾/成就提示开关，只存在本机，见 `src/game/ui/prefs.ts`；玩法说明、同步码；同步页可显示二维码，里面是 `/earth/#sync=同步码` 链接，另一台手机用相机扫了直接打开恢复，同步码在 `#` 后面不发给服务器、读完马上从地址栏抹掉；本机已有别的角色时先问再换；启动时先处理完扫码，才给原角色连线、同步、补交排队；服务器发来的存档先清洗、核对是这个角色的才写进本机，见 `src/game/ui/transfer.ts`） |

- 深色模式跟随系统；颜色都是变量，深浅两套一一对应（`tests/earth/contrast.test.ts` 检查对比度）。
- **可添加到主屏幕**：`public/earth/manifest.webmanifest` 和离线外壳 `public/earth/sw.js`（作用域 `/earth/`）。外壳安装时从首页 HTML 解析并预缓存构建文件，联网打开首页时更新、清理旧文件；`/api/` 从不缓存。断网时可以查看，联网后才能行动。
- **多区域（第 41 轮起）**：游戏世界由几个区域（西澳、南澳……）拼成，注册表在 `src/game/data/areas-base.ts`（`AREAS`、跨区域路线 `CROSS_ROUTES`）。规则层（引擎、服务器、存档清洗）用合并后的世界 `WORLD`（`mergeAreas`：地点、路线、打卡点、真实地点拼在一起；地点 id 必须全世界唯一，跨区域路线两端必须在不同区域，违反就启动报错）；存档里的 `region` 由所在地点决定。画面层按所在地点的区域（`areaOf`）画：手绘地图、真实底图、轮廓、在线频道都按区域分，跨区域后底图重建、在线频道重连。

## 5. 联机与手机同步

| 接口 | 作用 |
| --- | --- |
| `GET /api/earth/ws?region=wa&id&name&avatar&loc`（WebSocket） | 区域在线状态：`hello / join / leave / move / chat / emote / coop`。聊天、表情和共同事件提醒只发给同一地点的玩家 |
| `POST /api/earth/save` `{action:'create'|'get'|'act'|'board'|'coop', id, key, …}` | **服务端权威结算**。`create` 由服务器创建角色；`act` 发送一个动作（`{ rev, act: GameAction, op? }`），服务器调用规则引擎结算、保存并返回新存档；客户端版本落后时返回 409 和最新存档；`op` 是动作编号，同一编号已结算过时不再执行，返回当时的结果和最新存档（`dup: true`）。服务端只存 key 的哈希，不接受客户端上传存档 |

- **同步码** = `id.key`，在“同步”页复制，到另一台设备粘贴即可恢复。等同密码。
- 每个动作都发给服务器结算，成功后 `rev + 1`。同一存档的请求在服务器上排队执行。
- 两台设备同时玩：后发的一方因版本落后被拒绝，并自动载入最新进度。
- 服务器返回的存档隐去了随机数种子，客户端无法预知检定结果。
- 本机 `localStorage` 只缓存最近一次的服务器存档用于显示；联网时一律以服务器为准，改缓存没有作用。
- 断网时可以查看，但不能行动；创建角色也需要联网。
- `board` 返回排行榜前 20 名和自己的名次（只读），可选 `dim`（身家/打卡/图鉴/声望/比赛）、`scope`（本赛季/总榜）、`board`（全服/地区/好友）；不带参数等于旧版的全服身家总榜。**只有本人同意（`boardpref`）的玩家出现在榜上**，可匿名。改版前建的旧角色读档时 `get` 带 `lbAsk: true`，页面弹一次问要不要上榜。榜单记录在每次存档落盘时由服务端从权威存档算出，涨得异常的挂起复核。详见 [leaderboard.md](leaderboard.md)。
- **共同事件**（`coop`，`op: list / open / join / leave / start`）：同一地点的玩家组队做一件事（海滩清洁、街头合奏、帮人推车、救搁浅的海豚、码头钓鱼比赛、峡谷互助徒步、社区烧烤、帮人搬家）。要凑钱的（社区烧烤每人 $8）钱不够不能参加。每人选一个分工，用自己那项能力；团队分 = 每人（检定分 + 随机 0–60）的平均值 + 每多一人 +6，达到难度就成功，所有人拿同一个结果。
  - 每种共同事件每人每 5 个游戏日只能做一次（`COOP_COOLDOWN_DAYS`，存档字段 `coopDays` 记最近一次的游戏日，成败、晕倒都算做过），防止反复刷声望；成功的声望都是 0.5（平衡分析第九轮：原来每天一次、声望 1–6，同一地点几种叠着做，收入和升职都太快）。
  - 队伍（大厅）只存在存档实例的内存里：5 分钟没开始自动解散，结果保留 3 分钟给队友拉取（这两个时限按服务器真实时间算；正在结算的队伍不会被过期清掉）。对外只给名字、头像、分工和地点，不发存档 id。自己所在的队伍走开以后仍然列出（标「已走开」），可以退出。
  - 只有发起人能开始。点「开始」的请求一到，成员名单就冻结（之后的加入、退出返回 409），服务端在锁住这些成员的存档后重新检查每个人（还在这个地点、没有待处理事件、冷却期内没做过、时间天气合适），至少 2 人才结算（不结算时先解冻再返回，界面不会停在「正在开始」），用 `applyCoop()` 算出每个人的结果，**在同一次存储写入里**写进所有人的存档（版本号各加一；写入失败谁都没拿到，队伍解冻可重试）。每个队友的校验和落盘时间用自己存档的时间（防时钟回拨的规则和单人动作一致）。
  - 队伍有变化时客户端在在线频道发一个不带内容的 `coop` 提醒（服务端对同一连接 1 秒内只转发一次），同地点的人收到后合并成最多每 3 秒拉一次列表；队友那边看到结果后自动载入最新进度。队友结算后自己下一次操作会收到 409，提示「进度刚刚更新过（另一台设备，或队友发起的共同事件）」并载入最新进度。

- **送礼与二手摊**（`trade`，`op: list / gift / sale / cancel / decline / accept`）：在场的人旁边点 🎁，把背包里的一件东西送给他；「摆个二手摊」把东西挂在当前地点按价出售（每件给最低价、商店价、最高价三个价可选），同一地点的人都能买。
  - 挂单只在存档实例的内存里，物品成交前一直留在挂单人的背包里（实例重启只丢挂单不丢东西）；30 分钟没人接自动撤下；每人同时最多挂 3 件，同一件挂的单不超过背包数量；每人最多 3 份待收的礼物，每个地点最多 30 张挂单。送礼时服务端按哈希查到收件人的存档（`h:<哈希>`，落盘时顺带写，只在服务端），确认他就在这个地点；收件人名字以存档为准。
  - 收下 / 买下时服务端同时锁住双方存档，重新检查（挂单人还在这个地点——人走了单子就撤下；对方还有这件；我没有待处理事件、没带满、钱够；今天次数没用完），用 `applyTrade()` 算出双方结果，**一次写入**；接单期间挂单冻结，不能撤回或被别人接。
  - 常遇见的人：共同事件结束、交易成交后，双方存档的 `met` 里记下对方（id 哈希前缀、名字、头像、次数、最近一次的现实日，最多 30 人）。社交页列出来，在线的显示在哪，同地点的可以直接送礼。
  - 防刷：只能交易物品、不能直接转钱；每人每个现实日最多送出、收下各 5 次（买卖也算）；二手摊价格限定在商店价的 50%–150%。收件人用在线状态里的 id 哈希前缀指定，不暴露真实 id。

- **全服周目标**（`weekly`，`op: status / claim`）：每个现实周（珀斯时间）轮换一个目标——共同事件、送礼或二手摊成交、收费体验、出行抵达——全服一起累计。累计数存在 `week:<周序号>`（内存一份，落盘成功后才更新）；玩家自己出了几份力、领没领记在存档 `weekly`。达成后这周出过力的玩家各领一次奖励（$40、声望 +1）。目标按「小规模试运营」档：共同事件 8、交易 6、收费体验 8、出行 30（假设每周约 10 名活跃玩家，平衡分析第九轮给的三档里用户选的）。周和现实日都按存档单调不倒退的时间算，存档里的周序号只往前走（服务器时钟回拨不会重开旧周）；记入全服计数的写入排队提交，每次从已落盘的数往上加，和存档在同一次写入里落盘，写失败时两边都不变；领奖只看已落盘的数。「收费体验」只算价格大于 0 的体验。

- **地点留言板**（`notes`，`op: list / post / delete`）：附近页底部，给后来到这里的人留一句话。每个地点只留最近 20 条（存 `notes:<地点>`，内存一份、落盘成功后才更新）；每人每个现实日最多 3 条、同一个地点一天一条、每个地点一天最多新增 10 条、删帖不退额度（个人计数存 `notecd:<id 哈希>`，地点计数存 `notesday:<地点>`，两个计数的日期都只往前走，防时钟回拨重开额度；同一地点的发帖、删帖排队执行）；不能带网址、长串数字、@ 账号、「微信 xxx」这类联系方式，检测前先做全角转半角并去掉空格和分隔符；日期、钟点、金额只在没有「电话、联系、+区号」这类语境且不超过 2 处时豁免（`core/notes.ts` 的 `cleanNote()`，服务端和界面共用）；作者只能删自己的，作者 id 不外发。留言不改存档。

校验内容：字段白名单、类别枚举、坐标必须落在所属地点的打卡半径内、id 规范。任何一条不合格整批不写入。

## 7. CGI 素材（GPT image 2 / 远程 ComfyUI）

当前的 238 张图由 GPT image 2 生成：35 个地点主视觉 + 84 张事件插图 + 17 张 NPC 头像（2026-11-19），以及 102 张界面配图（2026-11-20，体验、摄影任务、节日、车辆、房产、住处、职业、课程、证书、鱼获、页头横幅、空状态；设计清单见 [`cg-screens.md`](cg-screens.md)）：

```bash
npm run earth:cgi:gpti -- --dry-run                  # 只看提示词
npm run earth:cgi:gpti -- --only=perth,event:whale-shark --force
```

- 走 gpt-image-2-skill 的 Codex 账号通道（不需要 OPENAI_API_KEY），模型默认 `gpt-5.6-sol`（`GPTI_MODEL` 可改；默认的 gpt-5.4 在 ChatGPT 账号下报 model_not_found）。单张 20 秒到 2 分钟。
- 1536×1024 原图放 `tools/earth/comfyui/.raw/`（不进仓库），网页用的压成 960 宽 WebP（每张约 100KB）。
- 地点图按 `prompts.mjs` 的 `LOC_SCENE` 一句标志性风景来画；游戏标签（机场、医院、健身房……）不进提示词，试画时它们被照字面画进去，画面又挤又乱。
- 画面是 AI 生成的示意图，不是实拍；不画可辨认的人：事件里有人的画面一律写背影、剪影或只露手，警察不画徽章和字。
- 界面配图分两种尺寸：行内缩略图和图鉴格子用方形任务（`size: 1024x1024`，`width: 256`，原图按实际宽高居中裁正方形，每张约 10–20KB），封面、横幅和空状态用宽图（960 或 640 宽）。键名带类别前缀（`exp:` `photo:` `fest:` `veh:` `prop:` `home:` `career:` `course:` `cert:` `fish:` `banner:` `empty:`），页面用 `thumb()` `cover()` `banner()` `emptyArt()` 读图，没图时退回原来的 emoji 方块或不占位。新增这些数据时在 `prompts.mjs` 对应的 `*_SCENE` 表补一句画面，否则 `cgi.test.ts` 会报「没有图」。
- NPC 头像按 `NPC_LOOK` 写年龄、职业、穿着和常驻地点背景，不写族裔（由纪按角色设定写日裔澳洲人）；提示词固定带「虚构原创角色、不像任何真人或名人」。方形 1024 原图，压成 256 宽，页面里 56px 显示；没有图时退回按 id 画的 SVG 立绘。
- 新增事件或 NPC 要在 `EVENT_SCENE` / `NPC_LOOK` 补一句画面描述再跑脚本，否则 `cgi.test.ts` 会报「没有插图」或「没有头像」。南澳事件的地名自动写成 South Australia；店铺通用事件两州都会触发，写「普通澳洲郊区、不要地标」，只写 Australia 时画出了悉尼歌剧院和乌鲁鲁。

远程 ComfyUI 版（原有脚本，暂时没有可用的 SDXL 模型）：

```bash
npm run earth:cgi -- --dry-run                       # 只看提示词（不需要 ComfyUI）
COMFYUI_URL=http://<主机>:8188 \
COMFYUI_CKPT=sd_xl_base_1.0.safetensors npm run earth:cgi
npm run earth:cgi -- --only=perth,event:whale-shark --force
```

- 提示词由游戏数据自动拼出（`prompts.mjs`），统一画风只改 `STYLE` 一处。
- 工作流模板 `workflow.sdxl.json` 是 ComfyUI 的 API 格式，可在 ComfyUI 里用 “Save (API Format)” 导出替换，保留 `__POSITIVE__ / __NEGATIVE__ / __CKPT__` 占位符。
- 脚本逐张落盘并更新 `manifest.json`，中断可续跑；已存在的图默认跳过。
- ComfyUI 本身没有鉴权，**不要把 8188 端口直接暴露到公网**：走 VPN / SSH 隧道，或放在带令牌的反向代理后面（`COMFYUI_TOKEN`）。

## 10. 已知限制（第一阶段）

- 真实定位打卡信任客户端上报的坐标，手机上伪造定位可以“瞬移”打卡。要防这一点需要另做位置可信度校验。
- 所有存档在同一个 Durable Object 实例里，适合当前规模；玩家多了要按 id 分片。
- 地图是手工简化的示意轮廓，不是测绘级数据。
- ComfyUI 脚本已对照 API 协议用模拟服务验证过流程，尚未连真实出图机跑过；首次使用请先 `--only=perth` 试一张。现有图片走的是 GPT image 2。
- 南澳的事件、NPC、房产、地下屋数值照西澳同类写，**待平衡**；南澳还没有真实地点和打卡点。
- 南澳夏令时用固定日期近似，起止日和现实每年差几天。
- 野生动物和鱼的分布按常识写，还没让 OpenClaw 逐条核实。
