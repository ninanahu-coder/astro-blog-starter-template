# 地球人生 / Terra Life —— 游戏框架说明

在真实地图上生活的在线人生模拟。第一阶段以**西澳大利亚**为试点：
生活需求（吃、睡、清洁、娱乐、社交）+ 开放世界式能力成长（体能、力量、驾驶、游泳、魅力、生存、街头）+
**到达地点触发事件** + 同地点玩家互动 + **手机多端云同步**。

- 试玩入口：`/earth`（手机优先）
- 本地运行：`npm run preview`（需要 Durable Object，所以用 wrangler 而不是 `astro dev`）
- 测试：`npm test`

> 这是原创设定。生活模拟与开放世界属性成长只是玩法类型上的参考，不使用任何现有游戏的名称、角色、美术或关卡。

## 1. 四个工具的分工

| 角色 | 工具 | 负责什么 | 产物落在哪里 | 不做什么 |
| --- | --- | --- | --- | --- |
| 逻辑 + 前端 | **Claude Code** | 类型、规则引擎、Durable Object、`/earth` 页面、测试；按 Codex 的分析报告实施调参 | `src/game/`、`src/pages/earth.astro`、`tests/earth/` | 不手写大批量数据、不生成图片、不自己下平衡分析结论 |
| 数据采集 | **OpenClaw** | 按任务书采集 POI、地点和节日的真实资料（OSM / Wikidata） | `tools/earth/openclaw/inbox/*.json` → `src/game/data/wa.pois.json` | 不改代码；只交 JSON |
| 检查与分析 | **Codex** | 审 PR（规则正确性、安全、数据许可）；跑数值模拟并写平衡分析；分析 OpenClaw 的数据。任务书 [codex-tasks.md](codex-tasks.md) | PR 审查评论；`docs/earth-game/balance.md` 的分析小节 | 不写逻辑和前端；调参只提建议 |
| CGI 素材 | **远程 ComfyUI** | 地点主视觉、事件插图 | `public/earth/cgi/*.png` + `manifest.json` | 不参与逻辑；缺图时前端自动用占位图 |

四者之间只通过**仓库里的文件**交接，互不依赖对方在线：

```

                                                               ├─▶ PR ──▶ Codex 审查 ──▶ 合并 ──▶ 部署
Claude Code ──▶ src/game/** + earth.astro + tests ─────────────┤
                                    Codex 跑 earth:sim ──▶ balance.md 分析 ──▶ Claude Code 按报告调参
                                                               │
src/game/data/* ──▶ prompts.mjs ──▶ 远程 ComfyUI ──▶ cgi/*.png ─┘
```

## 2. 代码结构

```
src/game/
  core/types.ts       全部数据结构（PlayerState / Region / GameEvent / Activity / Effect）
  core/character.ts   出身、初始属性、存档校验 sanitizeState()
  core/engine.ts      规则引擎：travel / performActivity / resolveEvent / gpsCheckIn（纯函数、确定性）
  core/geo.ts         距离、地图投影、真实坐标 → 游戏地点
  core/formulas.ts    派生属性（体质、吸引力、状态系数……）与真实地点动作的公式
  core/venues.ts      真实地点：附近列表、定位检查、吃饭/训练/打卡上班等结算
  core/board.ts       净资产排行榜：榜单记录与排名
  core/achievements.ts 成就：由存档现算的里程碑（不进存档、不发奖励）
  core/weather.ts     天气：由地点和游戏日确定（人人一样），风暴天取消海上的活动
  data/achievements.ts 成就表（选指标和目标值即可加一条）
  data/wa.ts          西澳：18 个地点、路线图、海岸线轮廓
  data/wa.pois.json   打卡点（OpenClaw 写入）
  data/venues.ts      真实地点的类型、动作和定位规则
  data/wa.venues.json 真实地点（OpenClaw 从 OSM 采集写入）
  data/activities.ts  地点互动表（数值调参都在这里）
  data/events.ts      到达事件表（加事件只加数据，不写逻辑）
  data/venue-events.ts 到店事件表：真实地点做完事后按地点类型触发（见 real-places.md §5）
  server/world.ts     Durable Object：在线位置、同地点聊天/表情、云存档、排行榜
src/pages/earth.astro 手机端单页客户端（只负责渲染和输入）
tools/earth/openclaw/ 采集任务书、JSON Schema、校验合并脚本
tools/earth/comfyui/  提示词生成、工作流模板、远程出图脚本
tests/earth/          引擎与数据自洽性测试
```

人物属性、派生数值公式和基本元素的完整说明见 [core-design.md](core-design.md)。数值平衡模拟的方法和结论见 [balance.md](balance.md)（`npm run earth:sim`）。消费与资产系统的方案（待确认）见 [economy-plan.md](economy-plan.md)。真实地点（人到真实的餐馆、健身房、公园就能在游戏里做事）和派生属性公式见 [real-places.md](real-places.md)。

设计原则：

1. **规则是纯函数**。`engine.ts` 不碰 DOM、不碰网络，随机数种子存在存档里。同一份代码前端跑、测试跑，服务端也用它做权威结算（已完成）。
2. **内容是数据**。新地点、新互动、新事件都是往数组里加一条；`Effect` 一种结构描述所有数值变化。
3. **不可信输入一律过 `sanitizeState()`**。本地存档、云端存档、别的设备传来的状态都先校验再用。

## 3. 玩法设定

### 初始属性

| 类别 | 字段 | 说明 |
| --- | --- | --- |
| 生活需求（0–100，随时间下降） | 饱食、精力、清洁、娱乐、社交 | 饱食或精力归零会持续掉健康 |
| 能力（0–100，越用越高；目前不会退步） | 体能、力量、驾驶、游泳、魅力、生存、街头 | 影响事件检定、行车速度、可做的互动 |
| 状态 | 现金、健康、声望、麻烦值、座驾 | 麻烦值 ≥ 60 会被盘查；健康归零会在最近的医院醒来，付医药费 $100 + 现金的 10%（最多 $500） |

四种出身（背包客 / 矿区轮班工 / 留学生 / 冲浪手）决定起始现金、座驾和能力侧重。

### 到达事件

- 每次抵达一个地点都会掷一次事件；**首次到访**且当地有“签名事件”（如罗特尼斯岛的短尾矮袋鼠、埃克斯茅斯的鲸鲨）时必定触发。
- 事件按 `locs / tags / kinds / arrivedBy` 匹配地点和到达方式，选项可带能力检定（`能力值 + 0~60 随机 ≥ 难度`）。
- **真实定位打卡**：手机本人到了某个地点的半径内，可以直接“抵达”并触发事件；400 米内的 POI 首次打卡加声望。

### 出行

公路（无车坐巴士、有车自驾并涨驾驶）、越野土路（需四驱）、渡轮、航班。时间流逝会带动需求衰减，所以长途前要吃饱睡好。

### 天气、相册与成就

- **天气**（`core/weather.ts`）：每个地点每个游戏日一种，由「地点 + 日期」哈希确定，所有玩家看到的一样，可以预报（地点卡显示明天的天气）。冬季风暴最多。风暴天下海、浮潜、冲浪、出海都做不了——普通互动、事件选项、NPC 专属互动里标了 `exposed: 'sea'` 的都受影响；海滩上会多出「看风暴」。下雨天城镇、港口、海岸、公园和海岛有专门的小事件；不下雨的夜里内陆和公园可以「看星星」。
- **昼夜**：按游戏时刻分清晨（5–8）、白天、傍晚（17–20）、夜晚四个时段。顶栏底色、地图夜色和星星跟着当地真实的日出日落走（第 37 轮，见「天象」），不跟这四个时段；两者不一致时顶栏时段名后面补一句实际天色，例如冬天 18:30「傍晚（天已经黑了）」。有的事件只在某个时段抵达时出现（清晨港口的渔船、傍晚海滩的日落、天黑后公路上的袋鼠、珀斯的河边夜景）；海滩清晨可以「看日出」。
- **天气相册**（存档字段 `photos`）：抵达一个地点时按当天天气收一张照片（地点 × 天气，共 90 张），只是收藏，不发奖励。
- **成就**（`core/achievements.ts`）：由存档现算的里程碑（19 个），不进存档、不发奖励。

## 4. 手机界面

`/earth` 是手机优先的单页应用，底部 5 个标签：

| 标签 | 内容 |
| --- | --- |
| 今天 | 角色卡与 6 条需求、「下一步」建议（按最缺的需求、周结算、上班、心愿排优先级）、昨天回顾（跨日后显示上一天的变化）、新手指南（前三天分步解开，见 `data/guide.ts`）、周结算预警、当前地点的互动、NPC、工作、住处、商店等 |
| 出行 | 地图（只在这一页绘制）：默认用 MapLibre 画 OpenStreetMap 真实地图，图块来自 OpenFreeMap（免费、不要 key），地图库单独打包、第一次打开出行页才下载；设置里关掉、离线、没有 WebGL 或加载失败时用手绘 SVG 地图（见 `src/game/ui/basemap.ts`）。点地点弹出目的地卡片、各条路线的价格时间和天气 |
| 附近 | 真实地点（定位后列出）、上班卡计时 |
| 社交 | 认识的人今天在哪、同地点玩家与本地频道（含快捷短语）、净资产排行 |
| 我 | 概况（成就、足迹、每日奖励、能力）、资产（含天气相册）、关系、日志（按天分组）、设置（字号三档、动画跟随系统/减少/正常、音效（Web Audio 现场合成，默认关，见 `src/game/ui/sound.ts`）、真实地图开关（默认开）、新手指南/昨天回顾/成就提示开关，只存在本机，见 `src/game/ui/prefs.ts`；玩法说明、同步码；同步页可显示二维码，里面是 `/earth/#sync=同步码` 链接，另一台手机用相机扫了直接打开恢复，同步码在 `#` 后面不发给服务器、读完马上从地址栏抹掉；本机已有别的角色时先问再换；启动时先处理完扫码，才给原角色连线、同步、补交排队；服务器发来的存档先清洗、核对是这个角色的才写进本机，见 `src/game/ui/transfer.ts`） |

- 深色模式跟随系统；颜色都是变量，深浅两套一一对应（`tests/earth/contrast.test.ts` 检查对比度）。
- **可添加到主屏幕**：`public/earth/manifest.webmanifest` 和离线外壳 `public/earth/sw.js`（作用域 `/earth/`）。外壳安装时从首页 HTML 解析并预缓存构建文件，联网打开首页时更新、清理旧文件；`/api/` 从不缓存。断网时可以查看，联网后才能行动。
- **多区域（第 41 轮起）**：游戏世界由几个区域（西澳、南澳……）拼成，注册表在 `src/game/data/areas-base.ts`（`AREAS`、跨区域路线 `CROSS_ROUTES`）。规则层（引擎、服务器、存档清洗）用合并后的世界 `WORLD`（`mergeAreas`：地点、路线、打卡点、真实地点拼在一起；地点 id 必须全世界唯一，跨区域路线两端必须在不同区域，违反就启动报错）；存档里的 `region` 由所在地点决定。画面层按所在地点的区域（`areaOf`）画：手绘地图、真实底图、轮廓、在线频道都按区域分，跨区域后底图重建、在线频道重连。
- **南澳（第 42 轮起）**：`src/game/data/sa-base.ts`，12 个地点（阿德莱德、格莱内尔格、汉多夫、巴罗萨谷、麦克拉伦谷、维克多港、袋鼠岛、林肯港、库伯佩迪、弗林德斯山脉、甘比尔山、锡杜纳）。坐标、类型、标签、简介和小知识由 OpenClaw 从 Wikidata / OSM / 维基百科采集（原始结果 `tools/earth/openclaw/inbox/sa-locations-2026-11-18.json`），Claude 核对后改正了几条不存在的路线和几条小知识；州界轮廓是手工简化的种子数据。「我」页足迹按区域分组。打卡点、真实地点（餐馆等）还没采集。
- **跨区域出行（第 43 轮）**：`CROSS_ROUTES` 里两条——珀斯—阿德莱德航班、卡尔古利—锡杜纳公路（横穿纳拉伯平原的艾尔公路）。价格和时间照旧按出行公式算，没有新数值。地图上从本区域的那一头画一小段通往另一个区域的出口（✈️ / 🛣️ + 目的地和区域名），点它出目的地卡片；出行列表里跨区域的路线标「去某某区域」。到了以后存档区域跟着变，地图换成那个区域，在线频道换到那个区域。印度洋—太平洋号火车要新的出行方式和价格，留到以后。
- **南澳事件与 NPC（第 44 轮）**：`src/game/data/events-sa.ts` 每个南澳地点一条签名事件（中央市场、格莱内尔格电车、汉多夫面包房、巴罗萨酒窖、维克多港马拉电车、袋鼠岛神奇岩石和海豹湾、林肯港金枪鱼码头、库伯佩迪翻矿渣找欧泊、威尔佩纳的黄脚岩袋鼠、蓝湖、锡杜纳生蚝等）；三位原创 NPC：巴罗萨的酿酒师葛蕾塔、库伯佩迪的欧泊矿工凯文、袋鼠岛的护林员艾拉。事件选项和 NPC 剧情的效果数值照西澳同类写，**待平衡**。
- **天象（第 8 批，只做显示）**：全部按地点经纬度和游戏日期用公式现场算，不接外部数据、不进存档、不影响任何规则和数值（见 `src/game/core/sky.ts`）。游戏四季对应南半球的现实月份（春 9–11 月、夏 12–2 月、秋 3–5 月、冬 6–8 月），季内按比例，今天页「今天的天」卡写出大约对应现实哪一天。气温：海边地点按几个纬度上的 1 月、7 月平均最高气温大致值插值，内陆夏 +4、冬 −1，再按天气修正、每天 ±2 度起伏；顶栏天气标签带最高气温。日出日落：NOAA 简化太阳位置公式，按西澳标准时间（UTC+8，无夏令时），珀斯和实际时刻差几分钟以内；画面明暗（顶栏底色、地图夜色、星星）跟着当地日出日落走，玩法时段（活动、事件、NPC 日程）照旧按钟点。潮汐（示意）：海边、港口、岛上显示涨潮还是退潮、现在潮高、接下来两次满潮干潮和今天潮差；四个主要分潮叠加，振幅按纬度取西澳海岸的大致量级（北边布鲁姆大潮八九米、珀斯以南不到一米），卡片写明真下海要看官方潮汐预报。山火季（示意）：按澳洲火险评级四级（中等、高、极端、灾难性）提示；南部（南纬 26° 以南）夏天、北部（南纬 23° 以北）旱季、中间 10–2 月，当天炎热升级、下雨降级，内陆炎热天再升一级，灾难性只在少数日子出现；高及以上顶栏有 🔥 提醒，极端和灾难性每个地点每个游戏日只弹一次提示（记在本机 `earth.fire.v1`，重新载入不重复；只在今天页、页面可见时弹，切走就不弹，见 `src/game/ui/alerts.ts`），提示和卡片都写明是游戏估算、不是真实预警，卡片链到 Emergency WA；不影响玩法。紫外线（示意）：按太阳高度的经验公式 UVI ≈ 12.5 × cos(天顶角)^2.42 估算，多云、下雨、风暴打折；按世卫分级，写出今天最高和指数 3 以上要防晒的时段（珀斯 1 月约 8 点到 17 点，和 SunSmart 公布的接近）；现在 8 以上时顶栏提醒。
- **虚拟人生风格界面**：今天页顶栏是一幅当地小场景（`src/game/ui/scene.ts` 现场画的 SVG：天空、云、远山或城市 / 海滩 / 小镇 / 红土、海、地面、树和你自己），天色跟着当地日出日落、天气换云和雨；时间、天气浮在场景上，地点做成名牌，最缺的需求（低于 60）变成人物头上的想法气泡；今天页顶栏不再吸顶。状态卡的六项需求改成圆环。NPC 改成对话样式：立绘（按 NPC 定配色）、名牌、关系条、对话气泡、圆角选项。事件弹窗没有配图时用当地场景压暗当背景，选项改成圆角，第一个能选的高亮。场景都是装饰（`aria-hidden`），不影响规则。设计稿见手机客户端草图画布「虚拟人生风格」一排。
- **性能检查（第 35 轮）**：在线频道的消息（进出、移动、聊天）攒 150 毫秒合成一次重画；社交页同地点玩家只列前 30 位，其余写个数；真实地图的地点标记内容没变就不重写；留言列表在页面这边也按每地点 20 条截断。其余列表都有上限：日志 40 条、聊天 50 条，背包、成就、图鉴、地点受数据本身数量限制。界面测试里一次灌 300 条进场消息检查只重画一两次。
- **首屏体积**：真实地点（`wa.venues.json`，约 80KB）、地图库、二维码库都不进首屏脚本，用到时才下载（真实地点下载失败时「附近」页显示重试按钮，不自动重试；重新联网、重新进入「附近」也会再试）；区域数据分成首屏版 `data/wa-base.ts`（不含真实地点）和完整版 `data/wa.ts`（服务器、测试用）。`tests/earth/bundle.test.ts` 按分包打包页面脚本，检查这三样不在首屏、首屏体积不超上限。
- **离线排队**：断网时做事、出行、钓鱼、拍照、在家睡觉做饭、上班、找熟人聊天帮忙这些动作先排在本机（最多 5 个，超过一天不再补交），今天页列出来、可全部取消；联网同步后按顺序补交，服务器照常逐个结算，哪个没通过就停下、后面的取消并说明原因。看真实位置的、事件选项、买卖租房课程这类大决定不排。每个动作发出前生成一个动作编号，排队时一起存下、补交沿用：动作其实已经在服务器结算、只是回复在路上丢了的，服务器认出编号不再做一次，直接回当时的结果（服务端每个存档记最近 16 个，和存档同一次写入）。见 `src/game/ui/queue.ts`。
- **无障碍**：切换标签、关掉事件弹窗后焦点回到页面内容；弹窗打开时背后页面 `inert`；事件结果页可按 Esc 关闭；输入框都有读屏标签；`ui.test.ts` 的 `a11yIssues()` 对每个标签页、「我」的每个子栏、事件弹窗和静态标记检查按钮名字、图片 alt、输入框标签、tabindex、进度条数值、对话框名字；`contrast.test.ts` 检查深浅两套配色的文字对比度。
- **界面测试**：`tests/earth/ui.test.ts` 现场用 esbuild 打包页面脚本，在 Node 里用最小 DOM 替身运行，请求直接交给 `EarthWorld`，覆盖主要页面和交互。

## 5. 联机与手机同步

| 接口 | 作用 |
| --- | --- |
| `GET /api/earth/ws?region=wa&id&name&avatar&loc`（WebSocket） | 区域在线状态：`hello / join / leave / move / chat / emote / coop`。聊天、表情和共同事件提醒只发给同一地点的玩家 |
| `POST /api/earth/save` `{action:'create'|'get'|'act'|'board'|'coop', id, key, …}` | **服务端权威结算**。`create` 由服务器创建角色；`act` 发送一个动作（`{ rev, act: GameAction, op? }`），服务器调用规则引擎结算、保存并返回新存档；客户端版本落后时返回 409 和最新存档；`op` 是动作编号，同一编号已结算过时不再执行，返回当时的结果和最新存档（`dup: true`）。服务端只存 key 的哈希，不接受客户端上传存档 |

- **同步码** = `id.key`，在“同步”页复制，到另一台设备粘贴即可恢复。等同密码。
- 每个动作都发给服务器结算，成功后 `rev + 1`。同一存档的请求在服务器上排队执行。
- 两台设备同时玩：后发的一方因版本落后被拒绝，并自动载入最新进度。
- 服务器返回的存档隐去了随机数种子，客户端无法预知检定结果。
- 本机 `localStorage` 只缓存最近一次的服务器存档用于显示；联网时一律以服务器为准，改缓存没有作用。
- 断网时可以查看，但不能行动；创建角色也需要联网。
- `board` 返回全服净资产前 20 名和自己的名次（只读）。榜单记录在每次存档落盘时由服务端顺带更新，只含名字、头像、净资产和游戏天数。
- **共同事件**（`coop`，`op: list / open / join / leave / start`）：同一地点的玩家组队做一件事（海滩清洁、街头合奏、帮人推车、救搁浅的海豚、码头钓鱼比赛、峡谷互助徒步、社区烧烤、帮人搬家）。要凑钱的（社区烧烤每人 $8）钱不够不能参加。每人选一个分工，用自己那项能力；团队分 = 每人（检定分 + 随机 0–60）的平均值 + 每多一人 +6，达到难度就成功，所有人拿同一个结果。
  - 每种共同事件每人每个游戏日只能做一次（存档字段 `coopDays`，成败、晕倒都算做过），防止两个账号反复刷声望。
  - 队伍（大厅）只存在存档实例的内存里：5 分钟没开始自动解散，结果保留 3 分钟给队友拉取（这两个时限按服务器真实时间算；正在结算的队伍不会被过期清掉）。对外只给名字、头像、分工和地点，不发存档 id。自己所在的队伍走开以后仍然列出（标「已走开」），可以退出。
  - 只有发起人能开始。点「开始」的请求一到，成员名单就冻结（之后的加入、退出返回 409），服务端在锁住这些成员的存档后重新检查每个人（还在这个地点、没有待处理事件、今天没做过、时间天气合适），至少 2 人才结算（不结算时先解冻再返回，界面不会停在「正在开始」），用 `applyCoop()` 算出每个人的结果，**在同一次存储写入里**写进所有人的存档（版本号各加一；写入失败谁都没拿到，队伍解冻可重试）。每个队友的校验和落盘时间用自己存档的时间（防时钟回拨的规则和单人动作一致）。
  - 队伍有变化时客户端在在线频道发一个不带内容的 `coop` 提醒（服务端对同一连接 1 秒内只转发一次），同地点的人收到后合并成最多每 3 秒拉一次列表；队友那边看到结果后自动载入最新进度。队友结算后自己下一次操作会收到 409，提示「进度刚刚更新过（另一台设备，或队友发起的共同事件）」并载入最新进度。

- **送礼与二手摊**（`trade`，`op: list / gift / sale / cancel / decline / accept`）：在场的人旁边点 🎁，把背包里的一件东西送给他；「摆个二手摊」把东西挂在当前地点按价出售（每件给最低价、商店价、最高价三个价可选），同一地点的人都能买。
  - 挂单只在存档实例的内存里，物品成交前一直留在挂单人的背包里（实例重启只丢挂单不丢东西）；30 分钟没人接自动撤下；每人同时最多挂 3 件，同一件挂的单不超过背包数量；每人最多 3 份待收的礼物，每个地点最多 30 张挂单。送礼时服务端按哈希查到收件人的存档（`h:<哈希>`，落盘时顺带写，只在服务端），确认他就在这个地点；收件人名字以存档为准。
  - 收下 / 买下时服务端同时锁住双方存档，重新检查（挂单人还在这个地点——人走了单子就撤下；对方还有这件；我没有待处理事件、没带满、钱够；今天次数没用完），用 `applyTrade()` 算出双方结果，**一次写入**；接单期间挂单冻结，不能撤回或被别人接。
  - 常遇见的人：共同事件结束、交易成交后，双方存档的 `met` 里记下对方（id 哈希前缀、名字、头像、次数、最近一次的现实日，最多 30 人）。社交页列出来，在线的显示在哪，同地点的可以直接送礼。
  - 防刷：只能交易物品、不能直接转钱；每人每个现实日最多送出、收下各 5 次（买卖也算）；二手摊价格限定在商店价的 50%–150%。收件人用在线状态里的 id 哈希前缀指定，不暴露真实 id。

- **全服周目标**（`weekly`，`op: status / claim`）：每个现实周（珀斯时间）轮换一个目标——共同事件、送礼或二手摊成交、收费体验、出行抵达——全服一起累计。累计数存在 `week:<周序号>`（内存一份，落盘成功后才更新）；玩家自己出了几份力、领没领记在存档 `weekly`。达成后这周出过力的玩家各领一次奖励（初始 $60、声望 +3，待平衡）。周和现实日都按存档单调不倒退的时间算，存档里的周序号只往前走（服务器时钟回拨不会重开旧周）；记入全服计数的写入排队提交，每次从已落盘的数往上加，和存档在同一次写入里落盘，写失败时两边都不变；领奖只看已落盘的数。「收费体验」只算价格大于 0 的体验。

- **地点留言板**（`notes`，`op: list / post / delete`）：附近页底部，给后来到这里的人留一句话。每个地点只留最近 20 条（存 `notes:<地点>`，内存一份、落盘成功后才更新）；每人每个现实日最多 3 条、同一个地点一天一条、每个地点一天最多新增 10 条、删帖不退额度（个人计数存 `notecd:<id 哈希>`，地点计数存 `notesday:<地点>`，两个计数的日期都只往前走，防时钟回拨重开额度；同一地点的发帖、删帖排队执行）；不能带网址、长串数字、@ 账号、「微信 xxx」这类联系方式，检测前先做全角转半角并去掉空格和分隔符；日期、钟点、金额只在没有「电话、联系、+区号」这类语境且不超过 2 处时豁免（`core/notes.ts` 的 `cleanNote()`，服务端和界面共用）；作者只能删自己的，作者 id 不外发。留言不改存档。

- ComfyUI 本身没有鉴权，**不要把 8188 端口直接暴露到公网**：走 VPN / SSH 隧道，或放在带令牌的反向代理后面（`COMFYUI_TOKEN`）。

## 10. 已知限制（第一阶段）

- 地图是手工简化的示意轮廓，不是测绘级数据。
- ComfyUI 脚本已对照 API 协议用模拟服务验证过流程，尚未连真实出图机跑过；首次使用请先 `--only=perth` 试一张。
