# AIGC 视频与语音（第 1 轮试点）

2026-11-20。目标是给「地球人生」加一点会动、会出声的东西，又不拖慢手机首屏。这一轮只做小批量：3 个地点的环境短片、17 位常驻 NPC 的打招呼语音。背景音这轮不做。

## 1. 用在哪里

| 位置 | 内容 | 本轮 |
| --- | --- | --- |
| 「这里」页地点卡的主视觉 | 5 秒左右的静音环境短片，循环播放，替换静态 CGI | 珀斯、卡里基尼、巴瑟尔顿 3 个 |
| 事件弹窗的头图 | 事件短片 | 不做（先看地点短片效果） |
| NPC 卡片「这里的人」 | 一句打招呼台词（文字常显）+「🔊 听」按钮 | 17 位全做 |

## 2. 格式和体积预算

- **短片**：H.264 MP4，640×360（16:9），24fps，去掉音轨（页面上一律静音），`+faststart`。单个上限 1MB（`CLIP_MAX_BYTES`），压制脚本先按 crf 22 压，超过 900KB 再逐级加大 crf。首尾 0.5 秒交叉淡化，循环播放不跳（只播一次的推镜片 `once` 不做淡化，见 §6.3）。只用 MP4 不用 WebM：iOS Safari 对 VP9 WebM 支持不全，H.264 哪里都能放。
- **语音**：MP3 64kbps 单声道 24kHz，响度统一到 -18 LUFS，一句 3–8 秒约 25–60KB，上限 100KB（`VOICE_MAX_BYTES`）。
- **不进首屏**：清单 `/earth/media/manifest.json` 在页面起来后 `fetch` 异步拉取；页面脚本只多了一个约 2KB 的 `src/game/ui/media.ts`（解析清单和拼 HTML）。短片 `preload="none"`，进入视口（40% 可见）才开始下载和播放，离开视口暂停。
- **离线缓存**：Service Worker 不拦 `/earth/media/` 下的 mp4/webm/mp3（视频是 Range 分段请求，缓存进去既占空间也容易让 Safari 播不了）；清单 JSON 照旧走「先联网、断网用缓存」。

## 3. 怎么接入

另建媒体清单，不往 `public/earth/cgi/manifest.json` 里加键（`cgi.test.ts` 要求那份清单和 CGI 提示词一一对应）：

```json
{
	"note": "AI 生成示意内容（视频：远程 ComfyUI MiniMax H3；语音：MiniMax TTS），不是实拍、不是真人录音。",
	"loc": { "perth": { "src": "/earth/media/loc/perth.mp4", "poster": "/earth/cgi/perth.webp" } },
	"voice": { "mia": { "src": "/earth/media/voice/mia.mp3", "text": "早啊！……" } }
}
```

- 页面：`hero()` 改调 `heroHtml(esc, media.loc[key], cgi[key], fallback)`——有短片放短片（封面是原 CGI），没有就退回静态图，再没有就退回图标。NPC 卡片在简介下面加 `greetHtml(...)`，没有语音就什么都不加。
- 清单当不可信数据：`parseMedia` 只认 `/earth/media/loc/*.mp4|webm`、`/earth/media/voice/*.mp3`、`/earth/cgi/*.webp` 这几种路径，键只认小写字母数字连字符，文字截到 120 字；拼 HTML 时全部过 `esc()`。
- 生成工具：
  - 语音：`MINIMAX_API_KEY=… node tools/earth/media/generate-voice.mjs [--only=mia] [--force] [--dry-run]`。台词和音色在 `tools/earth/media/voices.json`。
  - 短片：在 `tools/earth/media/h3/<地点>/` 放一份不进仓库的 `config.env`（`COMFY_URL`、`COMFY_CF_APP`、`OUT_W=1280`、`OUT_H=720`），`segments.json`（提示词）→ `python3 ../submit.py segments.json --seed 7700` → `h3v2.py poll segments.json` → `python3 tools/earth/media/encode-clips.py <地点…>`。

## 4. 无障碍

- 语音的文字一直显示在 NPC 卡片上（「早啊！……」），听不了、不想听、开着静音都不影响。
- 从不自动播放语音：只有点「🔊 听」才放，再点一次停；按钮有 `aria-label`（「听米娅打招呼（AI 语音示意）」）。语音不受「设置 · 音效」开关限制，因为是玩家主动点的。
- 短片没有声音，`aria-hidden`、不能聚焦；设置里「动画：减少」或系统开了减少动态效果时，不播放，只显示封面（原 CGI 静态图）。

## 5. 来源标注

- 地点主视觉（不管是短片还是原来的 CGI 静态图）和事件弹窗头图左下/左上角加「AI 生成示意」小标签；NPC 招呼语旁边写「AI 语音示意」。清单 `note` 字段写明来源。
- NPC 都是虚构人物：语音只用 MiniMax 系统音色，不克隆任何真人声音；短片首帧是原有 CGI，提示词里不写人物。

### 6.1 语音（MiniMax TTS）

- 端点 `https://api.minimax.io/v1/t2a_v2`（海外），模型 `speech-2.8-hd`，`emotion: happy`，语速 1.0。
- 生成前查 Token Plan「general」余量：2026-11-20 03:35 周余量 35%（门槛 30%，脚本里低于 30% 直接停），但 5 小时窗口 0%（2067），用 `mm-quota-retry` 每 10 分钟自动重试，04:00 窗口重置后 04:05 生成完。17 句共约 400 字，按 11-16 实测（每千字约耗周额度 0.033%）几乎不占额度。

### 6.2 短片（自托管远程 ComfyUI H3，RTX 5090）

- 工作流：h3v2 的 FL2VA，首帧和尾帧都用同一张原 CGI（1774×887 原图中心裁成 16:9、缩到 1280×720），这样短片首尾是同一画面，循环播放没有跳变。
- 时长 5 秒按 H3 帧网格圆整成 5.17 秒（124 帧）。种子 7700+1。上传用内容哈希命名（`submit.py` 包 `upload_unique`），提交后核对过 3 个任务的 LoadImage 文件名各不相同。
- 提示词按 h3v2 结构（对齐行 + integrated_multimodal_description + overall_soundscape + non_diegetic_music: N/A），固定机位广角，只写自然的小幅运动（水、云、树叶），写明地标不动；没写人和动物。过 h3prompt 门禁：0 错误；初稿有一条 W_FL2VA_NO_CONVERGENCE，补了收敛句后干净。提交稿在 `tools/earth/media/h3/<地点>/_prompts/seg1.submitted.txt`。

- 出片：3 段都是 124 帧（5.17 秒），远程排队时队列是空的，3 段大约 15 分钟全部取回。原片 4.1–4.5MB（带 H3 自生的环境声，网页不用）。
- 压制：`encode-clips.py` 先 crf 22（crf 28 只有 175KB，预算还宽，就用了更清楚的档）；循环处理是去掉原片开头 13 帧，把它交叉淡化接在结尾（0.5 秒）。成片 4.67 秒、112 帧，**413KB / 407KB / 413KB**（珀斯 / 卡里基尼 / 巴瑟尔顿），H.264 Main 640×360 yuv420p，无音轨。

### 6.3 对比：纯 i2v 推镜版（2026-11-20，珀斯、卡里基尼）

- 做法：`tools/earth/media/h3/submit_i2v.py`，只给首帧（同一张关键帧），不给尾帧（h3v2 的 FL2VA 模板删掉尾帧节点，和 `~/AI/video-workflow/bench_h3.py` 的 I2VA 用法一致）。没用「首尾同帧 + 提示词写推镜」，因为提示词库实测这样会推近后硬拉回。提示词沿用循环版的风景描述，加官方推镜句 `the camera pushes in with small amplitude at slow speed toward … and comes to rest on a slightly tighter wide shot … in the final second`（写清终点和停点）。过 h3prompt 门禁（I2VA，5.17 秒）：0 错误 0 警告。种子 7701，和循环版相同。提交稿在 `tools/earth/media/h3/<地点>-push/_prompts/`，原片不进仓库，**没换进页面**。
- 测量方法：320×180 灰度；运动量是相邻帧差的中位数；推近比例是每帧对首帧中心裁切放大做尺度搜索（1.00–1.40）。

| 检查 | 珀斯 循环版 → 推镜版 | 卡里基尼 循环版 → 推镜版 |
| --- | --- | --- |
| 首帧 vs 关键帧（串帧检查） | 4.5 → 4.8 ✓ | 4.7 → 5.0 ✓ |
| 运动量（相邻帧差中位） | 0.39 → **1.95**（5 倍） | 0.42 → 0.94（2 倍） |
| 推近比例（末帧相对首帧） | 1.000 → **1.080**，0–4.3 秒匀速推近，最后约 0.7 秒停住，没有回弹 | 1.000 → **1.005**（实际没推），平移 0 px，变化全来自水面和水雾 |
| 6 张等距抽帧目视 | 天际线、河岸、桉树枝随推镜整体放大，楼没有变形、没有长出新楼、无文字、无人 | 岩壁、瀑布形状稳定，无变形；看起来还是固定机位 |
| 网页规格压制（640×360 H.264，无音轨，5.17 秒，不做循环淡化） | crf 25 = 427KB，crf 28 = 264KB | crf 25 = 330KB，crf 28 = 208KB |

结论：
1. **推镜能不能出来看画面**：同一句推镜，珀斯推了 8%，卡里基尼几乎没推。推不推和画面、种子有关，扩到 35 个地点会有一部分照样静止，每段都要量一下推近比例。
2. **推镜版不能直接循环**：末帧比首帧放大 8%，`loop` 播到结尾会「啪」地跳回广角。真要用，页面得改成「播一遍停在末帧」（去掉 `loop`、`ended` 后保持），或者正放完倒放（往返循环，体积翻倍，倒放时水和云会逆流）。循环版没有这个问题。
3. **体积不是问题**：两版都在 430KB 以内。
4. 建议：默认还用循环版（稳定，每个地点都能循环）；想要「到达这个地点」时有点镜头感，可以把推镜版当成**只播一次的到达动画**，播完停在末帧。这需要改 `heroHtml`（按清单字段区分 `loop` / `once`），这一轮没改。**两版都没在真机上看过。**

**已采用（2026-11-20）：珀斯换成推镜版，只播一次。**
- 清单字段 `once: true`（`parseMedia` 只认布尔 true）；`heroHtml` 对 once 片不写 `loop`，改写 `data-once="1"`，仍然 `muted`、`preload="none"`、不自动播放。
- 页面 `wireClips`：每次**到达**（`state.loc` 变了）播一次，播完停在末帧；面板重绘时沿用原来的 `<video>` 元素，不会从头重播（循环片也受益，重绘不再从头开始）；这次到达已播过、重绘又生成了新元素时，直接跳到末帧不播；「减少动画」时不播，只显示封面（首帧）。
- 压制：`encode-clips.py --once perth@perth-push`，不做循环淡化，整段 5.17 秒、124 帧，crf 22 = **743KB**（在 1MB 预算内，比循环版 413KB 大，因为推镜整幅都在变）。
- **巴瑟尔顿**也试了推镜（同一套写法，推镜句终点是「沿栈桥朝地平线」，门禁 0 错误 0 警告，种子 7701）：末帧 ×1.070，0–5 秒匀速推近、到结尾还在微动（没像珀斯那样提前停住），运动量中位 0.24 → 1.26；6 张抽帧里栈桥、小屋、路灯都没变形，无文字无人。已换成 once 版，crf 22 = **531KB**。
- **卡里基尼**换种子 8802 又试一次：末帧仍是 ×1.005、平移 0，和种子 7701 一样没推起来（运动量 0.91，全是水）。两颗种子都不推，判断是这张图（瀑布正对镜头、构图居中）本身不吃推镜句，**继续用循环版**。两次的原片在 `tools/earth/media/h3/karijini-push/clips/`（不进仓库）。
- 小结：3 个地点里 2 个推起来（珀斯 8%、巴瑟尔顿 7%），1 个两颗种子都推不动。扩到其他地点时按这个比例估，大约三分之一要退回循环版。
- 首屏脚本 396414 → 397114 字节（+700，播放逻辑），gzip 123267，上限 560KB。
- **没在真机上看过**：iOS Safari 播完停在末帧、跳到末帧这两点都只看了代码，没实际验证。

**全覆盖规则（测试强制）。** 35 个地点里 22 个有短片，另外 13 个在 `clips-qa.json` 的 `skipped` 里各写了一句不做的原因。`tests/earth/media.test.ts` 检查：有短片的和写了原因的加起来必须正好是全部地点（新加地点时不会悄悄漏掉）；封面必须是 `/earth/media/loc/<地点>.webp` 且 `poster_diff < 6`；每段必须有 `eyeball: ok`。批量脚本出片时写的是 `eyeball: pending`，没人看过抽帧就过不了测试。
