## 1. 目标语言和优先级

| 优先级 | 语言 | 代码 | 读者 | 状态 |
| --- | --- | --- | --- | --- |
| P0 | 简体中文 | `zh-Hans` | 主体玩家：西澳、南澳的大陆华人和留学生 | 默认语言，也是基准：键名和占位符都以它为准 |
| P1 | 英文（澳洲拼写） | `en` | 玩家带来的本地同学和同事、ABC；地名、店名本来就是英文；也方便审查 | 已迁移的部分全部翻完 |
| P2 | 繁体中文 | `zh-Hant` | 港、台、澳门玩家；马来西亚华人多数读简体，不算在内 | 已迁移的部分全部翻完 |

英文排在繁体前面，原因有两条：

- 繁体玩家读简体基本没有障碍，不会英文的本地朋友读中文却完全进不去。
- 英文版能顺带检查文案有没有写死在代码里：中文界面里混着中文看不出来，英文界面里一眼就能看到。

暂时不加其他语言。以后要加，按 §8 的流程先做成「部分翻译」，不放进 `COMPLETE_LOCALES`。

## 2. 文案抽取

### 2.1 界面字符串表

- 文件位置：
  - `src/game/i18n/strings/zh-Hans.ts`：基准表，写成 `as const`，`StrKey` 就是从它推出来的类型。
  - `src/game/i18n/strings/en.ts`、`src/game/i18n/strings/zh-Hant.ts`：类型是 `Record<StrKey, string>`。基准表加了键，这两张表没跟上的话，`tsc` 直接报错；多写一个键也报错。
- 键名按「页面.区块.用途」分段，只用小写字母、数字、点和连字符，例如 `pref.basemap.hint`、`tab.social.online`。键名表示文案的用途，不跟着中文措辞改。
- 占位符写 `{name}`，由 `t(locale, key, { name })` 填。
  - 各语言同一个键的占位符必须完全一样，有测试检查。
  - 漏传参数时，`{name}` 会原样显示在界面上，不会悄悄变成空字符串。
  - 参数值里的花括号不会再被展开。
- 复数：文案尽量写成不分单复数的说法，比如 `Players online here: {n}`，而不是 `{n} players`。以后真的需要分单复数，用成对的键 `xxx.one` / `xxx.other`，加一个用 `Intl.PluralRules` 选键的 `tn()`；本批还没有这样的需求，所以没做。
- 一句话不要拆成几个键再拼起来，否则别的语言没法调整语序。整句写成一个键，变化的部分用占位符。
- 页面里用 `tx(key, params)` 取文案，它等于 `esc(t(prefs.lang, key, params))`。
  - 结果已经转义，可以直接拼进 `innerHTML`。
  - 不能在别处直接调 `t(prefs.lang, …)`，也不能写 `${t(…)}`，测试会拦。
  - 字符串表本身也当作不可信内容转义，因为将来可能有人通过 PR 提交翻译，不能让翻译文本带进 HTML。

### 2.2 数据表（`src/game/data/*.ts`）

数据表的多语言做法：**中文原文留在原来的数据文件里不动，译文放进旁边单独的翻译文件，按 id 对应。**

```ts
// src/game/i18n/data/en/locations.ts（示意，本批还没建）
import type { DataTr } from '../types.ts';
export const LOCATIONS_EN: DataTr<'name' | 'desc'> = {
	perth: { desc: 'Capital of Western Australia on the Swan River…' },
	// name 不用写：地点已经有 en 字段，取名时直接用它（见 §7）
};
```

为什么不在原数据上加 `name_en`、`desc_en` 这样的字段：

1. **不碰 core**。core 继续读中文字段，生成日志和结算，完全不知道有几种语言，`src/game/core/` 依然是纯函数。翻译只在界面层用 `dataText(locale, 'locations', id, 'desc', zh原文)` 去取，取不到就用中文原文。
2. **不和并行分支冲突**。十多个分支正在改 `items.ts`、`events.ts` 这些文件的同一批行。翻译放进新文件，合并时一行都不会撞。
3. **方便校对**。一个翻译文件就是一张待校对的表，交给翻译和校对的人，不需要懂数据结构。

翻译文件要守的约束，以后建第一个翻译文件时一起写进测试：

- 翻译文件里的 id 必须在原表里存在，防止原表删了或改了 id 以后，翻译文件里留下没主的条目。
- 字段名只能是原表里有的文本字段。
- 占位符要和原文一致。
- 每种语言的覆盖率打印成报告。覆盖率不作为门禁，因为数据表允许部分翻译、回退到中文。

### 2.3 core 生成的文字

日志（`journal`）、结算提示、服务器返回的错误，目前都是 core 或服务器直接拼好的中文，存进了存档。迁移分两步：

1. 先让日志条目带上可选的 `key` 和 `params`，`text` 字段保留，旧存档照样能显示。界面上有 `key` 的条目按当前语言渲染，没有的照原文显示。
   - core 只输出键和参数，不翻译。
   - `sanitizeState()` 要校验 `key` 在白名单里、`params` 只能是短字符串或数字。
2. 服务器错误改成返回错误码，界面按错误码取文案。

这一步要改存档结构和服务器，放在 §10 的最后。

## 3. 回退规则

- 界面文案的查找顺序：当前语言 → `LOCALES[x].fallback` 里列的语言 → 简体中文 → 键名本身。
  - 走到「键名本身」只可能是运行时拼错了键。静态写出的键由 `tsc` 和测试保证存在。
  - 繁体和英文都回退到简体中文。不会回退成空白，也不会回退成键名。
- 数据文本的查找顺序：翻译文件里这个 id 的这个字段 → 数据原文（中文）。
- 迁移期间，同一页上中英混排是允许的。选了非简体中文时，设置页会提示「部分界面还没有翻译，暂时显示简体中文」。所有界面迁移完以后去掉这句提示。
- 玩家自己写的内容不翻译：角色名、聊天、留言、挂单。

## 4. 语言切换和存储

**语言存在本机，不进存档。** 和字号、动画一样，语言放在 `earth.prefs.v1` 的 `lang` 字段里（`src/game/ui/prefs.ts`）。

理由：

- 语言是这台设备的显示偏好。一个人可能手机用中文，给朋友演示时用平板切英文。
- 存档由服务器权威结算，要经过 `sanitizeState()` 和 `publicState()`，不应该为了显示偏好改存档结构和服务器。
- 换设备时，同步码恢复后语言回到默认的简体中文，在设置页点一下就能改回来，代价很小。

具体做法：

- 读取：`parsePrefs()` 只接受 `zh-Hans`、`zh-Hant`、`en` 三个值，用 `isLocale()` 判断，它用的是 `Object.hasOwn`，原型链上的名字不认。坏值一律退回简体中文。
- 默认语言：一律是简体中文，**不按浏览器语言自动切换**。很多留学生的手机系统语言是英文，自动切换会把主力玩家切到英文。以后可以在开场页（`claude/earth-start-ui`）加一个语言选择。
- 切换：设置页「显示」卡里有「简体中文 / 繁體中文 / English」三个按钮。
  - 每个按钮的语言名用那门语言自己写，并带 `lang` 属性，玩家看不懂当前语言时也能找到自己的语言。
  - 点了以后调用 `setPrefs({ lang })`，同时更新 `<html lang>`（读屏和 CJK 字形选择都看这个属性），再重画面板。
- 服务端渲染的首屏 `<html lang="zh-CN">` 不变；脚本启动后，`applyPrefs()` 再按设置改掉。

## 5. 数字、货币、日期、时区

都在 `src/game/i18n/format.ts` 里，全是纯函数。现实时间由调用方传入毫秒数，函数内部不调 `Date.now()`。

| 类型 | 规则 | 函数 |
| --- | --- | --- |
| 金额 | 游戏里只有澳元。各语言都写 `$1,234`：不写 `A$`、`AUD` 或「澳元」，不保留小数，用千位分隔，负数写 `−$12`（用减号，不用连字符），四舍五入成 0 时不带负号。中文界面也不换算成「万」 | `fmtMoney` |
| 数字 | 千位分隔；小数位数由调用方决定，比如声望保留 1 位 | `fmtNumber` |
| 游戏内时间 | `clock` 是游戏里过去的分钟数，跟现实时区无关。简体中文的输出和 core 的 `formatClock` 一字不差（有测试对照）；英文是 `Day 3 08:05` | `fmtGameClock` |
| 游戏日历 | 季节、星期（`time.ts` 的 `SEASONS`、`WEEKDAYS`）以后迁成键 `cal.season.*`、`cal.weekday.*`；core 里的常量不动 | （待迁） |
| 现实时间 | 聊天、留言、挂单的时间这类真实时刻，按**玩家当前所在区域**的时区显示，不按设备时区。西澳是 `Australia/Perth`，全年 UTC+8，没有夏令时。南澳是 `Australia/Adelaide`，平时 UTC+9:30，夏令时 UTC+10:30（10 月第一个周日到 4 月第一个周日）。不认识的区域按珀斯 | `fmtRealDateTime` |
| 相对时间 | 「3 分钟前」这类相对时间跟时区无关，以后用 `Intl.RelativeTimeFormat` | （待迁） |
| 单位 | 澳洲用公制。距离写 km，温度写 °C，不按语言换算 | — |

现在页面里大约有 46 处 `$${…}` 直接拼金额，以后跟着各自所在的区块迁到 `fmtMoney`，不单独开一批去改。

## 6. Intl 依赖

- 格式化用浏览器自带的 `Intl`。三门语言的标签分别是 `zh-CN`、`zh-TW`、`en-AU`。
- Node 22 自带完整的 ICU，测试里断言的就是实际输出。
- 目前三门语言的金额格式完全一样，所以 `Intl` 在不同浏览器上的细微差别不会影响金额显示。

## 7. 地名和专有名词

- **地名保留英文原名。**
  - 中文界面：中文名作主名，英文原名用小字附在旁边。`claude/earth-main-ui` 已经在名牌上加了 `<span class="en">`。
  - 英文界面：只显示英文原名，取地点的 `en` 字段，不另外翻译。
  - 繁体界面：港台通行译名和大陆不同时用港台的叫法，没有通行译名时照简体字形转换。
- 原住民地名（Kalgoorlie、Karijini、Coober Pedy……）保持原拼写，不意译。
- 真实场所（OSM 的餐馆、商店）的名字一律用 OSM 上的原名，任何语言都不翻译，因为玩家要拿它去找现实里的店。
- NPC 的名字不翻译。NPC 的身份描述（「咖啡师」）算数据文本，按 §2.2 翻。
- 游戏术语在各语言里要统一叫法，记在术语表里，见 §8。

## 8. 翻译流程

| 步骤 | 谁做 | 做什么 |
| --- | --- | --- |
| 1. 抽取 | Claude Code | 迁移某个区块时：把中文写进基准表、定键名、在页面里改用 `tx()`，同时把英文和繁体的初稿写进对应的表，保证 `tsc` 和测试是绿的。界面文案一批只有几十条，跟着代码一起写 |
| 2. 批量初译 | OpenClaw | 数据表（§2.2）一张表几百条，按任务书批量出初稿，直接生成翻译文件。地名的 `en` 来自 OSM 和 Wikidata，不需要翻 |
| 3. 审校 | Codex | 对照术语表看用词是否一致、占位符是否齐全、语气是否统一、有没有把专有名词意译了；只写审查意见 |
| 4. 母语校对 | 人工 | 英文找本地同学或同事读一遍，繁体找港台玩家读一遍。校对过的语言才能放进 `COMPLETE_LOCALES` |

- 术语表：第一次批量翻数据表之前建 `docs/earth-game/i18n-glossary.md`，至少包括声望、心情、需求、技能名、季节、天气、交通方式。
- 文风：
  - 英文用澳洲拼写（colour、centre），句子短，不用感叹号，按钮用动词开头。
  - 繁体用台港通行词：設定、裝置、圖磚、預設、資訊。

### 防漏翻（已在 `tests/earth/i18n.test.ts` 里）

| 检查 | 拦什么 |
| --- | --- |
| 键名一致 | 别的语言里有基准表没有的键（键名拼错，或者删键时没删干净） |
| 漏翻 | `COMPLETE_LOCALES` 里的语言缺键或值为空；英文值里出现汉字；繁体值里出现常见的简体字 |
| 占位符一致 | 同一个键在各语言里的 `{占位符}` 集合不同（漏写、改了名） |
| 引用存在 | 代码里写到的 `'tab.…'`、`'pref.…'` 这类键必须在表里有；表里的键必须有代码在用，防止留下死文案 |
| 转义 | `tx` 必须包着 `esc`；页面里不能直接调 `t(prefs.lang…)`，不能写 `${t(…)}`；语言名也要经过 `esc` |
| 回退和格式化 | 回退链、漏传参数、原型链上的名字、金额四舍五入、负零、珀斯和阿德莱德时差（含夏令时）、和 `formatClock` 对照 |

另外有两条已经计划好、但本批没有做的检查：

- **类型层**：基准表加了键而翻译表没跟上，`tsc` 报错。这条已经生效，测试是第二道防线，因为 Node 跑测试时会擦掉类型。
- **写死的中文（棘轮测试）**：统计 `earth.astro` 脚本里的中文字面量数量，只许减少不许增加。当前大约有 1762 段。**这条测试等并行分支都合并以后才开**，否则每个往页面里加中文的分支合并后都会挂。

## 9. 字体

- 正文用系统字体栈，三门语言都能覆盖，不需要处理。
- 问题在标题衬线字。`claude/earth-start-ui` 自托管了 `public/earth/fonts/terra-serif.woff2`，是 Noto Serif SC 的子集，只含开场用到的约 60 个字，13 KB。换成繁体或英文以后，标题里的字大多不在子集里，浏览器会**逐字**回退到系统字体，同一个标题里会混着两种字形。
- 方案：
  1. 用衬线字显示的文案，在字符串表里集中放在 `serif.*` 前缀下，或者在 `SERIF_KEYS` 里登记。
  2. 生成子集的脚本按「所有语言、所有 `serif.*` 文案的字符并集，加上 ASCII 可见字符」取字。
     - 简体和英文用同一个 SC 子集。Noto Serif SC 自带拉丁字母，加进 ASCII 后体积只略增。
     - 繁体单独出一个 Noto Serif TC 子集 `terra-serif-tc.woff2`，用 `:lang(zh-TW)` 切换 `font-family`。不能拿 SC 字体显示繁体：SC 里虽然有一部分繁体字形，但写法按大陆规范，台港读者看着别扭。
  3. 生成脚本同时输出一份 `terra-serif.chars.txt`，列出子集里有哪些字。加一条测试：每门语言 `serif.*` 文案里的每个字都必须在这份清单里，漏了就失败，提醒重新取子集。
  4. 体积上限：两个子集合计不超过 60 KB，`font-display: swap`。
- 这一步要等 `earth-start-ui` 合并、字体文件进了 main 之后再做。本批迁移的标签栏和设置页都不用衬线字，不受影响。

## 10. 渐进迁移方案

### 10.1 原则

- **一批只迁一个区块**，一般是一个渲染函数。不顺手改格式，不挪代码位置。
- **等改这个区块的并行分支都合并以后，再迁这个区块。** i18n 迁移改动的行很多，和正在开发的分支撞在一起时，冲突要人工逐行合，很容易丢改动。
- **并行分支不需要配合**：新写的界面文案可以继续写死中文，迁移时一起抽走。只有一条要求：已经迁移、改成 `tx()` 的行，改的时候要继续用 `tx()`，不要改回中文。
- 每批迁移都要同时补全英文和繁体，不留「先迁键、以后再翻」的半成品。三门语言目前都在 `COMPLETE_LOCALES` 里，测试会拦住漏翻。

### 10.2 本分支和并行分支的合并情况

2026-11-20 用 `git merge-tree` 把本分支和 23 个 `claude/earth-*` 工作区分支逐个试合并：

- 22 个没有冲突。
- 只有 `claude/earth-onboarding` 冲突，位置在 `panelSync()` 里「显示」卡和「提示」卡相邻的几行：本分支把「显示」卡的文案换成了 `tx()`，onboarding 在「提示」卡里加了一行开关。
  - 解法：「显示」卡的四行（`sound`、`real`、`lang`、`return …显示…`）用本分支的版本，「提示」卡那行用 onboarding 的版本。
  - 建议 onboarding 先合，本分支再变基上去解这一处冲突。

本分支动到的位置如下，并行分支改到这些地方时注意：

- `import` 区：新增 i18n 一行。
- `TABS`、`ME_TABS` 的标签文字改成了键。
- `applyPrefs()` 加了一行设置 `<html lang>`。
- 新增 `tx` 的定义，放在 `setPrefs` 前面。
- 顶栏 `hud-title` 的标题那一行。
- 「我」页分栏那一行。
- 标签栏渲染那一行。
- `panelSync()` 的「显示」卡。
