# 底层方案：消费与资产系统（草案，待确认）

> 状态：**阶段 A 已实现**（交通工具、课程、体验与收藏）；B–D 待开发。
>
> 已确认的决定（采用方案默认值）：房价约为真实西澳的 1/5；出租年化收益封顶 4%；提供贷款；阶段 A 三项一起做。

## 1. 要解决的问题

数值模拟（[balance.md](balance.md)）显示：有正式工作的玩家每天净赚 $117–281，60 天攒下 $8,000–19,000，但除了买车（$4,500 / $12,000）和房租几乎没有花钱的地方。钱只增不减，攒钱这条线后面没有目标。

## 2. 设计原则

1. **每一笔大额消费都要换来玩家能感受到的东西**，只能是下面五种之一：
   - 舒适：心情、睡眠恢复
   - 时间：更快出行、更少等待
   - 能力：更快成长、解锁升职
   - 收藏与声望：独特体验、打卡
   - 被动收入：资产升值、出租
2. **持续性开销和一次性开销都要有**：只有一次性的，钱攒够买完就又没用了。
3. **不能有稳赚不赔的循环**：转手必亏，被动收入必须带维护成本和风险。
4. **全部数据驱动**：沿用现有写法，新内容只加数据文件，引擎不写特例。
5. **全部走服务端结算**：新动作全部加进 `GameAction`，客户端只发意图。

## 3. 五个新系统

### 3.1 交通工具（把现有的 `car` / `4wd` 改成数据驱动）

现在座驾是写死在引擎里的两个值。改成数据表 `data/vehicles.ts`：

| 字段 | 含义 |
| --- | --- |
| `price` | 买价 |
| `resale` | 卖出回收比例（0.5–0.7，转手必亏） |
| `speed` | 公路时速 |
| `costPerKm` | 油费 |
| `track` | 能不能走越野土路 |
| `weekly` | 每周保险与保养 |
| `sleep` | 能不能在车里过夜，以及舒适度 |

首批车型：

| 车型 | 价格 | 特点 |
| --- | --- | --- |
| 二手轿车 | $4,500 | 现有 |
| 摩托车 | $3,000 | 便宜、快，但不能载物，体能消耗大 |
| 四驱越野 | $12,000 | 现有，可走土路 |
| 露营车 | $28,000 | 可走土路，能在车里睡觉，舒适度介于露营和合租之间 |

露营车最贴合西澳的玩法：买了它就可以长期环游、不租房。

**存档变化**：`vehicle` 从 `'none' | 'car' | '4wd'` 改成车型 id 字符串，旧值直接映射，兼容旧存档。

### 3.2 技能课程

**花钱换能力**，同时解决“矿工练不了驾驶、升不了职”的问题。

- 数据表 `data/courses.ts`：驾校、冲浪学校、急救课、健身私教、商务社交课等。
- 每节课在符合条件的地点上，耗时 2–4 小时，能力成长是平常行为的 3–4 倍（仍走 `growSkill` 的递减曲线）。
- **价格随当前能力上涨**：`价格 = 基础价 × (1 + 当前值 / 25)`。低级便宜，高级很贵，防止拿钱直接买满。
- 每门课每个游戏日只能上一次。

### 3.3 体验与收藏

**花钱换独特回忆、声望和心情**，同时把玩家引向各地。

- 数据表 `data/experiences.ts`，每项绑定一个地点。比如：
  - 埃克斯茅斯 与鲸鲨同游 $400
  - 库努纳拉 邦格尔邦格尔观光飞行 $550
  - 布鲁姆 骆驼骑行看日落 $120
  - 玛格丽特河 酒庄晚宴 $180
  - 罗特尼斯岛 环岛骑行 $60
- **首次体验**：进收藏册（存档新字段 `collected`），声望 +3 到 +8，心情大加；可能带专属事件。
- **重复体验**：只给心情。
- 收藏册集齐一个片区（西南 / 皮尔巴拉 / 金伯利…）给称号，进角色页。

### 3.4 家具与住房升级

**对已有的住处花钱**，提高回家睡觉和在家活动的效果。

数据表 `data/furniture.ts`，按槽位，每个槽位一件，可替换：

| 槽位 | 例子 | 效果 |
| --- | --- | --- |
| 床 | 好床垫 $400 | 回家睡觉健康恢复 +10 |
| 厨房 | 炊具 $250 | 解锁“在家做饭”，$6 一顿，比外面吃便宜 |
| 浴室 | 热水器 $300 | 回家睡觉清洁恢复更多 |
| 娱乐 | 音响 / 游戏机 $500 | 解锁“在家娱乐” |
| 装饰 | 植物、画 $150 | 住房心情 +2 |

- 租的房子：搬走时家具半价折现。
- 自己的房子：家具跟着房子走，卖房时计入房价。

**存档变化**：`home` 加 `furniture: Record<槽位, 家具id>`。

### 3.5 房产（买房、贷款、出租）

**最大的长期目标和最大的资金去处。**

数据表 `data/properties.ts`，房产绑定地点：

| 字段 | 含义 |
| --- | --- |
| `homeType` | 复用现有房型，决定舒适度 |
| `price` | 房价 |
| `weekly` | 每周物业费、地税 |
| `rentIncome` | 出租的周租金 |

示意价格：

| 房产 | 价格 |
| --- | --- |
| 卡尔古利小屋 | $55,000 |
| 珀斯公寓 | $90,000 |
| 弗里曼特尔联排 | $140,000 |
| 海景小屋 | $220,000 |

规则：

- **买房**：付清全款，或首付 20% + 贷款。贷款按周自动还，每周利息 0.1%（年化约 5%）。
- **住进去**：不交房租，只交物业费。舒适度按房型。
- **出租**：每周收租金。每周 5% 概率空置（这周没收入），每 8–12 周有一次维修事件（$200–800）。租金扣掉物业费和还款后只是小正收益，不会躺赚。
- **卖房**：按买价的 95% 回收（扣中介费），先还清贷款。
- **断供**：现金不够当周还款时，宽限 2 周，再不够就强制按 85% 卖房还贷。

**存档变化**：

- 新字段 `properties: { id, loan, furniture, rented }[]`
- `home` 增加一种来源“自有”：`{ type, loc, owned: propertyId }`

## 4. 引擎层改动

### 4.1 每周结算统一

把现有的 `chargeRent()` 推广成 `weeklyTick()`，时间每跨过一周执行一次：

1. 房租
2. 贷款还款
3. 物业费
4. 车辆保险
5. 出租收入与空置判定
6. 断供处理

每一项都写进日志。存档里增加一个 `nextWeek`（下一次周结算的游戏日），替代现在 `home.paidUntil` 的作用。

### 4.2 新增派生属性（`attributes.ts`）

- **净资产** = 现金 + 车辆残值 + 房产价值 + 家具折现 − 贷款余额。
- **每周固定开销** = 房租 + 还款 + 物业费 + 保险，显示在角色页，让玩家知道自己“养得起”什么。

### 4.3 新动作（加进 `GameAction`）

| 动作 | 说明 |
| --- | --- |
| `{ t: 'vehicle', op: 'buy' \| 'sell', id? }` | 替代现在的“买车”互动 |
| `{ t: 'course', id }` | 上课 |
| `{ t: 'experience', id }` | 体验 |
| `{ t: 'furniture', op: 'buy' \| 'sell', id }` | 家具 |
| `{ t: 'property', op: 'buy' \| 'sell' \| 'movein' \| 'rentout', id, loan? }` | 房产 |
| `{ t: 'home', op: 'cook' \| 'relax' }` | 在家做饭 / 在家娱乐 |

## 5. 数值目标

以“咖啡店上班族”（日均净收入约 $117）为基准，消费系统上线后用模拟验证这些节点：

| 时间点 | 期望达成 |
| --- | --- |
| 第 1–2 周 | 买得起第一件家具、上几节便宜的课 |
| 第 3–5 周 | 买得起二手轿车 |
| 第 5–8 周 | 体验过 3–5 个收费项目 |
| 第 10–14 周 | 付得起第一套房的首付 |
| 第 6 个月左右 | 有能力买露营车或第二套房 |

验收标准：

- **净资产持续增长**，同时现金不再无限堆积：第 60 天中位现金应在 $1,000–4,000，其余变成资产。
- **没有稳赚的循环**：模拟里加一个只买卖车辆、房产的机器人，它的净资产必须下降。
- **出租房产**扣除所有开销后，年化收益不超过房价的 4%。
- **对照组**（不工作）和**背包客**的结果与现在相比没有明显变差。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 被动收入失控，玩家只靠收租 | 收益率封顶 4%；空置和维修事件；物业费随房价 |
| 课程变成“花钱直接买满” | 价格随能力上涨；每门每天一次；仍受递减曲线限制 |
| 断供把玩家逼入绝境 | 2 周宽限；强制卖房至少收回 85%；绝不让现金变负 |
| 旧存档迁移出错 | `sanitizeState()` 迁移旧座驾值和 `paidUntil`；补对应测试 |
| 界面越来越挤 | 新增“生活”标签页，把工作、住处、房产、车辆、收藏集中放；地点页只显示当地能做的 |

## 7. 分期

| 阶段 | 内容 | 理由 |
| --- | --- | --- |
| **A** | 交通工具数据化（含露营车、卖车）、技能课程、体验与收藏 | 改动最独立，马上给玩家花钱的理由；顺带修好矿工升不了职的问题 |
| **B** | 家具与住房升级、在家做饭和娱乐、`weeklyTick()` 统一周结算 | 为房产铺路；在家做饭让生活成本有选择 |
| **C** | 房产买卖、贷款、出租、断供；净资产 | 改动最大，依赖 B 的周结算和家具 |
| **D** | 净资产排行榜（服务端已能保证公平） | 需要先有 C |

每个阶段结束都跑一次 `npm run earth:sim`，更新 [balance-report.md](balance-report.md)，对照第 5 节的目标。

## 8. 待确认的问题

1. **价格尺度**：房价参照真实西澳房价的大约 1/5（珀斯公寓 $90,000）。要更写实，还是更“游戏化”？
2. **出租收益**：上限按年化 4% 设计。想让“当房东”成为一条主要发家路线的话，可以放宽。
3. **贷款**：要不要加贷款？不加的话买房只能全款，节奏会慢很多，但系统简单、也没有断供风险。
4. **阶段 A 先做哪几项**：建议三项一起做，一次完成。
