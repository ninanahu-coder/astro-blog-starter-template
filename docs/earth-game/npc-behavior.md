# NPC 行为和日程规则（第 43 批）

分支 `claude/earth-npc-behavior`，从 main `4f9c9e5` 开，changelog v43（合并时按顺序重编）。

每条内容都标了状态：

- **【现状】** main 上已经有的。
- **【本版已做】** 这个分支的第一版代码。
- **【提议】** 还没做，等用户拍板。
- **【并行分支】** 别的分支在做，这里只写怎么对齐。

标「待平衡」的数值都是初值。按 AGENTS.md，由 Codex 跑模拟出分析、用户拍板后再改，Claude 不下平衡结论。

两条硬约束：

1. **确定性**。NPC 的行为只由「NPC + 游戏时钟」（和地点天气）决定，所有玩家在同一时刻看到的一样，不用存档里的随机种子，不读真实时钟。需要「随机」的地方（病假、台词）用和天气同一个 FNV-1a 哈希 `unit()`。
2. **不加存档字段**。NPC 的状态全部现算，`PlayerState` 不变，不涉及 `save-sync.md` 的迁移。

## 1. 现状【现状】

| 部分 | 位置 | 做什么 |
| --- | --- | --- |
| 常驻 | `npcs.ts` 的 `loc`、`hours` | 每位 NPC 一个常驻地点和作息，跨午夜的作息（戴夫 20–6）也支持 |
| 日程 | `npcs.ts` 的 `schedule` | 按星期、季节、节日改去处，按顺序取第一条满足的 |
| 当天安排 | `engine.ts` `npcPlan` | 只看今天 |
| 此刻安排 | `engine.ts` `planNow` | 凌晨还在昨天跨午夜的班次里时沿用昨天 |
| 在不在场 | `npcPresent`、`npcStatus`（there / before / after） | 界面三处和引擎用同一套判断 |
| 当前地点在场的人 | `npcsAt` | 返回关系、各互动能不能做、送什么礼 |
| 联动 | `npc-duos.ts` | 两位 NPC 好感都到 40 时触发一次，剧情基于两人日程的交集 |

**缺的东西**：NPC 365 天都上班；天气只挡「出海类专属互动」，NPC 自己照常出海；去外地是瞬移；NPC 没有自己的状态，聊天只看玩家的魅力。

## 2. 规则引擎：分层的状态机【本版已做】

代码在 `src/game/core/npc-behavior.ts`（纯函数），数据在 `src/game/data/npc-behavior.ts`。`engine.ts` 的 `npcPlan` 改成调用 `planFor`，签名不变。

### 2.1 当天安排的优先级

```
休年假（NPC_LEAVE） > 病假（NPC_SICK） > schedule 里第一条满足的 > 常驻
```

`schedule` 的条件多了天气（见 2.3），节日、天气、星期、季节的先后仍由数据里的顺序决定。

`NpcPlan` 多了 `away?: 'leave' | 'sick'`。请假时 `loc`、`hours` 是常驻的，只用来显示「平时在哪」；`npcPresent` 一律返回 false，`npcStatus` 返回新状态 `away`。

### 2.2 不在：年假和病假【本版已做，数值待平衡】

**年假**（`NPC_LEAVE`，8 条，每位最多一段）：每年同一段时间，写在数据里。

| NPC | 时间 | 说明 |
| --- | --- | --- |
| 米娅 | 冬季第 8–12 天 | 回老家探亲 |
| 老杰克 | 冬季第 20–26 天 | 禁渔期，去南边看女儿 |
| 南希 | 秋季第 2–5 天 | 去珀斯看病的老姐妹 |
| 里奥 | 夏季第 3–8 天 | 去印尼追浪 |
| 萨姆 | 冬季第 1–6 天 | 淡季回老家 |
| 由纪 | 夏季第 15–21 天 | 雨季关店回日本 |
| 葛蕾塔 | 冬季第 10–14 天 | 去欧洲参加酿酒展 |
| 哈利 | 春季第 15–17 天 | 博物馆闭馆布展 |

- 测试保证年假不撞上 TA 自己日程里的节日（玩家冲着节日赶去，人却不在）。
- 日期是编的种子数据，不是真实事件，不需要外部来源。

**病假**（`NPC_SICK`）：

- 每位 NPC 每天按季节有一个开始生病的概率：春 1%、夏 0.8%、秋 1.2%、冬 2%（待平衡）。一病 1–2 天（`maxDays: 2`）。
- 由 `unit('npc-sick|<id>|<day>')` 决定，确定性。
- **节日安排那几天不病**：TA 的 `schedule` 里有节日条目、今天正好生效时，跳过病假判断。
- 实测（4 年 × 17 位）：病假约占 NPC·天的 1.8%，年假约 2.3%。

### 2.4 移动与空间分布【本版已做，待平衡】

`npcWhere(npc, clock, region?)` 回答「TA 此刻在哪」：

| kind | 含义 | loc |
| --- | --- | --- |
| `there` | 在当天的去处当班 | 去处 |
| `travel` | 在路上，`to` 是目的地 | 出发地 |
| `off` | 不在班上，在家歇着 | 常驻地点 |
| `away` | 请假 | 常驻地点 |

- 去外地那天：开工前 `travelHours` 小时出发，收工后同样时长往回走。
- `travelHours` = 两地直线距离 ÷ 80 km/h，向上取整，钳在 1–8 小时；找不到坐标时 2 小时（`NPC_TRAVEL`，待平衡）。珀斯→罗特尼斯岛 1 小时，黑德兰港→布鲁姆 6 小时。
- 跨午夜：先看今天、再看昨天的班次窗口，和 `planNow` 一致。昨天请假、平时又是跨午夜的班，凌晨那段仍算请假。
- **和在场判断完全一致**：测试逐 90 分钟扫 70 天，`kind === 'there' && loc === L` 当且仅当 `npcPresent(npc, L)`。

`npcMap(npcs, clock, region?)`：同一时刻的空间分布，地点 → 在那里当班的 NPC。测试保证没有分身。

界面只在「这里的人」里用了 `travel`：不在场的人如果正在路上，多一句「正在去××的路上」。

### 2.5 NPC 的需求和心情【本版已做，数值待平衡】

**需求**（`npcNeeds`，`NPC_NEEDS`）：

- **精力**：开工时 95，到收工线性降 55；在路上 55，在家 80；炎热再 −15。
- **同伴**：同一地点当班的其他 NPC 人数（来自 `npcMap`）。

**心情分**（`npcMood`）= 脾气基础分 + 各项：

| 项 | 值 | 数据 |
| --- | --- | --- |
| 脾气 | 每位 −4 到 +8 | `NPC_TEMPER[id].base` |
| 天气 | 每位对几种天气有好恶，如麦克下雨 +10、汤姆风暴 −12 | `NPC_TEMPER[id].weather` |
| 节日 | 所在地点正在办节日 +12 | `NPC_MOOD.festival` |
| 周末 | +4 | `NPC_MOOD.weekend` |
| 累 | 精力低于 60 时，每少 4 点 −1 | `energyPivot`、`energyDiv` |
| 有伴 / 孤单 | 当班时有别的 NPC 在 +4，只有自己 −2 | `company`、`lonely` |

分档：≥12 很好、≥0 不错、≥−8 一般、更低是不好。一年里当班时刻的分布约为：很好 7%、不错 66%、一般 23%、不好 2%。

**原因**：和心情同方向、分量最大的那一项。

### 2.6 心情影响对话【本版已做，数值待平衡】

- **招呼台词**：`NPC_LINES[心情][原因]`，同一天同一位 NPC 固定一句（`unit('npc-line|id|day')`）。没有对应原因时用 `calm`。占位符 `{weather}`、`{festival}`、`{place}` 在 core 里替换，页面插值仍经 `esc()`。
- **聊天检定**：门槛从固定 45 改为 `45 + chatDc[心情]`：很好 −8、不错 0、一般 +4、不好 +10。测试用 300 个种子比较，心情好时「聊得投机」的比例明显更高。
- **聊天结果**：开头先是 TA 的招呼，比如「老杰克：「风暴，什么都干不成。」和老杰克寒暄了几句。」
- **界面**：「这里的人」的气泡显示心情图标和招呼台词，下一行仍显示简介。

`NpcAvailability` 多了 `mood` 字段。

## 5. 与并行分支的对齐【并行分支】

- **社交 NPC（`claude/earth-social-npc`）**：关系衰减、帮小忙、知己都在那边。本分支不碰关系分数。
  - 合并点：`NpcAvailability` 两边都加了字段（那边 `favor`、`fading`、`confidant`，这边 `mood`），`npcsAt` 的 return 那一行两边都改了，合并时都保留。
  - 聊天分支：那边改了 `gain = …` 和第一句 `text = …`（加知己近况）；这边改了 `const good = …` 的门槛，另起一行在 `text` 前加招呼。两边都留，招呼在前、近况在后。
  - 那边的「认识的人今天在哪」加了「好久没见」提示；这边在同一个 map 里加了请假那一行。合并时都保留。
  - 那边的「帮小忙」：NPC 请假时人不在场，自然帮不了；托付的周期仍按那边的规则算。
- **天气（`claude/earth-weather`）**：那边改了天气的抽法、加了 `cold`，`weatherOn(locId, day)` 签名不变，这边只用它。合并后可以给脾气表加 `cold` 的好恶，测试会检查天气 id 都存在。
- **节日互动（`claude/earth-live-social`）**：现实节日是另一层，本分支只看游戏内节日（`festivals.ts`）。
- **属性（`claude/earth-activity-attrs`）**、**时间与睡眠（`claude/earth-time-sleep`）**：没有交集。
- **任务（`claude/earth-quests`）**：任务如果要求「找到某位 NPC」，判断在不在场用 `npcPresent`，请假的日子会找不到，任务提示里最好提一句。
- **NPC 头像（`claude/earth-npc-portraits`，PR #46）**：头像旁边可以按心情换表情，见第 6 节。
- **新手引导（`claude/earth-onboarding`）**：如果引导里写死「去珀斯找米娅」，碰上米娅年假（冬季第 8–12 天）会找不到。新角色从春季第 1 天（游戏日 0）开始，引导期间不会撞上。

## 6. 未来【提议】

### 6.1 规则

- 【提议】**病假通知**：认识的 NPC 生病时，「认识的人今天在哪」里多一个「去看看 TA」：带一份 TA 喜欢的东西去 TA 常驻地点，关系 +，生病的人病好后记得。需要和社交分支的「帮小忙」合在一套。
- 【提议】**年假前后的剧情**：年假前一天说「明天要走了」，回来那天带一份当地特产（只给心情）。
- 【提议】**`cold` 的好恶**：天气分支合并后再加。
- 【提议】**心情影响送礼和帮忙**：本版只影响聊天。送礼可以「心情差时最爱的礼物加成」，帮忙可以「TA 累的时候帮忙关系多涨」。要先看模拟里关系增长速度再定。
- 【提议】**NPC 之间的约会**：用 `npcMap` 的交集自动发现「两人此刻在同一地点」，在那时触发 `npc-duos` 的联动剧情（现在是任意时间和其中一位互动就触发）。
- 【提议】**人流**：地点的「热闹程度」= 在场 NPC 数 + 在线玩家数 + 节日，影响街头卖艺收入。属于经济分支，那边拍板。

### 6.2 LLM（本版不接）

- 【提议】**台词生成离线化**：如果要更多台词，可以用 LLM 离线生成候选，由人审核后写进 `NPC_LINES`，游戏运行时仍然只查表。这样保持确定性、不增加线上成本，也不会让 NPC 说出未审的内容。
- 【提议】**不建议**在线让 LLM 扮演 NPC 和玩家自由对话：玩家里有未成年留学生，在线生成的内容很难保证；回答不确定，会和「所有玩家看到的一样」冲突；还会带来成本和延迟。如果以后要做，只限于「换一种说法」这类改写，输入只有表里的台词和心情，不传玩家输入。
