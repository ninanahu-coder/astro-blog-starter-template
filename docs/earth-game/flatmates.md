# 室友与合租

分支 `claude/earth-flatmates`，changelog v43（合并时按顺序重新编号）。

> **2026-11-23 合并 main `44f7cbe`**，更新日志改为 v88。下文 §0–§2 的「现状」和房租数字（$160、$320）是合并前按房型标价写的；合并后房租按 main 的租约房租、已通知的涨租和租金指数算，再分摊。§12、§13 的测试和模拟数字也是合并前的。合并后的接法、复核修正和新数字见 §14。

每条内容都标了状态：

- **【现状】** main 上已经有的。
- **【本批】** 这个分支的第一版代码。
- **【提议】** 还没做，等用户拍板。
- **【并行分支】** 别的分支在做，这里只写怎么对齐。

标「待平衡」的数值都是初值。按 AGENTS.md 的分工，由 Codex 跑模拟出分析，用户拍板后再改，Claude 不下平衡结论。

设计原则：

1. **单人能玩完整。** 第一版只有 NPC 室友；玩家室友是加分项，没人在线也不卡进度。
2. **玩家之间不留私下联系的口子。** 玩家室友（§7）不显示真实位置、不开私聊，随时能单方面退出和屏蔽。
3. **不打乱别的系统的随机序列。** 室友的随机数用 `seed + 时钟 + 用途` 做哈希，不推进 `state.seed`。

## 2. 分摊房租和账单【本批，数值待平衡】

**现状**：游戏里没有水电网账单，房租视为包水电。

**本批规则**（`rentShare()`、`flatRentDue()`）：

- 一个人住、合租房间：你付整份房租，和现状一样，**一个人住的经济完全不变**。
- 二房东有室友时：（房租 + 每周水电网）÷ 人数。水电网 `billsWeek`：一居室 $45、海景公寓 $55、海景小屋 $70（待平衡）。
  例：一居室 $320，一位室友 → 你付 (320 + 45) ÷ 2 = $183。
- 室友那份第一版视为按时交给房东，不经过你的现金。拖欠体现在事件「借钱」里（§4），不做「室友不交房租你来垫」，避免二房东被 NPC 拖到收房。
- `weeklyCosts().rent` 显示的是分摊、转租之后你实际要掏的数。

**为什么水电网只在合租时算**：给一个人住的情况加账单，是在改全游戏的生活成本，归 `economy` 分支管。如果 `economy` 以后给所有住处加水电网，这里的 `billsWeek` 要换成同一个数，见 §9。

## 3. 家里卫生和家务轮值【本批，数值待平衡】

- 家里卫生 `flatshare.clean` 0–100，新住处从 70 起。
- **每周结算**：你弄脏 10，每位室友按 tidy（0/1/2）弄脏 18 / 10 / 4。
- **轮值**：值日表是「你 + 室友」轮流，每周一个人（`dutyFor()`，按结算日序号取模）。
  - 轮到室友：TA 按 tidy 打扫回来 12 / 25 / 40。
  - 轮到你：那一周做过至少一次家务，所有室友关系 +3；没做 −8，并记一条日志。
- **做家务**（住处卡片「做家务」）：45 分钟，精力 −6，卫生 +30。随时能做，不限次数（卫生满了不能做）。
- **家里乱**（卫生 < 35）：
  - 回家睡觉清洁少恢复 15，得到心情「家里乱糟糟」(−4，12 小时)；
  - 住处心情 −3；
  - 爱干净（tidy 2）的室友每周关系 −2；
  - 可能抽到「浴室的头发」事件。

## 4. 室友性格和事件【本批，数值待平衡】

### 4.1 人设

8 位原创 NPC（`FLATMATES`），性格四个维度各 0–2：tidy 爱干净、noise 吵、borrow 爱借东西、warm 热心。不和镇上的 17 位 NPC 重叠，不对应任何真人或现有作品角色。

### 4.2 事件

- **什么时候抽**：回家睡醒后，有室友、没有待处理的室友事件时，30% 几率（`eventChance`，待平衡）抽一个。只从「这位室友的性格够得上」的事件里按权重抽；定好要搬走的人不再惹事。
- **不挡出行**：室友事件不走全局的 `pending`，显示在住处卡片里，不处理也能出门。3 天没处理作废，那位室友关系 −4。
- **8 个事件**：

| 事件 | 条件 | 选项（关系变化） |
| --- | --- | --- |
| 半夜的客厅 | noise 2 | 请小声（−3）/ 戴耳塞忍（0，精力 −12，心情「被室友吵到了」）/ 一起聊（+6，社交 +20，精力 −15） |
| 隔墙的音乐 | noise ≥1 | 请戴耳机（−1）/ 自己也听会儿（+1） |
| 堆满的水槽 | tidy 0 | 帮洗（+3，卫生 +12）/ 群里提值日表（−3，卫生 +6）/ 不管（0，卫生 −5） |
| 浴室的头发 | 家里乱 | 自己通（0，卫生 +10）/ 拍照发给 TA（−4） |
| 借点钱 | borrow ≥1 | 借 $40（+5，记账）/ 婉拒（−2） |
| 少了的洗发水 | borrow 2 | 直接问（−3）/ 再买一瓶 $8（0）/ 算了（+1，心情「有点憋屈」） |
| 一大锅饭 | warm 2 | 一起吃（+5，饱食 +40，社交 +15，心情「被人照顾了一下」）/ 谢绝（0） |
| 厨房里聊两句 | warm ≥1 | 多聊（+3，社交 +10）/ 赶时间（0） |

每个事件都有不花钱的选项（测试检查）。

### 4.3 借东西不还

借出去的钱记在 `mate.owes`。每个结算日按 borrow 0/1/2 以 95% / 70% / 35% 的几率还清（待平衡）；没还记一条日志。室友搬走时还没还的就要不回来了。

### 4.4 关系

- 每位室友一个关系分 `vibe`，−100 到 100，新室友从 10 起。
- 平均关系 ≥ 40：回家睡觉得到心情「室友相处融洽」(+5，24 小时)。
- 某位室友关系 ≤ −40：结算时 TA 提出下周搬走。
- 室友关系和镇上 NPC 的关系（`relations`）分开，不参与 `social-npc` 分支的变淡规则。

## 5. 搬走与转租【本批】

- **室友搬走**：关系太差自己走（§4.4），或二房东请 TA 走（提前一周，关系 −10）。合租房间的室友不归你管。
- **你搬走**：退租、换房、搬进自有房、被收房都会清空室友。二房东的租约视为室友接手（只是文案，没有额外结算）。
- **转租**：人不在住处时，可以把租的房间短期转租出去（营地不行）。
  - 转租期间不能回去睡觉、做饭、放松，也不会有室友事件；
  - 每个结算日照付你那份房租，同时收回 90%（`subletRate`，待平衡），实际只掏 10%；
  - 回来后点「收回房间」，马上能住。
  - 转租收入按这周实际转租的天数折算（`flatshare.subFrom` 记从哪天起；每个结算日后挪到那个结算日）。中途收回，这周已转租的天数不算钱。合并 main 时复核修正：原来按结算那一刻的开关算整周，结算前一刻转租、结算后收回就能每周只付一成房租。

## 7. 玩家室友（异步）和防骚扰【提议】

第一版没做：需要服务端两份存档一起写（像二手摊成交那样锁住双方），而且屏蔽要和 `live-social` 的 `blocked` 用同一份名单，那个分支还没合并。下面是建议方案。

### 7.1 怎么成为室友

- 只能邀请「常遇见的人」（`state.met`，一起做过事 ≥ 2 次）里的人，用 id 哈希前缀标识，不出现真实 id。
- 邀请挂在服务端（像二手摊挂单），对方下次上线在住处卡片看到「××想请你合租」，**接受才生效**；7 个现实日不处理自动失效。
- 每人每现实日最多发 3 个邀请；被拒绝后 7 天内不能再邀请同一人。
- 双方都在服务端重新检查：邀请方是二房东、有空床；被邀请方当时没有住处或愿意搬家。

### 7.2 住在一起以后

- 两份存档各记一条室友：`{ kind: 'player', hash, name, avatar, since }`。各付各的那份房租，**不在玩家之间转钱**（不做借钱、垫付），避免变成转账和诈骗的通道。
- 家务轮值照常；对方值日周做没做，由对方自己的家务动作决定，结算时服务端读两份存档。
- 不生成性格事件：别的玩家的行为不由系统模拟。只有中性提示（「××这周做过家务了」）。
- 不显示对方的真实位置和在线时间，不开私聊；只显示名字、头像、这周有没有做家务。

### 7.3 退出、屏蔽、举报

- **退出合租**：任何一方随时单方面退出，立即生效，不需要对方同意，不扣关系、不扣钱。邀请方退出 = 请对方走；被邀请方退出 = 搬走（住处变成无）。
- **屏蔽**：退出时可以勾选「同时屏蔽」，写进 `live-social` 的 `blocked`（同一份名单、同样的 50 人上限）。被屏蔽的人发不了合租邀请，对方不会收到通知。
- **举报**：直接用 `live-social` 的举报（原因多一项「合租骚扰」由那边决定），举报后自动退出合租并屏蔽。
- 被举报自动隐藏的人（`live-social` §6.2）不能发合租邀请。

### 7.4 要确认的事

- 玩家室友要不要第一版就有，还是先看 NPC 室友的数据。
- 被邀请方要不要能「挂名」：自己在别处有住处，只是名义上合租（建议不要，太像社交软件）。

## 8. 其他【提议】

- **自有房产招租客**：住在自己的房子里、收一位租客的房租。和 `OwnedProperty.rented`（整套出租）是两回事，要和 `home-vehicle` 对齐。

## 10. 存档

新增字段 `flatshare`（按 `save-sync.md` §5.1，没改 `SAVE_VERSION`）：

```ts
flatshare: {
  mates: { id: string; vibe: number; since: number; owes: number; out?: number }[]; // 最多 4 位
  clean: number;  // 0–100
  ev: { id: string; mate: string; day: number } | null;
  chore: number;  // 最近一次做家务的游戏日，−1 没做过
  sublet: boolean;
}
```

- `createCharacter()` 给空值；`sanitizeState()` 里一行 `cleanFlatshare(r.flatshare)`。
- 清洗：只读自有键（原型链上的不算）；室友只留已知人设、去重、最多 4 位；数值钳到范围；事件要对得上名单里的室友；幂等。
- 序列化后不到 400 字节。没有秘密字段。
- `home` 的形状没改：转租标记放在 `flatshare.sublet`，不往 `Home` 里加键。

## 13. 模拟（180 天 × 100 次）

main（4f9c9e5）和本分支各跑一次 `npm run earth:sim -- --days=180 --runs=100`，原始报告见 [flatmates-sim.md](flatmates-sim.md)。

机器人的室友策略：有室友事件就选第一个付得起的选项；轮到自己值日、在家、精力 > 40 时做一次家务。机器人不会主动找室友，**二房东分摊房租的经济影响模拟里没有覆盖**；转租也没覆盖。

**只有住「合租房间」的 8 种策略有变化**，其余策略（公寓、营地、打零工、各出身对照……）的数字逐字相同——符合预期：一个人住的经济没动，室友随机数不推进 `seed`。

| 策略（合租） | 日均净收入 | 期末净资产 | 买房（中位） | 平均心情 |
| --- | --- | --- | --- | --- |
| 咖啡店上班族 | $71 → $73 | $28,067 → $28,571 | 第 89 → 87 天 | 68 → 68 |
| 矿工 | $343 → $343 | $74,396 → $74,356 | 第 26 → 26 天 | 57 → 58 |
| 酒保 | $84 → $86 | $30,525 → $30,934 | 第 84 → 82 天 | 74 → 73 |
| 农场工 | $21 → $20 | $22,181 → $20,585 | 第 144 → 151 天 | 67 → 66 |
| 咖啡店 + 共同事件（三种搭档） | $95/94/94 → $96/95/94 | 变化 < $200 | 第 76 天左右不变 | 67/67/68 不变 |

- 晕倒、被收房、升职次数、破产天数占比都没变。
- 钱的变化主要来自时间分配：做家务、事件里一起吃饭占掉一点时间，「休息」和「酒吧」的开销略少（每天少 $1–6）。
- 农场工变化最大（净资产 −$1,596，买房晚 7 天），但它的第 60 天现金 10%–90% 区间本来就有 $2,000 宽，这次落在区间内。魅力 71 → 64、游泳 19 → 23，是去酒吧的时间换成了在家的事。
